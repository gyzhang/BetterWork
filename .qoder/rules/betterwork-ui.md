# Renderer UI 与主题纪律

设计真相源是 [docs/10-ui-ux-system.md](../../docs/10-ui-ux-system.md)；变更核心信息架构或视觉语言前先更新该文档。

- **新增页面先走最短路径**（docs/10 §10.1）：普通视图每个可见分支实际组合 `PageHeader`／`ScrollRegion`，导入不用不算复用；工具栏/集合/正文沿用现有骨架。设置内嵌分区按已登记形态处理。新命名卡片/徽标外壳、额外版心和未登记内联 style 同样受护栏约束，不能换名字绕过。自定义按钮回到原生语义基座，菜单键盘委托只有 `PopoverMenu` 这个出口。
- **同档控件比较真实自然高度**（docs/10 §9.10、docs/12 §9）：单行输入/选择/按钮共用行高与同档字号；`npm run ui:check` 跑全部正式主题与两档视口、保存临时截图，并检查菜单/模态键盘语义。不得只比 `min-height` 或用 stretch 遮住差异。

- **页面称呼只查一张表**（docs/10 §6.1）：一级导航是 工作／成果／知识／技能／专家（代码侧是 `App.tsx` 的 `PRIMARY_NAV_ITEMS`），加侧栏底部「设置」；Skill 管理那一页叫**技能页**，「能力」只是模型／技能／MCP／搜索的总称，不给页面当名字。写走查清单、验收步骤、提交信息前先去那张表取名字和动作字面（「准备环境」「确认依赖授权」「召唤」「开始工作」「停止」），不要凭印象改写；护栏同时比对表与代码两侧。踩过的坑：2026-09-30 一份走查清单把技能页写成退役称呼，全仓 7 处历史文本于当日改准。

- **写 UI 交互前先查组件台账**（docs/10 §10.1）：已有基座必须复用；缺基座时先补基座再接页面，不得就地自造同类控件。绕过台账的代价已经发生过一次——用 `<details>` 手搓「更多」菜单，结果点外面不收起、能同开两个、菜单字号比自己的触发按钮还大。
- **纵向堆叠不得贴死**：同一容器里上下相邻的控件/表单/提示/卡片之间必须有可见垂直间距；间距由容器的 `gap` 拥有，子元素不自带上下 `margin` 凑同一道缝。`components/layout/` 骨架容器必须自带 `display` + `gap`，页面不得用后代选择器替骨架补 `gap`；表单控件不写 `width:100%`（在弹性行里会挤到同排标签逐字断行）。**设置页六个页签的 `.settings-section` 自带 `gap: 24px`**，子元素不得再用 `margin-top`/`margin-bottom` 凑间距——记忆页 `.memory-settings` 覆盖 `gap: 12px` 是有意收紧。护栏见 `standards/coding-standard.test.ts`「设置页纵向间距由容器 gap 拥有」，理由见 docs/10 §9.8。
- **新增/修改页面必须复用统一页面骨架**（docs/10 §8.3：`.page-header` 页头带 + `.page-body` 860px 版心）：禁止页面自定版心宽度、页头结构或标题坐标；工作视图的对话列与输入框必须同宽。
- **只用语义化主题 Token**（定义于 `apps/desktop/src/renderer/src/appearance.ts` 与 `styles.css`）：禁止新增硬编码色值，禁止用局部 `.dark` 补丁绕过 Token 契约。建立新 Token 时必须当场迁移所有相关硬编码值，不留半套。
- **控件几何取档，不写裸 px**（docs/10 §9.10）：高度档 `--control-height-sm`／`--control-height`／`--control-height-lg`（28／32／36）与内距档 `--control-padding-sm`／`--control-padding`／`--control-padding-lg`（4px 8px／6px 10px／8px 12px）**成对使用**——只对齐高度不对齐内距，同排的按钮与输入框仍是一个饱满一个瘦。多行编辑区的内距一律取 `--control-padding-lg`，原生勾选框边长取 `--control-check-size`，侧栏行高走 `--row-height*` 不套控件档；`.composer textarea` 的 `11px 0` 是登记在案的例外（左右内距归 `.composer`）。
- **焦点环画在控件自己的盒子里，不得外扩**（docs/10 §9.10、[ADR-0035](../../docs/adr/0035-focus-ring-inside-control-box.md)）：`outline: 2px solid var(--focus-ring)` 必须与 `outline-offset: var(--focus-ring-offset)`（**-3px**）同块出现，不写正值、不漏写、也不得浅到环宽以内——画在盒外的那一段会被祖先的 `overflow` 裁掉，而 `overflow-y: auto` 会顺手把 `overflow-x: visible` 强制成 `auto`，「这一层会不会裁」写页面时预判不了。**判据是环带落点不是符号**：Chromium 的环带 = `[-偏移, -偏移 + 环宽)`，`-1px` 是负值却只有一半在盒内（2026-10-01 光哥量出记忆页搜索框左右环比上下细一倍），`-3px` 让 2px 的环整体住在边框盒里、往里 1px 起画。实心填充按钮与环之间那 1px 缝由「`background-clip: padding-box` 让边框槽不铺填充」＋「环带不盖住那一格」**两条一起**成立，缺一即无缝；不新增色值 Token，也不占 `box-shadow`（`.memory-row` 的状态标记条在用）。要关掉某个表面的环必须**指名搬到哪**——`.composer textarea` 的 `outline: 0` 登记在护栏清单里，承载者是 `.composer:has(textarea:focus-visible)`，不用 `:focus-within`（焦点走到卡片里的附件与主按钮时会误亮整张卡）。护栏四条见 `standards/coding-standard.test.ts`「界面观感基线」——其中一条数**环的出口**（`RING_OUTLETS` 五条：全局元素规则、`.disclosure-label`、`.scroll-region`、`.single-select-picker-option`、`.composer:has(...)`，多一条要写明它为什么落不到全局那条上），`summary` 的环因此留在基座的类上，不进按元素名点名的清单（「样式表不再点名 details／summary 元素」是本基座自己的牙）。
- **排版、图标与表面也取档，不写裸值**（docs/10 §9.13、ADR-0033）：字号六档 `--font-size-caption|body|emphasis|heading|page|hero`（12／13／15／18／20／28px）、行高四档 `--line-height-tight|normal|body|loose`（1.4／1.5／1.6／1.7）、表面内距四档 `--card-padding`／`--surface-padding-panel|modal|page`、标记方块三档 `--mark-row|card|hero`（24／32／40px）；**图标字形是类型不是数字**——`icons.tsx` 的 `ICON_SIZES` 导出 `IconSize`（12／13／16／18／20），写 `size={14}` 编译不过，`IconButton` 的 `GLYPH_SIZE` 引用同一张表。区块标题一律 18px：页面标题 20px 已由光哥定档（docs/10 §9.7），再留 21px 就是同时供着只差 1px 的两档，层级由「页头带／版心内」与字重承担。例外（图形化标识、`line-height: 1` 的绝对定位角标、成果文档 `.markdown-preview` 排版、非方块的控件几何）只能逐条登记在护栏的 `TYPE_LADDER_EXEMPTIONS`／`NON_MARK_GEOMETRY`／`SURFACE_PADDING`，只降不升；要加档位先改 docs/10 §9.13。
- **一道缝只有一把尺**（docs/10 §9.8）：`gap` / `row-gap` / `column-gap` 与 `margin`（含负值与逻辑属性）共用 4／8／12／16／24／32 六档，由护栏强制，不得再写 5／6／7／9／10／11／13／14／18／20／22px 这类「差一点就一样」的值；要加档位先改 docs/10 §9.8。`padding` 不走这把尺，走上面的控件档位或容器留白。
- 外观由两个维度组成：`system / light / dark` 模式 × 可扩展色系；每套正式色系必须同时提供浅色与深色 Variant。
- **应用主题不得改变 Artifact 自身的文档、演示、表格或图表配色**。
- 中文体验优先；正文和常规控件禁止用小于 12px 的字号换取空间，优先折叠、覆盖和响应式重排。`<small>` 已有 12px 全局基线，组件只在此之上放大，不再逐处补 `font-size`。
- **界面功能图标一律使用内联 SVG 描边图标**（图标集在 `apps/desktop/src/renderer/src/icons.tsx`，`currentColor`、统一 24 网格与笔画粗细）：禁止用 Unicode 字符或 emoji 充当系统操作、导航、按钮等界面图标；新增图标先进图标集再使用，品牌字标与格式徽标（MD/PDF）除外。
- **浮层一律复用 `PopoverMenu` 基座**（docs/10 §10.1）：下拉、菜单、选择器不得用 `<details>` 或 `position:absolute` 面板自造；菜单字号由基座镜像触发控件，破坏性菜单项用 `tone: 'danger'`。护栏锁「`.popover-menu-item` 不自带字号」与「overlay 阴影只允许登记过的浮层表面」。
- **空态一律用 `EmptyPage`（整页／对话列级，可带 eyebrow）、`EmptyContext`（区域级，可换图标）或 `EmptyNotice`（行内与小节级）**（`components/EmptyState.tsx`，docs/10 §10.1）：不得再写 `.empty-*`／`.setting-placeholder` 之类的自造占位类，也不得借首屏 `.welcome` 的品牌 hero 排版当空态——几何一样的两份外观，只差一个「看起来像欢迎页」的理由。
- **状态徽标一律用 `Badge`**（`components/Badge.tsx`，docs/10 §10.1）：只读状态文字用 `tone` × `shape` 表达，不得再写 `*-chip`／`*-badge` 自造一套外观；圆角一律取 `--radius-*`／`--control-radius` 档位，24–40px 高度一律取 `--control-height-*`／`--row-height-*` 档位；带内裸值已清零，例外（文本钳制高度、3–4px 微标）按清单只降不升。
- **页签一律用 `Tabs`、切换按钮组一律用 `SegmentedControl`**（`components/Tabs.tsx`，docs/10 §10.1、§9.10）：`tablist`／`tab`／`aria-selected`、roving tabindex 与左右方向键只有一份实现，页面不得再手拼；选中态样式只住在 `.tabs` 与 `.segmented-control` 上。**两件的 `size` 自 2026-10-01 起必填、与 `Button` 同一张档位表**（原先整条页签带钉死 28px、切换组钉死 32px，所以技能页页头的「卡片／列表」会比旁边的主按钮矮）；它们排在动作里时同样受动作排同档约束。
- **表单字段一律用 `Field` 基座、下拉一律用 `FieldSelect`**（docs/10 §10.1、§9.10）：标签 + 控件 + 说明的纵向结构只有一份，页面不得再写 `label { gap / font-size }` 各调一遍；需要说明文字时给 `controlId` 走 `htmlFor` 关联。**`FieldSelect` 的 `size` 也是必填**（触发器原先固定 32px，与同行的 28／36px 控件对不上）。原生 `<select>` 已全仓清零，不得回归——它的弹层由系统绘制，字号与暗色都脱离 Token。护栏锁「渲染层出现 `<select>`／`<option>`」与「`label` 选择器自带 gap／margin」。
- **单行输入一律用 `TextField`、多行编辑区一律用 `TextArea`**（`components/TextField.tsx`，docs/10 §9.10、§9.13 规矩 11、§10.1，[ADR-0034](../../docs/adr/0034-input-control-base.md)）：`size` **必填**，与 `Button`／`FieldSelect` 同一张「`--control-height-*` × `--control-padding-*`」**成对**档位表——只对齐高度不对齐内距，同排的输入框与按钮仍是一个饱满一个瘦；它排在动作里同样受动作排同档约束。**`TextArea` 没有档位**（高度由 `rows` 与内容决定），内距一律取 `--control-padding-lg`，等宽正文给 `mono` 属性而不是自写 `font-family`。底色、边框、圆角、聚焦环、字号、行高与**只读态**归基座，领域钩子只留位置与尺寸（护栏的例外按 `selector`＋`property` 登记，存量必须与清单等量）。**留原生的只有勾选轴**（`type="checkbox"`／`"radio"`，判据写在护栏的 `CHECK_AXIS_TYPES` 上，不是文件清单）与 `Composer` 那一处任务输入区；结构与说明仍归 `Field`（§9.13 规矩 5），不得再写 `.某容器 input { … }` 那样的后代规则。
- **区块头一律用 `SectionHeader` 基座**（`components/SectionHeader.tsx`，docs/10 §10.1）：「小标题（可带 eyebrow）＋ 一句说明 ＋ 右槽动作」用 `title`／`hint`／`eyebrow`／`actions` 四个槽表达，层级由 `block`（页面区块，h2）与 `panel`（面板小节，h3）两档决定；不得再用 `<strong>` 冒充标题，也不得在页面里手写 `section-header*` 槽位类。面板自己的内缩与分隔线写在传进 `className` 的领域钩子类上，不写 `.某面板 .section-header { padding }`；右槽按钮的外观由按钮自己带档位（`Button variant="chip"`／`variant="quiet"`，见下一条），不得靠容器后代选择器发外观。**浮层（`Modal` 的 dialog／sheet）第一个子块同样是它**，右槽 `actions` 放关闭按钮，页面不再写 `<h2>`。**生产代码不得出现裸 `<h1>`～`<h4>`**：出口只有 `SectionHeader`、`PageHeader`、`EmptyState` 三个基座，以及首屏品牌 hero、Markdown 成果正文、设置空间标题带三处登记例外。护栏锁五条，见 `standards/coding-standard.test.ts`「区块头基座纪律」。
- **卡片一律用 `Card` 基座，卡片行用 `ListRow` 的 `card` 档**（`components/Card.tsx`，docs/10 §10.1）：底、边框、圆角与内距只有 `.card, .option-card, .list-row[data-variant='card']` 这一处出口，档位是 `--card-padding`／`--card-gap`；「图标 + 名称 + 署名 + 三行说明 + 展开 + 页脚」用 `leading`／`title`／`byline`／`description`／`children`／`footer` 六个槽表达。领域钩子类（`.skill-card` 等）只留悬停显形与定位差异，**不得再声明 `padding`／`background`／`border`／`border-radius`**，也不得由页面手写 `.card-*` 槽位类。整片可点区只包住「身份 + 说明」，标签行与页脚动作留在点击区之外——点「删除」不该同时进详情。
- **目录条目（专家、技能）的卡片与列表行一律用配对的 `EntryFacts`**（`components/CatalogCard.tsx`，docs/10 §10.1、ADR-0032）：一条条目要交代的五格——身份块／名称／署名／说明／一排动作——由类型强制必填，页面只留一个 `xxxFacts()` 纯函数，两种视图不许各写一遍（G4 把专家页照抄到技能页那次，就在列表档丢了署名）；`onOpen` 与 `className` 是交互与定位、不是事实，拆给外层只有卡片档吃；`CatalogRow` 不接收整行点击，主行动的悬停显形归基座的 `.card-primary`。**说明这一格两档都必须有截断出口**：卡片三行定高、行单行省略，省略号后面那句全文一律由 `Tooltip` 就地补全（docs/10 §10.1、ADR-0032 §决策 9）。配对件与 `Card` 之外不得再手摆 `<Card` 六槽，护栏五条见 `standards/coding-standard.test.ts`「目录条目卡片纪律」。
- **折叠披露一律用 `Disclosure` 基座**（`components/Disclosure.tsx`，docs/10 §10.1）：「点一行展开更多」那一行的几何只有一份——命中区取 `--control-height`、12px 名称、展开后把名称点亮并让标记转 90°，展开内容与那一行之间的缝归 `.disclosure` 自己的 `gap`。`open` 是受控属性，展开状态由基座用 `onToggle` 跟着 DOM 走，页面不得再写一遍 `<details>`／`<summary>`。展开标记由基座画：原生 disclosure 三角在 `summary` 改成 flex 之后会消失，而应用里其他展开控件（导航分组、下拉触发器、工作过程条）本来就画 SVG chevron。领域钩子只留位置与内容差异（`.task-run-history` 的 `border-top`、`.tool-field pre`），不得重述行几何；**浮层仍然不得用 `<details>` 自造**（`PopoverMenu` 那条继续成立），这里收的是就地展开一行，不是菜单。护栏三条见 `standards/coding-standard.test.ts`「折叠披露基座纪律」。
- **按钮一律用 `Button` 基座**（`components/Button.tsx`，docs/10 §10.1、§9.10、ADR-0031）：`variant`（primary／secondary／text／outline／quiet／chip／danger／link）只管颜色，`size`（sm 28／md 32／lg 36）只管几何，两者正交；`tone` 对 `secondary`／`text`／`outline`／`quiet` 四档生效（`neutral` 是缺省，无独立规则）。皮只由 `.btn` ＋ `[data-*]` 一处输出——**生产代码不再出现裸 `<button>`，也不再手写 `className="secondary-button"` 之类的皮类名**；`className` 只承载定位钩子，且**不得引用已被基座收编的类名**（CSS 里那条规则已随收编删除，挂着它就是声称一个不存在的外观）。**`size` 自 2026-10-01 起必填、没有缺省**（`AsyncButton` 同步），「不写」不再是第三种高度——不设「按 `variant` 给条件缺省 `size`」也是同一件事：隐式缺省会造出没人报错的混排。**一排动作的契约单位是「动作排」，与它用了哪个组件无关**：`ActionBar.children`、`PageHeader.leading`、`PageHeader.actions`、`SectionHeader.actions`、`Card.footer`、`ListRow.actions`、`PageToolbar` 的直接子节点都算一排，槽内控件必须同档（护栏登记在 `ACTION_ROW_SLOTS`，新增「一排」要先加进这张表）。**自己写个 `display: flex` 把两颗按钮并排不算落在槽位里**——护栏按那张表查，对这种排是盲的；页面里就地的一排用 `ActionBar as="div"` 承载（docs/10 §9.10）。选档按排的性质：页头与**页面区块头**（`SectionHeader variant="block"`）的 `actions` 用 `lg`，`ActionBar`／`Card.footer`／`PageToolbar`／表单尾排用 `md`，`ListRow.actions`／**面板小节头**（`variant="panel"`）与密集行内用 `sm`，`PageHeader.leading` 的后退入口用 `sm`；**`lg` 只住在页头与区块头**。确实不是动作按钮的形态（选择卡、整片可点的卡片／通知行、下拉触发器、投放区）按理由登记进护栏的 `NON_ACTION_BUTTON_SHAPES`，不得靠加豁免绕过。`IconButton` 走自己的命中区轴 23／28／34，与文字按钮等高不是它的契约，但档位同样必填（见下下条）。护栏九条并做过变异验证。
- **一次就地动作的 busy 态一律用 `AsyncButton`，独立加载行一律用 `InlineLoading`**（`components/AsyncButton.tsx`，docs/10 §10.1）：`disabled`、`aria-busy` 与文案切换由基座一次负责，页面不再写 `busy ? '正在保存…' : '保存'`；只渲染当前那一行文字，两份标签叠占位会把 busy 文案读进可及名称。外观委托给 `Button`，自己不再保留 `variant → 皮类名` 映射。spinner 只有一枚 `.spinner`，不得再写第二套 `@keyframes`。
- **只装一个图标的按钮一律用 `IconButton`，一排「主按钮＋取消」一律用 `ActionBar`**（docs/10 §10.1、§9.10）：图标按钮的 `label` 必填，方块只有 `sm` 23px／`md` 28px／`row` 34px（对齐侧栏行高）三档，**`size` 自 2026-10-01 起必填**（原先的解构缺省 `'md'` 让 18 个调用点里 12 处没写档位也渲染得出来），不得写 `<button><XIcon /></button>` 也不得靠 `.某容器 button` 发外观；未读数一类的附加节点走 `trailing` 槽，不另造带角标的按钮皮；`ActionBar` 把说明钉在左、主行动钉在最右，`children` 按视觉顺序给按钮，并带 `role="group"` 与动作条名称——「取消」一律排在主行动左侧。
- **纵向导航一律用 `NavList`／`NavItem`，切换同一块内容的视图用 `SegmentedControl`**（docs/10 §10.1）：「当前在哪一项」走 `aria-current`（或 `aria-pressed`），不得再用 `className={当前 ? 'active' : ''}` 表达选中；`NavList` 的 `label` 必填，窄栏折叠只换 `--nav-item-*` 自定义属性、不重述几何，文字用 `clip-path` 收掉而不是 `font-size: 0`。护栏锁「已收编导航类不得复活」「`.nav-item`／`.nav-list` 的几何只住在基座」「生产代码的 `className` 里不再出现 `active`」。
- **列表行一律用 `ListRow` 基座**（`components/ListRow.tsx`，docs/10 §10.1）：「图标／徽标 + 标题 + 说明 + 次要信息 + 右侧动作」用 `leading`／`title`／`detail`／`meta`／`actions`／`trailing` 槽位表达，外壳只取 `divider`／`card`／`plain` 三档；结构特殊的行把额外内容作为 `children` 交进主区，不得另起一套行几何。整行可点时给 `onClick` + `label`（此时 `actions` 里不能再放按钮），选中走 `selected`，降饱和走 `tone="muted"`／`disabled`；行内文字的字号（标题 13、说明与 meta 12）也只在基座写。护栏锁「2026-09-26 一致性评估 §3.4 那 12 个已收编类的样式不得复活」「行的 `gap`／`padding` 只能由 `.list-row*` 自己的选择器声明」与「留在行上的领域钩子类不得再写行骨架」。
- **布尔设置一律用 `Switch`，多选／全选留原生 `checkbox`**（`components/Switch.tsx`，docs/10 §10.1）：「这一项是开还是关」与「这些项里勾了哪几个」是两种事实，不得为了观感统一互相塞。开关的 `label` 是**恒定名称**，状态走 `aria-checked`——禁止再用「开启 X／关闭 X」的按钮文案翻转充当开关（那会让可及名称随状态改变）。需要确认才能改的状态仍由页面弹确认框，未确认前开关保持原状态：开关只负责表达与触发，不接管确认流程。成组的勾选一律用 `CheckList`、MCP 工具绑定用 `McpToolBindingsPicker`，不要就地再排一遍复选框行。
- **只读状态片一律用 `Badge`；连接状态用 `ConnectionStatus`**（`components/ConnectionStatus.tsx`，docs/10 §10.1）：`Badge` 的 `tone` 缺某一档（如「成好」）时**补档**，不得回头写「按状态改字色」的领域规则——`Badge` 管外观、tone 表管语义色、页面管措辞，三层各只在一处。
- **卡片描述一律三行定高，截断处交给 `Tooltip` 补全**（`components/Tooltip.tsx`，docs/10 §10.1）：一行也占满三行的高度，卡片才真正等高；`Tooltip` 只在锚点**真的被裁切**时出现，没裁切就不弹——短描述悬停弹一句全文，读起来像控件坏了。不得用 CSS `::after` 或 `title` 属性自造提示。`NavItem` 的名称一律由它承载，定宽列里收短的那一行就是需要读回全文的那一行。
- **定宽列不放出横向滚动条**（docs/10 §9.8）：侧栏 240px、上下文面板 380px、消息中心 360px 与 `Modal` 的 sheet 抽屉 480px 宽度写死，横向溢出只能截断或折行，不能滚动——一条横向杠会把整列的注意力从内容挪到控件上。滚动容器一律 `overflow: hidden auto`；**收短必须落在看得见的边线上**，所以 `display: grid` 的外壳要写 `grid-template-columns: minmax(0, 1fr)`、作为 grid／flex 项的行与 `NavItem` 基座要带 `min-width: 0`（可收缩住基座，领域类只声明占多宽）。定宽表面里的说明文字不得写 `flex: none` 钉在一行——放不下就整句换到下一行。护栏三条并做过变异验证，见 `standards/coding-standard.test.ts`「定宽列的横向溢出纪律」。
- **定宽列里的每一段都要自带内缩，那道内缩只有 16px 一档**（docs/10 §9.8）：上下文面板的列内距不由 `.context-content` 统一给（分隔线要贯通整列宽），所以每一段必须自己套一件带水平内缩的壳——`.context-section`／`.activity-list`／`.brief-panel`／`EmptyContext`。漏壳的那一段会贴到列的左边缘，同列其余段落却缩着 16px，读起来像两副骨架。**有壳还要有档**：并档前同一格散着 12／14／15／16 四种取值，同列相邻两块差 1–2px 而没有任何门禁报错。消息中心的面板头同档；`EmptyContext` 的 28px 是居中空态的四周留白，侧栏与设置左导航的段落是**行**（行的水平缝归 `NavList` 基座，整列的余量归下面那条「列壳」轴），两处都不在这条轴上。新增一段先选壳；新增壳要在 `components/ContextPanel.test.tsx`「上下文面板的分段内缩」的清单里写明理由，而值由 `standards/coding-standard.test.ts`「定宽列段落内缩档位」锁：清单与存量等量、段落壳必须 16px、登记为「不在这一轴」的每一项仍与实测一致。**「谁给内缩」与「空态由谁渲染」是两件事**：空态一律走 `EmptyNotice`／`EmptyContext`，内缩仍由外面那件已登记的壳负责，不得再让一个自造占位类同时管这两件。
- **定宽列「整列的水平余量」也只有一档 16px，由列壳自己给**（docs/10 §9.8）：上一条管列**里**的段落，这条管列壳本身——并档前侧栏 12／设置左导航 20／成果详情左列 10／窄栏 8，谁都不与谁比对。取 16 不取 12：16 已在档位表上（`--surface-padding-panel`，也是 `--card-padding` 的水平格），12 在这一轴没有对应物。于是这道缝只有一个算法：**列壳 16 ＋ 行自己的内距 8 → 行里的图标落在 24；段落壳 16 → 段落文字落在 16**。`.brand`／`.section-label`／`.sidebar-divider` 不再各补一道横向余量，行内距只住 `NavItem` 基座那一处 `8px`——`--nav-item-padding` 那道没人读的 hook 已删，窄栏不得再覆盖成第三个数。新增列壳要在护栏的 `COLUMN_SHELL_WIDTH_OWNERS` 里写明理由；窄栏那两份 8px 与 `.workspace-*` 一族的 6／8／10／12px 分别登记为「不在这一轴」（宽度配平项／控件内距与树层级缩进），不得靠加豁免绕过。护栏四条见 `standards/coding-standard.test.ts`「定宽列列壳内缩档位」。
- **一排就地动作一律横排**（docs/10 §9.8、§10.1）：详情／编辑／删除／启用停用这类次级动作是一**排**，按钮宽度由内容决定、放不下才换行。禁止用 `flex-direction: column` 把它们竖成一列各占一整行——那是表单墙的观感，不是动作条。窄视口 `@media` 里的重排是允许的另一回事。护栏：`standards/coding-standard.test.ts`「动作条不得把一排就地按钮竖成一列」。
- **一张卡片要能自我介绍**（docs/10 §10.1、ADR-0030）：领域卡片按「图标 → 名称＋署名与版本号 → 描述 → 用途标签与状态片 → 就地动作」排，缺行不等于简洁。页脚是一排就地动作，间距归容器 `gap`，**不得用一颗占满整行的「详情」按钮冒充动作区**。卡片主行动可以悬停才显形，但只能用 `opacity`：位置常驻、DOM 与可及树保留、`:focus-within` 必须同样显形；带图标不代替文字。版本号取修订号，不加可随意填写的版本字段。后端会拒绝的操作（改内置、删仍有运行历史的）不得做成按钮让人点了才知道，按来源与引用改给可用入口。
- **带分隔线的小节，线两侧都要有留白**（docs/10 §9.8）：上一块的最后一行（标签行、说明行）不得贴在下一个小节的 `border-top` 上；这道缝由**上一块所在容器**的 `gap`／`padding` 拥有，不在标签行上补 `margin-bottom` 凑数。详情页头部（署名·版本／简介／用途标签）因此包在 `.expert-detail-head` 里由 `gap` + `padding-bottom` 负责。
- **同一块内容的卡片／列表切换一律用 `ViewContainer` ＋ `SegmentedControl`，模式偏好走 `hooks/use-view-mode.ts`**（docs/10 §10.1）：读写与 storage 兜底只有一份，每页用自己的 storage key；不得在页面里再写一遍 `localStorage.getItem` 读模式。
- **模态与覆盖层一律复用 `Modal` 基座**（docs/10 §10.1）：夺走整页焦点的表面用 `components/Modal.tsx` 的 `dialog`／`sheet`／`viewer` 三变体；锚定在触发器局部的覆盖层（消息中心）用同文件的 `useOverlaySemantics`，只借语义不借定位。inert、Esc、背板关闭、初始焦点、Tab 循环、焦点归还、`aria-modal` 全仓只有一处实现，页面里不得再写一遍；触发元素必须带 `aria-haspopup="dialog"` 与 `aria-expanded`。护栏拦「出现 `role="dialog"`／`aria-modal`／`key === 'Escape'` 却没接基座」的情况。模态内可以开 `PopoverMenu`：层级上浮层高于模态，Esc 被浮层吃掉时模态不关，焦点在浮层里时面板 Tab 循环不抢焦点——这三件事都由基座负责，页面不得自己补。
- **一条发言与任务输入区一律走 `MessageBlock`／`Composer`**（docs/10 §10.1）：气泡的发言者标签、正文排版与**就地动作**是一个块——动作住在气泡外面时只能靠负 margin 追回下缘，那条负 margin 记录的是「这两块本来属于同一件事」这个没写下来的事实。整段 `<form className="composer">` 归 `Composer`，页面只给状态与回调：提交与 ⌘／Ctrl＋↵ 共用一个 `onStartRun`，输入法组合中的 Enter 不提交；`submit` 用 idle／starting／running 三档可辨识联合表达「这颗主按钮现在是什么」，与「运行中是否锁绑定区」分列——停止按钮要求确实有一次可停的运行。护栏锁两条：基座之外出现气泡或 composer 表单结构、以及「状态 · 时间」这句运行摘要在 `RunSummaryRow` 之外再拼一次，即失败。
- 长操作三要素缺一不可：可见状态、取消入口、明确结果。
- 反馈先按 `docs/10-ui-ux-system.md` §11.5.1 决策表归类，**只有三个落点、每个落点只有一个出口组件**：用户当场发起、当场可见的结果（成功/信息/拒绝/失败）→ `TransientToast`（自消、不落库）；需要停留且当前表单/对象可据以行动的错误或警告 → `InlineError`（`components/InlineError.tsx`，danger／warning 两档，`message` 可省、只给 `problems` 也行）；用户可能已切走的长操作结果 → `NotificationService` 进消息中心 + 全局 `ToastHost`（同页抑制）。**一次结果只有一个落点**：调用链上最先能承载这条消息的那一层负责呈现，再把同一句话上传到另一个通道即重复播报，IPC 收口因此二选一——已有内联/浮层承载的走「只记录」那一类（`trackAction`），还没有任何出口的走「让用户看见」那一类（`reportAction`，或手写 `catch` 把失败交给同一个出口）；**出口不必是全局的**，接在局部 `TransientToast` 上同样合规（docs/12 §5 的 Renderer 小节、§8）。**两个 toast 不可混用**：`TransientToast` 局部自消，`ToastHost` 是已持久化通知的投影；短时确认严禁走 `NotificationService`。两个浮层共用 `#toast-stack` 一枚堆叠容器，页面不得再给自己的提示块写 `position: fixed`。禁止页面/Hook 自造 Toast、顶部横幅（常驻或固定悬浮皆算）、自动消失计时器，也禁止给内联反馈块长出 danger／warning 以外的配色档（那条管的是**表面**——有底有内距的块；分界看「说的是哪一件事」，不看「有没有底」——一句无底纯文字，讲的是动作结果就仍归本轴，讲的是「这个对象现在是什么」才走 §11.5.2 的 `StatusNote`）。**未读数只数还需要处理的**：`level: success` 的通知落库即已读、不弹浮层，铃铛数字不涨。全仓旧内联错误表面（`.inline-message`／`.field-error`／`.memory-warnings`／`.knowledge-issues`／`.artifact-action-error`／`.memory-projection` 等）已 100% 迁入基座并登记「不得复活」；`role="alert"` 只允许出现在 `InlineError` 与 `EmptyState` 的整页错误态。护栏见 `standards/coding-standard.test.ts`「反馈通道纪律」与 `SkillsView.test.tsx`。具体工程约束见 `docs/12-engineering-standards.md` §8。
- **一句只读状态说明一律用 `StatusNote`**（`components/StatusNote.tsx`，docs/10 §11.5.2）：状态轴说「这个对象现在是什么」，反馈轴（§11.5.1）说「你刚做的那一下怎么样了」，两轴各只有一个出口。基座无底、无内距、不自带上下缝（缝归容器 `gap`），档位只有 `neutral`／`success`／`warning`／`danger` 四档——`--info` 属通知等级词汇，不为它补第五档。**不得用它承载操作结果**：「已保存」这类一次性确认走 `TransientToast`，写成常驻一行就是换个类名的成功横幅；判据是「这句话明天还成立吗」。11 个自造状态说明类（`.success-copy`／`.skill-blocked-reasons`／`.expert-card-status`／`.memory-dependencies`／`.memory-duplicate-hint`／`.memory-policy-hint`／`.memory-pending-governance`／`.appearance-note`／`.action-note`／`.context-hint`／`.context-phase`）与 `.danger`／`.danger-text` 裸字色 utility 均已登记「不得复活」。**两处有意保留**：`.dependency-warning`——`Field` 的 hint 是 `<span>`，块级基座放进去是非法 HTML；`.context-note`——上下文面板里「该怎么读这一段」的说明（3 处）既不是「这里没有东西」也不是「这个对象现在是什么」，不属这两条轴，所以留一个类、但只留一个（`.context-hint`／`.context-phase` 与它只差字色，2026-09-29 逐句分类后退役：空态归 `EmptyNotice`、对象状态归本基座）。护栏四条见 `standards/coding-standard.test.ts`「状态呈现纪律」。
- 过程信息按用户目标分组并渐进披露；原始 Run 事件不得成为默认主界面的视觉中心；不展示模型私有思维链。
- Artifact 是一等界面对象；右侧上下文面板按场景出现且必须允许完全收起。
- 模型配置使用独立设置空间，不嵌入 Composer 或任务消息流。
