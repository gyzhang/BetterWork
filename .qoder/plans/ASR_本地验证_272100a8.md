# ASR 本地 CPU 推理验证

## 目标

在用户的 Mac（macOS arm64）上验证两个 ASR 方案的可行性，产出量化对比数据，为后续 ADR 和集成决策提供依据。

## 验证范围

| 方案 | 模型 | 大小 | 运行方式 |
|------|------|------|---------|
| FunASR SenseVoice q8 | SenseVoice-Small GGUF | ~254 MB | 单二进制 + VAD，纯 CPU |
| whisper.cpp small | Whisper Small | ~466 MB | C++ 二进制，Metal GPU / CPU 两种模式 |

## 验证步骤

### Step 1：环境准备

- [ ] 在 workspace 外创建临时验证目录 `/tmp/asr-validation/`
- [ ] 下载 FunASR macOS arm64 预编译二进制 + SenseVoice q8 模型 + FSMN-VAD 模型
- [ ] 下载或编译 whisper.cpp macOS arm64 二进制 + small 模型
- [ ] 准备测试音频：中文朗读 ~30s、英文朗读 ~30s（16kHz mono WAV）

### Step 2：FunASR SenseVoice 验证

- [ ] 运行中文测试音频，记录：转写结果、推理耗时、内存占用
- [ ] 运行英文测试音频，记录同上
- [ ] 验证 VAD（语音活动检测）是否正常工作
- [ ] 测试长音频（>60s）的稳定性

### Step 3：whisper.cpp 验证

- [ ] Metal GPU 模式运行中文测试音频，记录：转写结果、推理耗时、内存占用
- [ ] CPU-only 模式运行同一音频，记录同上（对比 GPU 加速效果）
- [ ] 英文测试音频重复上述流程
- [ ] 测试 tiny 模型（~75 MB）的准确率作为轻量备选参考

### Step 4：对比与总结

- [ ] 整理对比表：准确率（CER/WER）、推理耗时、内存占用、模型大小
- [ ] 评估"语音输入替代打字"场景的可用性（延迟是否可接受）
- [ ] 写验证报告到 `docs/logs/2026-10-17.md`
- [ ] 根据结果决定是否需要追加 ADR

## 成功标准

1. 两个方案都能在 macOS arm64 上成功运行
2. 中文转写 CER < 15%（可用门槛）
3. 30s 音频推理耗时 < 5s（用户体验可接受）
4. 内存占用 < 1 GB（不影响日常使用）

## 不做的事

- 不修改 BetterWork 代码（纯验证，不集成）
- 不验证流式/实时 ASR（先验证离线转写，流式是下一步）
- 不验证 TTS（本轮只做 ASR）
- 不写 ADR（验证通过后再写）

## 预计耗时

~1-2 小时（下载 + 运行 + 整理报告）
