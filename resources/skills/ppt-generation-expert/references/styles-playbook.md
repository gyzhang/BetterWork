# 叙事方法手册（借鉴 ppt-master styles）

内容规划阶段（写 SVG 之前）先定"叙事风格 + 页面角色序列"，再动笔。**模板档案（`templates/<公司>.md`）与铁律始终优先于上游风格默认**——本手册只提供方法与页序，不覆盖配色与字号纪律。

## 1. 选型决策树（先问三个问题）

```
受众会逐条审阅并追问出处吗？ ──是──▶ mbb-consulting（document density，桌面阅读）
                            └─否─┐
同一套指标下个月还要再看一次吗？ ──是──▶ operating-review（每期同形，便于逐期比较）
                              └─否─┐
这份材料要用来争取资源或立项吗？ ──是──▶ investor-pitch（凭证据而非形容词）
                              └─否─┐
受众要当场依据它做判断（而非事后背条款）？ ──是──▶ duty-manual（可判断的标题 + 判断轴）
                                        └─否──▶ consulting-decision（通用兜底）
```

## 2. 五套风格对比（本 skill 常用）

| 风格 | 一句话 | 页序基准 | 标题形态 | 专属包 |
|---|---|---|---|---|
| `operating-review` | 结果→偏差→主因→担当行动，深度跟随重要性 | 12 页（计分卡/趋势/偏差分解/异常/对标/行动） | 断言式（含方向） | ✅ `styles/operating-review.md` |
| `mbb-consulting` | 金字塔 + 动作标题 + 编号图表 + 关键信息栏 | 14+ 页（执行综合/诊断/建议/决策请求/附录） | 两行动作标题 | ✅ `styles/mbb-consulting.md` |
| `duty-manual` | 机制先于规则，全册一条判断轴 | 按章（影响开场/机制/轴总览/分档/清单/反例） | 可判断的句子 | ✅ `styles/duty-manual.md` |
| `consulting-decision` | 答案先行、证据紧随，每页一个支配性问题 | 通用（见 `styles-playbook.md §3`） | 断言式 | 内联（§3） |
| `investor-pitch` | 一条通往"是"的最短诚实路径 | 13 角色（见 `styles-playbook.md §4`） | 主张本身 | 内联（§4） |

**三套新包共有的落地裁决**（写成包就是为了一次性解决这些冲突）：

| 上游默认 | 本管线裁决 |
|---|---|
| 状态色绿／琥珀／红、荧光强调色 | **一律改色板内方案**（色板唯一事实源 = `spec_lock.md`，`verify_palette.py` 机械校验） |
| 脚注/标注 10–12px、无字号下限 | **字号下限 13px**；密度靠"减模块/删内容"调节，不缩字号 |
| duty-manual 整册暗底 | **改白底**（铁律 10）；保留左边缘章节进度条等装置 |
| mbb "无卡片无阴影" | 该风格页用"发丝线分区 + 左侧强调条"替代圆角卡片；**同册不混用两种** |

**跨包不混用的三条硬边界**（2026-09-29 补：三份包各自带一套色/形/外框裁决，混用会产出"看着合规但没有叙事逻辑"的册子）：

1. **强调色分工不跨包借用**——`operating-review` 是唯一定义了**状态语义**的包（达标 `#00D3E4` 青 / 关注 `#266DE7` 亮蓝 + 文字标签 / 偏离 `#DF203C` 红）；`duty-manual` 与 `mbb-consulting` 只定义**强调**（关键量/紧张点 = `#266DE7` 亮蓝）。做月报时若套用 mbb 的"强调用亮蓝"，会与 operating-review 的"临界用亮蓝"撞成同一含义两种取值。
2. **容器圆角是风格标识**——`duty-manual` 用 `rx=0` 细线方框（手册性格），`mbb-consulting` 用发丝线分区不用圆角卡片，其余用 `rx=8` 圆角卡。**同一册只取一种**，不要逐页自由发挥。
3. **页例外框（chrome）是成套的**——`mbb-consulting` 的编号徽标 / 单位行 / 章追踪器 / 脚注编号必须整套上或整套不用；只上脚注不算 MBB 风格，反而像漏做了东西。

**与根本事实源的关系**：三份包只回答"叙事怎么落地"，**色/字/版式的唯一事实源仍是 `spec_lock.md`（色、字）与 `templates/<公司>.md`（版式）**——包里的落地裁决表是这两者的子集视图，不是第二事实源，冲突时按后者执行。

## 3. consulting-decision（咨询决策式）——通用兜底

**一句话**：答案先行、证据紧随，每页回答一个支配性问题。

**金字塔叙事**：支配性问题 → 总答案 → 关键支撑论点（3~4 个）→ 每个支撑的页级证据。全册保持可追溯：`总答案 → 支撑 → 页消息 → 证据`。

**页面消息纪律**：
- 标题写成**断言**（"算力需求缺的是供给，不是需求"），不写成话题标签（"英伟达财报情况"）
- 每页一个支配性问题；支撑证据放在答案的正下方或旁边
- 一页只承载一个论点；两个需要分别权衡的论点拆成两页

**主张纪律（四分法）**：事实、假设、推论、建议必须语义分离——事实给出处、假设标不确定性、推论从可见证据推导、建议配理由与行动。永远不把无支撑的主张升格为结论。

**页序要点**：封面 → 执行综合（总答案+支撑索引）→ 支撑论点逐页展开（每页"断言标题 + 证据在旁"）→ 分论点收敛（结论条）→ 行动/请示 → 附录证据。

**图表纪律**：从"决策问题"出发选图（见 `charts-library.md`）；直接标注数值；标明单位与来源行；删掉无助于解读的图例/网格线/装饰。

**视觉倾向**：中性底色 + 少量语义强调色；相关系列用同色系深浅（不用彩虹色）；去装饰性卡片/渐变/发光。

## 4. investor-pitch（投资路演式）——争取资源、产品推介

**一句话**：给决策者一条通往"是"的最短诚实路径——凭证据而非形容词。

**叙事弧**：为什么是现在（世界发生了什么变化）→ 问题与代价 → 方案与证明 → 市场与商业模式 → 团队 → 这笔投入买到什么。按阶段配重：早期靠洞察与团队，后期靠进展与单位经济。

**页面消息纪律**：
- 标题就是主张本身（转发出去没有讲解人也能读懂）
- 每页一个主张 + 页面上可见的证据；指标与它的定义同页出现
- **四类区分**：已实现（achieved）/ 已签约（contracted）/ 在管道（pipeline）/ 预测（projected）必须视觉可辨，预测不得借用结果的信用
- 经不起尽调的主张直接删除，而不是弱化措辞

**页序要点**（13 角色）：Why now / 问题 / 方案 / 产品证据 / Traction / 商业模式 / 市场空间（自下而上推导）/ 竞争（诚实对比）/ GTM / 团队 / 财务与计划 / The ask / 尽调附录。

**市场空间纪律**：自下而上（客户数×单价）推导，展示推导过程，不堆同心圆大数。

## 5. 与本管线结合（工作流插入点）

1. **规划页序**：按 §1 决策树选风格 → 读对应包（或 §3/§4）→ 列出页面角色序列（每页一句"页面职责"）+ 为每页选定图形域（查 `charts-library.md` / `charts-atlas.md` / `diagrams-library.md`）→ 再进入 SVG 编写
2. **断言式标题检查**：交付前自查——标题是主张还是话题？证据在主张旁边吗？（写入 `pages.json` 的 `title` 时同样适用）
3. **月报/复盘**：用 `operating-review`——它的"每期同形"特性对周期性汇报价值最大
4. **争取资源/立项汇报**：用 `investor-pitch`——Why now 页定调，The ask 独立成页
5. **制度/手册类**：用 `duty-manual`——但**视觉必须按包内 §6 改白底**，不要照搬上游暗底
6. 风格方法论提供"方法与默认"，**已注册模板的色板与版式（`templates/<公司>.md` 档案）始终优先**；冲突一律按包内"落地裁决"表执行
