# 关系图 / 结构图骨架库（skill 自持 8 个）

`assets/diagrams/<key>.svg`——**1280×720 规范化 SVG，可直接拷进 `svg_output/` 当页面起点**。全部已过质检门（`quality_gate=passed`），配色为模板色板，字号在档案 §4 档位内（13/14/16/22px）。

## 0. 为什么单列一个库（而不是塞进 chart/）

ppt-master 上游把图形分三个信息模型，**各有归属**（`references/executor-chart.md` / `executor-structure.md` / `executor-table.md`）：

| 信息模型 | 判据 | 上游机制 | 本 skill 取用方式 |
|---|---|---|---|
| **值驱动** | 数值决定条长/点位/角度/面积/半径 | `chart/<key>`，33 个骨架 | 拷 `$PPTM_HOME/skills/ppt-master/templates/charts/<key>.svg`（见 charts-library.md） |
| **拓扑驱动** | 只由顺序/分组/包含/因果/命名区域决定形状 | **上游刻意不设目录**（"no Structure catalog"），要求按关系原子现场组合 | **本库**：把工作汇报里高频、结构固定的 8 类固化成骨架 |
| **行列定位** | 行表头 × 列表头共同定位每个事实 | `table/<key>`，6 个骨架 | 拷 `$PPTM_HOME/skills/ppt-master/templates/tables/<key>.svg` |

关系原子对照（决定了每类的结构规则从哪里来）：`order`（顺序/路径）、`link`（依赖/往来）、`parent`（隶属/分解）、`membership`（归属/泳道/区间）、`contrast`（对比）、`overlap`（共享）。本库每个骨架在文件头注释里标明了它用到的原子。

## 1. 选型（先想关系，再挑图）

| 你要表达的关系 | 骨架 | 拓扑原子 | 典型页面 |
|---|---|---|---|
| 谁向谁汇报、谁归谁管 | `diagram/org_chart` | `parent` | 组织架构、责任分工、编制归属 |
| 先后顺序、有分支有回退 | `diagram/flow_chart` | `order` + `link` | 审批流、作业流程、处置流程 |
| 主体与多个外部系统的往来强度 | `diagram/network_graph` | `link`（hub 星型） | 系统集成、接口依赖、协作网络 |
| 关键事件按时间先后排列 | `diagram/timeline_chart` | `order` | 演进历程、政策节点、版本里程碑 |
| 把周期切成阶段并标验收点 | `diagram/milestone_chart` | `order` + `membership` | 项目阶段、验收计划、交付节奏 |
| 多条线在同一时间轴并行推进 | `diagram/roadmap_chart` | `order` × `membership` | 产品路线、能力规划、多线并进 |
| 任务 × 期次的排期与进度 | `diagram/project_schedule_table` | 行列格 + 期次驱动 | 交付排期、进度总表、资源计划 |
| 层级构成、越往上价值密度越高 | `diagram/pyramid_chart` | `parent`（分解）+ `contrast`（位阶） | 市场分层、客户价值金字塔、人才梯队 |

**互斥边界（最容易挑错的三组）**：
- `diagram/timeline_chart` 只放**时间点事件**；一旦要表达**区间/时长**就用 `diagram/milestone_chart`；一旦要表达**任务级起止与工时**就用 `diagram/project_schedule_table`（要资源泳道和依赖线则用 `chart/gantt_chart`）。
- `diagram/org_chart` 只表达**层级归属**；节点上挂数值并按大小排序属于值驱动，改用 `chart/horizontal_bar_chart`。
- `diagram/network_graph` 表达**强度/往来**；有明确先后的流程改用 `diagram/flow_chart`。
- `diagram/pyramid_chart` 的层宽是**示意化**的（不编码真实比例）；层宽要编码真实数值并精确对比 → `chart/horizontal_bar_chart`；逐层转化递减（漏斗语义） → `chart/funnel_chart`。

## 2. 共用的结构纪律（8 个骨架都遵守，改图时必须保持）

0. **元素分组（2026-09-16 起强制）**：根 `<svg>` 带 `data-pptx-page-role="content"`；白底 rect 作根图元（`id="page-background"` + `data-pptx-role="background"`）**不建组**；每个逻辑模块一个带描述性 id 的顶层 `<g>` 并声明 `data-pptx-bounds`；内部子单元（图标+文字、数值+标签）用嵌套 `<g>`（可匿名、无需 bounds）。**相邻模块区不得重叠超 1px**，bounds 须完整包住组内元素（含 descender，四周留 ≥4px）。实测收益：导出产出真正的 PowerPoint 命名分组，用户可一次点选整个卡片。
1. **标题区禁入**：y58~114 不画任何元素（标题由公司模板版式占位符承载）。
2. **坐标域**：内容 y135~690、安全边距 x70~1210；底注 y≤690。
3. **顶部结论条**：`rect x70 y135 w1140 h50 rx8 fill #E4E6EA` + 左侧 `w6` 主蓝色条 + 两条 14px 断言式文案。这是全库统一的"页首结论"语言，保证相邻页骨架差异化但密度一致。
4. **图例/边界说明**：底部用 14px 灰字写明"实线/虚线/颜色分别代表什么"，并说明本图的**结构不变量**。少了这句，下一轮改图极易把语义改乱。
5. **字号只用 spec_lock `## typography` 声明的角色值**：13（辅助注释，下限）/14（正文）/16（节点与小标题）/21（强调）/22（大数字）/24（卡片标题）——新项目照抄 `tests/fixtures/spec_lock.full.md` 的标准块。**下限 13px，禁止 11~12px**（档案 §4 实操口径同为「辅助注释 ≥13px」，styles-playbook.md §2 落地裁决表把它列为硬性裁决）。注意档案 §4 另有一张母版 pt→px 档位表，两者口径不同：遇到冲突时按 **spec_lock 角色值**执行，并复核 spec_lock 里是否已声明该角色。
6. **配色只用模板色板**：`#0C2864 / #1B4593 / #266DE7 / #048AE3 / #00D3E4 / #778495 / #E4E6EA`，红色 `#DF203C` 仅用于异常/风险且单页 ≤5% 版面。
7. **状态三态可辨**：已落地 / 进行中 / 计划中 必须**同时**用填充、边框虚实、文字颜色区分，不得只靠文字。

## 3. 逐类改法与常见错误

### 3.1 `org_chart`（组织架构）
- **改法**：层距 120px（y 225 / 345 / 465）；第 n 层节点 x = 层中心 − 节点宽/2；父子干线 y = 父节点底 + 23px，子顶 = 干线 y + 45px；节点等宽等高（52 / 50 / 46px）。
- **错误**：① 用节点大小编码人数——层级图不编码数值，人数写在节点副注或右栏；② 子节点不等宽导致分支视觉权重失真；③ 用虚线画行政汇报线。
- **上限**：单页 ≤3 层；同级 >6 个节点时按业务域拆页，或改为"部门 + 编制表"两栏。

### 3.2 `flow_chart`（流程图）
- **改法**：节点等高 56px，行距 215px（y 245 / 460）；同排水平净距 ≥50px；箭头＝轴线 + 实心三角（三角 14×20px，顶点落在目标节点边缘）；箭头轴长 ≥34px 才清晰。
- **错误**：① 分支不带条件标注（必须写"通过/不通过"这类判据）；② 多个判定节点串成网状——超过 2 个判定就应拆页或改为 swimlane；③ 用箭头方向代替关系强弱。
- **上限**：主路径 ≤6 个环节、判定 ≤2 个；超出改用 `roadmap_chart` 的分阶段表达。

### 3.3 `network_graph`（关系网络）
- **改法**：hub 半径 72px、叶节点 52px；叶节点按 hub 为中心均匀分布，圆心距 210~230px；**线宽编码强度**：`边宽 = 1 + 2 × (强度 / 最大强度)`；右栏强度条 `长 = 190 × 强度 / 最大强度`。
- **错误**：① 叶节点半径编码调用量（那是值驱动，改用 `chart/bubble_chart`）；② 叶间随意连线造成"全连接"假象；③ 强度只写在边旁不编码线宽。
- **上限**：叶节点 ≤6 个；更多时按"核心/外围"分层，或多页分组。

### 3.4 `timeline_chart`（事件时间轴）
- **改法**：事件点 x 均匀分布、间距 180px；卡片 180×76px（以事件点居中）；上排 y=300、下排 y=470；主轴 y=420、点半径 9px；刻度线连接卡片与主轴。
- **错误**：① 事件点上下交替时不检查卡片互撞（相邻两排的 x 覆盖区间必须不相交）；② 已完成段与计划段混用同一线型/点型；③ 一个事件塞多个时间点——区间请改用 `milestone_chart`。
- **上限**：单行 ≤6 个事件点；更多请按年份/阶段分页。

### 3.5 `milestone_chart`（里程碑 + 阶段区间）
- **改法**：阶段带 y=376、高 64px，按数量等分且**首尾相连不留空白**；里程碑菱形半尺寸 18px，**只落在阶段边界**；卡片 220×76px（以菱形 x 居中），刻度线 48px；投入/判据写在带下方并与所属带左对齐。
- **错误**：① 菱形不落在边界上（视觉上会读成"阶段中的随机时刻"）；② 阶段带之间留空白；③ 里程碑写"进展良好"这类不可证伪的判据——必须写成可判定条件。
- **上限**：阶段 ≤4 段、里程碑 ≤4 个；再多请把判据移到附录页。

### 3.6 `roadmap_chart`（路线图 / 泳道 × 阶段）
- **改法**：泳道高 110px、行距 120px（y 254 / 374 / 494）；阶段列宽 235px、列距 245px（x 230 / 475 / 720 / 965）；条目块 = 列 x+18、泳道 y+19、尺寸 199×72px；阶段表头高 44px（y 200）。
- **错误**：① 同一泳道跨阶段换色（同线必须同色系，跨泳道才换色相）；② 一格塞两个条目；③ 计划中用实线框——虚实必须与"是否已落地"一致。
- **上限**：3 泳道 × 4 阶段；超限拆页，**不缩字号、不叠放**。

### 3.7 `project_schedule_table`（项目排期表）
- **改法**：期次列宽 140px、起点 x=370；第 i 期起、跨 n 期的条 `x = 370 + i×140 + 8`、`宽 = n×140 − 16`；行高 54px（首行 y=244）；条高 38px、条 y = 行 y + 8；进度叠加条 `宽 = 条宽 × 进度`。
- **错误**：① 条块不对齐期次格线（半格漂移会让整表失去可信度）；② 任务名同时出现在左列和条内；③ 用文字"进行中"代替进度条长度。
- **上限**：≤8 行任务、≤8 个期次；超出拆页或按季度折叠。

### 3.8 `pyramid_chart`（金字塔构成）
- **改法**：层数 n → 第 i 层 `y = 240 + (i−1)×72`；上宽 = 240 + (i−1)×80、下宽 = 上宽 + 80（每侧每层加宽 40px，四条斜边平行）；中轴 x=430；层内只放占比短文字（16px 白），说明外置右列并与层中线对齐，引线自层右缘中点画至 x=740；左缘竖直注释线表达「价值密度 ↔ 规模体量」反向张力。
- **错误**：① 层宽按真实数据比例画——比例悬殊时底层窄到放不下文字（数据靠文字标注，宽度示意化）；② 各层加宽量不一致导致斜边不平行（同分段漏斗的斜率纪律）；③ 层内塞长文字撑破顶层宽度——说明一律外置。
- **上限**：≤5 层；层内文字 ≤4 字；右列每块说明 ≤20 字。超限拆页或改 `chart/treemap_chart`。

## 4. 与管线配合

1. 拷骨架：`cp assets/diagrams/<key>.svg <project>/svg_output/slideNN.svg`
2. **按本页真实内容替换全部示例文案，并同步改结构**（增删节点/格子时要重算坐标与连线，不能只改字）；**增删模块时同步改 `data-pptx-bounds`**——bounds 不跟着改会立刻触发重叠或溢出报错。
3. **期次/时长驱动的骨架**（`project_schedule_table`）改了期次数或跨期数，要按骨架注释里的公式重算条块坐标（`x = 370 + i×140 + 8`、`宽 = n×140 − 16`）。
4. 增删元素后自检四条：① 是否侵入 y58~114；② 是否越出 x70~1210 / y690；③ 标签是否互撞（改一处坐标必须重新目检全部元素）；④ 模块 bounds 是否仍包住组内元素且互不重叠。
5. 走 `svg_native_export.py` 质检导出（与图表页同一条链路）。

**生成稳定性（机械保障）**：`tests/selftest_e2e.py --suite skeletons` 会把本库全部骨架过一遍质检门与页边界检查；`charts-library.md` / `diagrams-library.md` 里点名的每个骨架 key 都必须真实存在，否则自检直接失败。
