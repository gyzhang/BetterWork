# SVG 转 PNG 旁路

> 仅当用户明确需要图片而不是 PPTX 时加载。该路径不属于 BetterWork 当前声明的 PPTX 命令链；执行前须确认本次运行实际提供了相应渲染工具。

## 1. 旁路：SVG → PNG（书稿配图等非 PPT 交付）

当目标产物是**图片而非 PPTX**（书籍配图、文章插图、报告图解）时，走同一条 SVG 写作纪律，但渲染链路不同：

- **写作照旧**：1280×720（或自定义画布，如竖版封面 1200×1800）、微软雅黑、模板色板、字号只用 spec_lock 声明的角色。**逐元素手写 SVG，禁止 matplotlib 等程序化绘图**（观感差距极大）。
- **质检照跑**：`svg_native_export.py <project_dir>` 仍要跑——它管的是语法合同与字号声明，PPTX 只是副产品，不要都行。
- **渲染走 pymupdf 直读 SVG**（2026-09-10 复验）：`pymupdf.open("x.svg")[0].get_pixmap(matrix=pymupdf.Matrix(2.2,2.2))` → 2816×1584 PNG。**macOS 上这是唯一可靠的中文 SVG→PNG 链路**；LibreOffice 转 PDF 再渲染会静默丢全部 CJK 文本（字体回退失败 + Draw 的 SVG 滤镜缺陷），不要用于中文图。
- **封面等竖版画布**直接写自定义 viewBox 的 SVG 并单独渲染即可，不必强行塞进 ppt169 项目（质检器期望 1280×720，塞进去会被拒）。
- **交付时同时保留 SVG 矢量源**：文件名与正文引用一一对应。用途是做 HTML 阅读版时内联（清晰度无损、可配色主题），以及改数据时只改 SVG 重渲染、无需重画。
- **质检告警分流**：`quality_gate=passed` 即视为可交付。两类常见告警**无害、不必为消除它们而改图**——`Noncanonical compact authoring`（样式压缩建议）与 `paragraph-like line run split across sibling <text>`（建议把折行文案合并为单 text+tspan）。真正要处理的是含 `exceeds ... data-pptx-bounds` 的告警（修法见下方排障区对应条目）。
- **分组边界留白**（2026-09-10 实测）：`data-pptx-bounds` 的判定按**文本 bbox 含 descender** 计算——文字基线 y 与分组下界的净距要留 6px 以上；贴着下界写会告警。短柱的数值标签一律放柱**右**（放左侧 end-anchor 会与左侧类别标签相撞）。
- **折线图上的说明文字要算完再放**（2026-09-10 两次实证）：给曲线加文字标注时，先按该 x 位置**插值算出曲线的 y**，再决定基线坐标；凭感觉放在"中间"很可能压到线上。两条曲线之间的填充区越往左越窄——标注一律放在**间隙最宽处**（通常是右侧 2/3 处），窄的地方放不下就换位置而不是缩字号。同理，标注与相邻曲线的垂直净距要 ≥12px（含 descender）。
- **改图后必须重新目检全部元素**：调过一次坐标（哪怕只挪了一个标签）就要重新渲染并放大过目——坐标是相互咬合的，修一处常挤到另一处。渲染 PNG 后用 `Read` 直接看图，不要只看质检报告。
