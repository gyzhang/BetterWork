### 2.5 几何一致性校验（数据页必跑，导出前）

```bash
PPTM_HOME=/path/to/ppt-master python3 scripts/verify_geometry.py <project_dir>
```

读页面里的 `<!-- chart-data: ... -->` 声明 → 用上游计算器重算权威坐标 → 与 `<g id="<object>-area">` 内实际绘制的标记逐个比对（容差 2px）。**抓的是静态质检抓不到的那类错**：改了数忘了重算几何、抄骨架忘了换算——SVG 语法完全合法，只有把坐标算一遍才发现。实测能精确报出偏差（`第 3 项超出 2px：465.0→500.0, 135.0→100.0`）。

值驱动页必须在图表组内写两条标记（`object=<key>` 为组前缀）：
- `<!-- chart-plot-area: object=<key> | x_min,y_min,x_max,y_max -->`（上游契约；radar/pie 用 `center: cx,cy | radius: r` 形式）
- `<!-- chart-data: object=<key> | calc=bar|line|radar | labels=... | values=... | area=... | value-range=... | bar-width=... -->`（本 skill 契约，供校验器重算）

`calc` 不在 `bar/line/radar` 内时校验器判 `manual-verify` 只出 receipt 不判失败——**诚实标注，不假装验过**；此类页按骨架内注释的公式人工核对（如堆叠柱属上游 `decomposable-calc`，需在骨架注释里写明分段公式）。

**真实交付实测（2026-09-16，14 页经营分析）**：12 个内容页中 6 个图表对象走 `calc=bar/line` 自动校验全部 `status=ok`；堆叠柱两页按 formula-verify 处理。**分组带来一个易误判的现象**：合并时 `merge_into_template.py` 打印的「移植形状 N 个」会从数十个降到 **5~8 个**——因为顶层现在是分组，`migrate_shapes` 数的是 spTree 的直接子级。这不是丢形状，用 `p:grpSp` 与 `p:sp` 计数复核即可（该次交付：14 页 / `p:pic=0` / `p:grpSp=84` / `p:sp=812`）。

### 2.6 版式适配校验（所有页面必跑，导出前）

```bash
python3 scripts/verify_layout.py <project_dir>
```

**几何校验管「标记画得对不对」，版式校验管「文字放得下放不下」——两者互补，缺一必翻车。** 按 Microsoft YaHei 度量估算文字包围盒，跑四个检查族：

| 族 | 判据 | 级 |
|---|---|---|
| **L1 标签压条** | 深色文字与深色条/块重叠 → 对比度不足，字「消失」在条里 | error |
| **L2 出容器** | 卡片/表格面板内的文字越过边框（含 descender）→ 边框切断文字 | error |
| **L2 过紧** | 文字距边框 <6px（默认留白） | warn |
| **L3 出安全区** | 文字侵入标题区（**校验判据 y<120**）或越出页面/页脚带 | error |
| **L4 文字互撞** | 两段文字两轴都重叠 ≥2px 且面积达较小者 20% | warn |
| **L5 装饰条不吻合** | 卡片边缘的同色窄条是直角矩形，戳出宿主圆角轮廓 → "条是方的、卡是圆的" | error |

**三个相近数字不要混淆（2026-09-29 澄清）**：模板档案 §6 的**书写纪律**是标题占位符区 **y 58~114 禁绘**、内容主体从 **y ≥135** 起；而 L3 的 **y<120** 是校验器的**宽松判据**。落在 114~120 之间的元素能被 L3 放行，但**不符合书写纪律**——一律按 **114** 执行。

L5 的修法是**批量工具**（不改文案、纯几何改写，导出后仍是原生可编辑形状）：

```bash
python3 scripts/round_accent_strips.py <project_dir> [--apply]
```

先干跑看清单，确认后加 `--apply`；它把 `<rect width=6>` 换成贴边 `<path>`（与宿主同侧的角用宿主半径 r 倒角、纵向取宿主全高）。**骨架库与夹具也必须保持一致**——2026-09-16 实测：7 个骨架 + 2 个回归夹具都带这个缺陷，而它们是所有人拷贝的源头。

**为什么上游质检抓不到**：这些页面的 SVG 语法完全合法、元素也都在声明的 `data-pptx-bounds` 内，上游只验「合同 + bounds」，验不出**空间关系**——不渲染成图根本看不见。2026-09-16 真实事故：4 页数值标签压进深蓝条（字没了）+ 3 张卡片末行被下边框横穿 + 1 页同柱双标签互撞，**全部靠人眼在 PowerPoint 里发现**。现在由 `svg_native_export.py` 的两个闸门挡住，含冲突的页面**根本导不出去**。

校验器会直接给可执行修法，不用自己推：

```
[L1] 标签「652.42　95.61%」与条 (x 330~759) 重叠 95×17px，且同为深色 → 文字不可读。
     修法：value-range 上限 ≥ 890（当前 700），或缩短标签
[L1] 标签「104.15」与条 (x 330~729) 重叠 37×17px … 修法：标签改为 text-anchor="start"，x=737.2（条尾 +8）
[L2] 组「layer-p0」容器 70,200~430,440：文字「负责：财务 + HR｜完成：规则书面化」越过边框 → 下切断 5.4px
```

**误报边界（已验证）**：容器留白设 6px；相邻行（行距 ≥1.05em）在本 bbox 模型下不会互相重叠；浅色字压在深色条上是**有意内嵌**（如堆叠段值用白字），不报 L1。

### 2.7 配色合规校验（所有页面必跑，导出前）

```bash
python3 scripts/verify_palette.py <project_dir>
```

模板档案 §2 明令「**禁止引入色板外颜色**」，但**上游质检、数据几何校验、版式适配校验都看不见颜色**——写页面时"自创一个看起来更柔和的颜色"不会被任何既有闸门拦住，只会在真 PowerPoint 里被肉眼发现（或永远不被发现）。

**色板唯一事实源 = `<project>/spec_lock.md` 的 `## colors` 块**（+ 恒允许 `#FFFFFF`）。需要新颜色时**先加角色到 spec_lock**，而不是直接在页面里写色值。

```
色板（spec_lock 声明 + 白）：#00D3E4 #048AE3 #0C2864 #1B4593 #266DE7 #778495 #DF203C #E4E6EA #FFFFFF
[VIOLATION] p04_cost_structure.svg: fill="#EF9F27" 不在 spec_lock 声明的色板内
```

**2026-09-18 自查战果**：本项目全册扫出 **7 处越板**（琥珀 `#EF9F27`×3、深琥珀 `#854F0B`×3、浅蓝 `#EAF0F8`×1，都是写页面时自创的），**7 个骨架库里又扫出 2 处**（`#2780C8`、`#EAF0F8`）——骨架是拷贝源头，越板会被复制到每一页。全部已归入色板。

**触发这条检查的常见场景**：想区分"中风险"层时自创琥珀色；想加一个浅色底时自创浅蓝。**正确做法**：中风险用 `#266DE7` 亮蓝 + 文字标签补语义；浅底用 `#E4E6EA`。

### 2.8 分组与容器的三条隐性约束（2026-09-19 实测，此前未写明）

**这三条在任何既有文档里都没有，但校验器是这么判的——不遵守会一次性报几百条假阳性。**

| # | 约束 | 违反的后果（实测） |
|---|---|---|
| 1 | **一个容器 rect 必须与「它负责的文字」同处一个嵌套 `<g>`** | `verify_layout.py` 的 `_containers()` 会把 **同一顶层组内全部文字归到该组的每一个容器上**。一次「三卡并排」若把 3 个 `rect` 直接放在同一个顶层组里，两张卡的文字会被判「越过边框」——实测单页报 **25 条 error**，全册 36 页共 **463 条假阳性**。<br>**正确写法**：顶层组只装嵌套组，形如 `<g id="cards-row"><g id="card-1"><rect/><text/>…</g><g id="card-2">…</g></g>`（fixture `s01_summary.svg` 的 `cost-kpi` / `cost-kpi-1` 就是这个形态）。 |
| 2 | **卡内首行基线必须 ≥ 容器 y + 6 + ascent**（ascent ≈ 0.8 × font-size） | 报 `[L2] 距边框 上仅余 1.8px（建议 ≥6px）`。22px 标题的首行基线至少要落在 `y+24`；实测初稿按 `y + size*0.86` 放置，**36 页全部命中该 warn**。 |
| 3 | **相邻模块区的 `data-pptx-bounds` 必须纵向留出 >1px 净距**（x 轴通常同宽，故只有 y 能救） | 报 blocking：`activity-strip overlaps page-footnote by 1122.0px x 3.0px`。**坑在 padding**：给 bounds 写 `height+4` 的余量，会把「实体间距 13px」吃成「bounds 重叠 3px」。写成 `height+1` 即可。 |

**另两条口径**：
- **只有「宽 ≥280 且高 ≥90」的 rect 才算容器**。所以**表格的表头条（高 30）不构成容器**→ 表格内的文字**不会**被 L2 校验（要靠 `build` 阶段的文字宽度自检兜住，见下条）；**四联卡（宽 266）也不构成容器**，同理。
- **进闸门前先在生成器里做一次文字宽度自检**：把每行文字的估算宽度与「容器宽 − 2×padding」比对，超了就报错。实测这一步在跑 `verify_layout.py` 之前就抓出 **8 处超宽文案**（`需 337px > 可用 314px`），比事后改版省事得多。

**LibreOffice 不可用时的替代核验（2026-09-19，本机无 `soffice`）**：铁律 9 的双轨制里，几何轨依赖 `soffice --convert-to pdf`。若该命令不可用（`which soffice` 为空），**不要就此跳过错**——用「源 SVG pymupdf 渲染 + 合并后 PPTX 的 XML 级核验」顶上，四项断言都要跑：

1. `p:pic = 0`（必须是位图零张）
2. `p:grpSp > 0` 且**组名集合 == SVG 里的顶层 `g id` 集合**（证明原生分组真的落地了，用户在 PowerPoint 里能一次点选整张卡）
3. 全册 `<a:rPr sz="…">` 的分布换算回 px 后**只出现 spec_lock 声明的字号**（`sz` 是 1/100 pt，px = sz/100/0.75；实测 980/1050/1200/1650 精确对应 13/14/16/22px）
4. 非占位符元素**没有落在标题禁入区**（y 58~114，与模板档案 §6 一致）

> 这四项能替代 `soffice` 轨的「形状存在性 / 字号 / 版面分区」检查；**替代不了**的是「合并后视觉是否串色/错位」——那一条要在交付说明里**如实告知用户**，并请他在真 PowerPoint 里过一遍。不要因为本机没装 LibreOffice 就省略这句话。


### 2.9 通用版面纪律（模板无关）

- **元素分组**：与 §2 第 4 条**同一套规则**（细则同见 svg-native-guide.md §2）。三处同步，不得各写一套——否则规范会像过去那样分化成"文档说 A、脚本判 B"
- **相邻模块区不得重叠超 1px**（判定需两轴同时超出容差 1.0px）；bounds 必须完整包住组内元素含文字 descender（四周留 ≥4px）
- **横向条图的数值标签一律放条尾外侧**（`x = bar_end + 8`，`text-anchor="start"`），**绝不用 `text-anchor="end"` 锚在固定 x 上**——锚点一旦落进条内，深色字压深色条就"消失"了（2026-09-16 四个页面因此各丢一个数值）。选 `value-range` 时必须预留**标签车道**：`最长条长度 + 8 + 标签估宽 ≤ 绘图区右边界`，否则加大 range 上限（`verify_layout.py` 会算出该给多少）。同一张图内标签格式要统一（都带占比或都不带）
- **卡片高度按末行文字的下沿定，不按行数定**：末行基线 + descender(0.26em) 距卡片下边框须留 ≥6px。定高写死 240 而末行基线落在 242，边框就会把字横切开（2026-09-16 P13 三张卡片同因）
- **同柱双标签要留 16px 以上行距**：柱顶合计与段值若都在柱外，基线间距小于 1.05em 就会挤成一团；段值标签优先放**段内白字居中**（段高 ≥0.9 文字行高即可）
- **卡片边缘的同色装饰条必须跟随宿主圆角**（2026-09-16 Kevin 指出）——**本条是唯一详尽说明**，L5 校验条目与排障条目均指向此处，改判决/工具时**只改这里**：
  - ⚠️ **判据不看条的 rx（2026-09-20 修）**：`rect` 的 rx 是**四角统一**的，改它修不了"同侧两角倒、另一侧平直"这个形状——设小则戳出、设大则右侧也被倒角。所以**带 rx 的条同样是缺陷**（书稿 29 处全是 `rx="2"`，曾因判据看 rx 而对整条工具链隐形，实测 L5 一条不报）。现已改为只要"窄条 + 实心 + 贴宿主边缘 + 落在宿主内"即处理
  - ⚠️ **横条（贴宿主上边的色带）也支持**（2026-09-20 补）：docstring 一直写着"左/顶边缘"，实现原先只做左边。横条是把竖条沿 y=x 镜像，**弧的 sweep 由 0 变 1**——改这里务必重新渲染目检，sweep 写反会得到内凹形状
- 相邻页正文骨架差异化：左视觉+右卡片 / 上流程+下卡片 / 镜像变体，禁止相邻页同骨架
- 信息密度：单页主卡 ≤4 个、卡正文 ≤3 行；反馈"太满"时删行不缩字号、加大间距、次要信息并入标签
- 圆环图用标准 stroke+strokeDasharray 写法保证正圆；小图标用形状拼或 tabler 图标池，不用 emoji
