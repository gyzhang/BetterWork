# 实验、综合项目与评估

状态：仅实验规范。以下素材名称和示例路径描述待编撰的资产；这些文件和可运行练习尚不存在。章节 ID 和前置条件在[课程大纲](curriculum.md)中维护。

## 1. 共享练习模型

所有学员展示基础退出 F01–F04、完成 L01–L20 并交付两个综合项目的基线版本。每位学员选择一个综合项目进行更深入的最終答辩和校园或行业适配。有经验的程序员可以免修基础教学，但不能免修核心成果。

练习通过六个阶段成长：

1. 基础任务：文件、JSON、异步工作、测试和小型表格。
2. 场景对比、模型限制、一次工具交互和有界循环。
3. 确定性工具、MCP、度量检索、上下文/记忆和可复用方法。
4. Harness 边界、持久化、人工检查点和评估。
5. Excel 分析和完整的 Markdown、DOCX 和 PPTX 交付物。
6. 两个集成旅程、应用交付和独立适配。

每个概念从完整示例开始，进入引导修改，以未见过的变体结束。早期起始代码提供传输和设置；学员实现被评估的循环、工具、控制和转换。后续实验减少脚手架。未通过的掌握检查点导致针对性反馈和新变体，不是基于出勤的晋级。

教学代码与生产导入保持隔离。BetterWork 是参考之一，不是决定可教内容的依赖。作者为每项必需能力提供经过测试的教学适配器，包括产品中尚不可用的能力。未来代码遵循现有根目录工具和工程规范；本计划本身不创建运行时或工具配置。

## 4. 综合项目 A：从研究到方案

### 场景简报

选择一个校园团队评估学生社团研究/规划的 Agent，或一个部门团队评估业务 Agent 机会。两者均收到合成的平台描述、用户简报、约束和小型外部参考集合。教师提供所有领域词汇和决策标准；不假设专业的客户交付经验。

任务是决策支持方案，不是自主的组织决策。

### 规划素材包

| 资产 | 内容 | 刻意复杂化 |
| --- | --- | --- |
| `business-brief.md` | 用户角色、痛点、当前流程、期望结果、约束 | 一个需要澄清的未明确需求 |
| `platform-capabilities.md` | 支持的集成、运行时和部署能力 | 一个请求的功能不受支持 |
| `reference-materials/` | 经批准的本地参考文档，含 ID 和定位器 | 两份文档在某需求上不一致 |
| `recorded-web-responses.json` | 固定来源 URL、标题、捕获元数据、摘录/正文和内容哈希 | 一个搜索摘要缺少支持的全文 |
| `source-manifest.json` | 稳定标识、权限、版本信息和预期用途 | 一个来源存在但未被选定用于任务 |
| `injection-example.txt` | 一个明确标记的合成对抗文档 | 来源文本请求访问不相关文件 |
| `review-feedback.md` | 受众或推荐优先级的变更 | 需要在初始大纲之后修订 |
| `proposal-template.docx` | 可再分发的标题、正文、表格和来源样式 | 长表格和标题层级需要审核 |
| `proposal-template.pptx` | 可再分发的可编辑幻灯片布局 | 一张密集幻灯片需要重构 |

捕获的元数据来自实际素材准备；虚构的捕获日期不是证据。实时来源练习保留其自身的捕获来源追溯，不期望精确复现离线文本。

### 必需旅程

1. 澄清问题、决策者、缺失需求和可用来源。
2. 提出有界研究计划并获得审核者确认。
3. 检索本地信息并使用录制的外部响应作为确定性基线；单独在经批准的公开材料上进行有界的实时来源查找并保留其来源追溯。
4. 登记证据并区分有支持的事实、冲突、假设和未回答的问题。
5. 对比至少两种实现方案，包括一个合适的非 Agent 或固定工作流替代方案。
6. 在产出完整文档之前审核方案大纲。
7. 从审核过的内容和证据产出 Markdown 方案、可编辑 Word 文档和可编辑 PowerPoint 演示。
8. 应用审核者反馈并保留前期 Artifact 版本和输入关系。

### 必需输出

- 场景简报和经批准的研究计划。
- 证据登记册，含来源标识、版本/捕获元数据、定位器和摘录。
- 声明-证据对照表；假设和建议分别标注。
- 方案的 Markdown 和 DOCX 版本，涵盖问题、选项、推荐、架构边界、风险和验收标准。
- 面向目标决策者的简洁 PPTX 演示。
- 两种 Office 格式的结构检查、来源映射和人工可编辑性/视觉审核。
- 评估报告，包含成功和刻意不成功的案例。

声明-证据对照表是必修课程交付物。作者在引入更丰富的引用系统之前提供简单的经过测试的表示；学员因可追溯的支持而被评估，不是因复制产品 UI。

### 验收

- 最终方案中的每项事实声明均有来源定位器支持或明确标识为未经验证。
- 冲突的来源被呈现，不被悄悄合并为虚假共识。
- 未选定的材料在教学宿主的工具中保持不可访问。
- 嵌入的指令不能更改工具权限或扩展材料范围。
- 审核者反馈创建新版本而不覆写原始版本。
- 方案可独立于聊天历史阅读。
- DOCX 和 PPTX 均在文档化的办公应用中打开。文本和表格是可编辑对象，不是全页截图；演示编辑和保存每种格式的样本。图表保留文档化的数据映射和可编辑图表或可编辑来源表。
- Markdown/DOCX 标题、表格、声明和来源引用一致；演示可以总结但不能更改经验证的事实。
- 审核未发现裁剪的必需内容、不可读的图表、断裂的来源引用或未标注的不确定性。

Markdown、DOCX 和 PPTX 均为必需。缺失的生成或验证支持是课程编撰问题，需在实验发布前解决，独立于 BetterWork 的发布计划。

## 5. 综合项目 B：从运营数据到管理演示

### 场景简报

学生社团或部门从电子表格导出分析支出和项目进度、讨论异常并创建演示。然后为另一个报告期间重复工作，同时保留定义并替换变化的输入数据。在完整工作簿之前教授一个小型手工验证示例；提供粒度、键、预算、期间、偏差和对账的定义。

教学数据集是规范化的合成导出。不声称每个总账使用相同的符号约定、字段名称或会计规则。真实导出需要经验证的来源到教学模式映射。

### 规划素材包和契约

| 资产 | 粒度和必需字段 | 验证重点 |
| --- | --- | --- |
| `ledger-entries.xlsx` | 每个 `entry_id` 一条记录：`reporting_period`、可选 `project_id`、`metric_code`、带符号的 `amount_minor`、`currency` | 唯一记录、批准的指标映射、整数最小单位、期间/币种一致性 |
| `projects.xlsx` | 每个 `project_id` 一行：项目标签、状态、计划工时、实际工时 | 唯一维度键、允许的状态、显式工时单位 |
| `budgets.xlsx` | 每个期间/项目/指标/币种键一行：`budget_minor` | 无意外重复预算行；缺失预算不同于零 |
| `metric-definitions.md` | 范围、符号、单位、聚合粒度、公式、舍入、排除记录 | 业务审核者在计算前批准定义 |
| `expected-metrics.json` | 独立验证的预期汇总、变化、警告和对账总计 | 标准答案不在被测模型下准备 |
| `previous-report.pptx` | 合成的前期报告 | 历史上下文不是当期数据 |
| `report-template.pptx` | 可再分发的可编辑演示模板 | 资产权益和依赖可用性 |
| `period-two/` | 使用相同文档化模式的新期输入文件 | 一个变更的指标和一个新的数据质量问题 |

素材作者提供清洁包和单独的变异案例：重复键、未匹配项目、缺失值、不兼容币种、无可用的缓存值的公式单元格以及包含指令的来源。

### 计算边界

- 在记录的粒度处汇总总账事实，然后再与项目和预算汇总合并；在关联前后验证关联基数并对账总计。
- 没有明确的业务规则，不得用零替代缺失值。
- 保留币种和单位信息；不做隐式币种转换。
- 期间变化金额 = 当期 - 前期；变化比率在有符号的前期值非零时以其为分母。负基线需要解读警告。
- 预算偏差 = 实际 - 预算；其比率在预算非零时以预算为分母。偏差是否有利取决于指标定义。
- 零分母不产生数值比率并给出警告。缺失的比较值产生不可用的比较，而非编造的百分比。
- 在经验证的数值范围内保留整数最小单位的精确来源金额；舍入和百分比显示规则属于批准的素材规范。
- 缺失的公式缓存不能被悄悄当作重算值。要求可用的导出或显式支持的重算路径。
- 模型可映射和解释经验证的结果；工具执行聚合、关联和算术。

教学实现必须支持文档化的工作簿检查、关联、对账和计算。仅有界的对比辅助工具不能满足本实验；素材 Schema 约束问题但不移除必需的数据工程工作。

### 必需旅程

1. 检查工作簿结构、工作表、关键字段、期间和公式/值状态。
2. 产出数据质量报告并与审核者解决阻塞性歧义。
3. 确认指标定义以及总账、项目和预算数据之间的关系。
4. 执行确定性计算并将结果与独立标准答案对比。
5. 将数值发现与需要额外证据的解释分离。
6. 审核报告大纲，然后生成带来源定位器的管理演示。
7. 使用批准的方法和选定的前期 Artifact 版本创建第二任务，但使用新期输入。
8. 演示一个取消案例和一个重启/返工案例，不发布不完整的输出。

### 必需输出

- 数据质量报告和经批准的输入/指标映射。
- 与标准答案校验的结构化计算和对账结果。
- 区分观察和假设的来源落地叙述。
- 两个可编辑的、期间特定的 PPTX 文件、审核的大纲、输入/版本溯源和修订证据。
- 取消、恢复和评估记录。综合项目 A 提供必需的 Markdown/DOCX 组合；本案例深化电子表格和重复报告能力。

### 验收

- 必需的数值结果在文档化的精度策略下与独立标准答案匹配。
- 总计不因关联而膨胀；缺失或未匹配的记录可见。
- 图表、表格和叙述数字与计算结果一致。
- 材料发现标识相关工作簿、工作表/范围、期间和计算。
- 因果假设被标注；Agent 不单纯从指标变化推断因果。
- 当前输入不从前一期作为隐藏默认值继承。
- 来源工作簿未被更改，输出保持可编辑。
- 重启/取消证据显示显式状态且无重复发布的 Artifact。

## 6. 场景与平台迁移

选择一个场景；全部使用合成数据和咨询输出。校园工作是完全标准的替代，不是对学生的降低评估。

| 场景 | 建议训练场景 | 迁移问题 |
| --- | --- | --- |
| 校园 | 将社团预算 Agent 适配到研究项目进度报告 | 哪些定义和权限变更了？谁验证推荐？哪些学生信息必须保密？ |
| 银行 | 对比操作规程并起草流程改进方案 | 适用哪个政策版本？谁审核推荐？哪些数据不能离开批准的环境？ |
| 能源 | 分析维护/工单导出并总结运营问题 | 数据粒度是什么？哪些结论需要工程师确认？哪些运营操作仍被禁止？ |
| 制造业 | 分析质量/交付导出并准备管理报告 | 批次和时间段可比较吗？缺陷如何定义？哪个系统拥有纠正措施？ |

学员提供平台能力地图，涵盖模型访问、工具注册、标识、材料范围、持久化、人工检查点、追踪、评估、部署和运维。每个差距有缓解措施、负责角色或显式的未解决状态。使用教师选定的框架或文档化平台，不需要客户账户。学员还交付本地 CLI/API 应用，包括设置、安全密钥配置、启停、错误报告和运维说明；仅方案不满足应用交付。

没有练习授权贷款决策、生产控制、设备操作、客户系统回写或合规认证。

## 7. 评估层次

| 层次 | 方法 | 确立什么 | 不确立什么 |
| --- | --- | --- | --- |
| 工具/单元 | 固定输入和独立预期结果 | 计算和校验行为 | 端到端模型质量 |
| 运行时集成 | 脚本化 Provider、注入检索/MCP、持久化状态测试 | 顺序、范围、取消、恢复和绑定行为 | 真实服务连接或有用叙述 |
| 检索 | 同一语料库上的标签查询；关键词/嵌入对比固定 top-k | Recall@k、无关命中和文档化的相关性权衡 | 回答正确性或嵌入的普遍优越性 |
| 实际集成 | 本地 MCP 服务器、选定嵌入适配器、经批准的实时来源查找 | 观察到的协议和依赖行为 | 生产授权或服务可用性保证 |
| 实时模型任务 | 固定任务集和公开的 Provider/配置 | 该配置下观察到的任务行为 | 通用可靠性或精确可复现性 |
| 人工交付物 | 审核方案/报告、来源、可编辑性、实用性 | 对目标受众和任务的适用性 | 超出已检查证据的技术保证 |
| 交付与迁移 | 新环境交付、未见变体、能力/归属审核 | 可复现的应用和有理由的适配 | 生产部署或监管批准 |

发布评估集每个综合项目至少包含十个案例：三个正常案例、三个缺失/模糊输入案例、两个授权/注入案例和两个生命周期/返工案例。使用受控素材执行完整集合；数值单元和文档结构覆盖为额外项。对于实时模型评估，每个综合项目选择至少一个正常、一个信息不足和一个修订案例，每个运行两次并记录所有尝试。这个小型教学样本演示评估实践，不是生产可靠性估计。

在实时运行之前，冻结案例评分标准、Provider/模型设置、语料库修订版本和资源预算。报告完成率、落地性、延迟和 Token/成本观察（如可用）；不可用的使用为未知，不是零。失败案例需要诊断和文档化的修正/重测，不擦除早期结果。人工验收适用于最终提交的文档。模型评分器可以辅助但不能替代来源检查、独立数值标准答案或学员答辩。

## 8. 最终评估评分标准

| 维度 | 分值 | 证据 |
| --- | --- | --- |
| 场景设计与任务边界 | 15 | 场景简报、替代方案、可度量的验收 |
| Agent 机制与工具集成 | 20 | 已解释的循环、结构化契约、可工作的 MCP 集成 |
| 数据/证据正确性 | 20 | 数值标准答案、检索对比、声明/来源映射、不确定性处理 |
| Harness 可靠性与控制 | 20 | 边界、取消、失败、恢复和负面测试 |
| 可用交付物 | 15 | 两个综合项目、Markdown/DOCX/PPTX、视觉/可编辑性检查、版本溯源 |
| 可复现性与教学回顾 | 10 | 交付重放、环境证据、准确概念、独立调试 |

草案通过阈值：至少 80/100、完成 G0–G4 且满足以下每个关键门禁。G5 记录最终结果。使用演示证据评分每个维度：缺失/不正确不得分、仅协助或不完整证据得部分分、独立正确执行加解释得满分。教师校准示例必须在教学前定义中间分数。专业词汇和校园 vs 行业选择均不改变分数。这些是建议的课程标准，不是已度量的学员结果或产品验收标准。

关键门禁不能通过呈现质量来补偿：

- 提交中不包含凭证或未授权的私有数据。
- 定义的边界测试中无未授权的工具执行。
- 不将虚构来源或明知无支持的数值结果呈现为已验证。
- 不覆写原始输入文件。
- 不将未完成或已取消的 Run 报告为已完成。
- 两个基线综合项目和全部三种必需文档格式均存在并通过结构/人工检查。
- 学员独立解释循环/Harness、为未见输入改变行为并诊断提供的缺陷。
- 必需的确定性检查通过；必需的实时/集成/人工检查有证据或结果明确标注为不完整。缺失的作者提供资产触发课程补救，不降低退出标准。

## 9. 课程就绪门禁

1. **规划就绪：** 两条入口路线、O1–O8、章节依赖、素材和评估已规格化。本修订规划草案是当前交付物，待用户审核。
2. **实验就绪：** 起始代码/解决方案、基础衔接模块、素材、精确命令和失败案例已在固定修订版本测试；必需适配器不依赖未来产品发布。
3. **试点就绪：** 至少一位未接触 Agent 的程序员和一位大一等效学员按需完成模块 00 和第 01–05 章，仅使用文档化支持通过 G1。记录协助、误解、时间和补救；两位参与者是可用性检查，不是广泛验证。
4. **综合项目就绪：** 两个完整旅程、全部三种文档格式、实际集成和应用交付通过离线和必需的实时/人工检查。用两种入口画像重复后续课程试点以测试总工作量和 G5 就绪度。
5. **发布就绪：** 所有章节满足编撰检查清单、资产可再分发、链接可解析且学员反馈已纳入。发布度量的进度和任何支持环境限制。

门禁 2–5 不会仅因创建本规划目录而满足。[编撰计划](authoring-plan.md)定义了如何达到它们。
