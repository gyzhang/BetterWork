# 实用 Agent 设计与开发

> 从基础编程到完整应用，学习理解、设计、构建、评估和交付 Agent。

状态：教程规划草案。本目录包含课程规划，而非已完成的章节、可运行的实验，或学员通过验证的证据。

## 1. 课程面向对象

本课程服务两种入口画像，最终能力相同：

| 入口画像 | 起始优势 | 提供的支持 |
| --- | --- | --- |
| 编程新手（未接触 Agent） | 能编写程序；可能了解 API、调试和测试 | 基于诊断的免修已掌握的基础练习 |
| 有一定编程经验的大一计算机学生 | 能使用变量、条件、循环、函数和简单列表/映射 | 针对文件、JSON、HTTP、异步工作、模块、Git、测试和领域术语的显式准备 |

两种画像均不假设了解 Agent、机器学习、专业软件架构、会计或客户交付。不要求预先掌握 TypeScript、React、Electron、数据库、线性代数和模型训练。

实际最低要求是能编写并解释一个包含函数、循环和条件的小程序。低于此水平的学员需先完成一门独立的编程入门课程。具备基本编程经验不等于知道如何构建软件系统。

目标是可迁移的工程能力，不是培训使用 BetterWork 或记忆框架 API。服务银行、能源和制造业客户的员工是一个应用受众；学生可以用校园场景展示同等能力。

## 2. 学习目标决定课程

课程从学员必须独立展示的能力反向设计。BetterWork 当前的功能集、发布计划和实现缺口不限制这些目标。

| 关注点 | 治理问题 | 与另一条线的关系 |
| --- | --- | --- |
| 产品开发 | 工作中的桌面产品下一步应交付什么？ | 提供真实的问题、决策和示例 |
| 课程设计 | 学员必须理解和展示什么？ | 定义自身的前置条件、练习、产出和评估 |
| 课程准备 | 需要哪些教学实现、数据集和说明？ | 构建缺失的教学资产，不等待产品发布 |

例如，Word 生成是与 Markdown 和 PowerPoint 并列的必修学习成果。如果在编撰某章时合适的实现不可用，准备一个经过测试的教学实现是作者工作——不是将该成果变为可选的理由。

产品和课程可以相互启发而不共享完成检查清单。本计划变更课程范围，不变更产品路线图，不声称规划中的教学资产已可运行。

## 3. 两个贯穿案例

### 案例 A：深度研究与方案

问题与选定材料 → 研究计划 → 本地与外部证据 → 对比与综合 → 经审核的方案 → Markdown、DOCX 或 PPTX → 修订。

重点：研究范围、证据质量、冲突信息、不确定性、人工检查点和可复用交付物。

### 案例 B：部门运营分析

来自总账和项目管理系统的 Excel 导出 → 模式与质量检查 → 商定的指标定义 → 确定性计算 → 解读 → 演示 → 下一期复用。

重点：期间/单位一致性、关联正确性、缺失值、数值验证、可追溯性，以及事实与因果假设的分离。

两个案例均使用合成或经明确批准的脱敏材料。客户账户、公司模板和内部数据不是核心教学的前提条件。

低领域知识入口使用校园研究提案和学生社团预算/项目报告。专业变体使用业务 Agent 方案和部门运营。相同的来源、计算、权限和输出要求适用；行业熟悉度不影响技术通过标准。在财务示例之前，先用一个小型完整数据集教授表格粒度、关联、期间、单位、预算和偏差。

## 5. 教学设计

- 从解释 → 追踪 → 修改 → 实现 → 评估 → 迁移逐步递进。
- 在框架或产品内部之前使用伪代码和完整的输入/输出示例。
- 在使用之前讲授概念；提供术语表和小型领域入门，不假设专业经验。
- 用完整示例、部分完成的练习、独立变体和延迟迁移任务搭建练习脚手架；随时间逐步减少脚手架。
- 在第一个循环中引入工具白名单、取消和迭代限制；在 Harness 章节中深化。
- 保持一个持续演进的应用，每个实验都有里程碑快照和经过测试的起始代码。
- 从基础阶段就开始教授测试和失败分析，不仅在最终评估章节。
- 区分离线检查、实时模型评估和人工文档审核。教师提供的共享模型访问可以支持没有个人账户的学员。
- 允许编码助手，但要求学员独立解释、修改和调试其提交，并披露协助情况。
- 评估可观察的决策、行为、输出和状态；不要求访问模型的私有推理过程。

## 6. 草案技术基线

| 领域 | 教学选择与理由 |
| --- | --- |
| 参考语言 | TypeScript/Node.js 提供单一一致的可运行路径和显式契约；不是入学前置条件。伪代码和经评估的语言衔接支持 Python/C/Java 学员 |
| 首个执行界面 | 一个小型终端程序和测试；理解循环不需要前端框架 |
| 模型 | 最小 Provider 契约、用于确定性检查的脚本化响应和用于行为评估的真实模型；先教限制再教抽象 |
| 工具与集成 | 结构化契约、运行时校验、确定性计算、显式访问；一个只读 MCP 集成 |
| 检索 | 在小型语料库上进行词法和嵌入检索实操；在增加复杂性之前对比检索质量 |
| 测试 | 先写小型断言，再用 Vitest 和集成/评估套件；现有仓库规范适用于贡献的示例 |
| 数据与文档 | Excel 检查/关联/指标；Markdown、DOCX 和 PPTX 生成，含内容模型、模板、来源追溯和修订 |
| 状态与交付 | 状态机和持久化，然后 SQLite；可用的 CLI/API 交付配合提供的薄 UI 适配器；桌面 IPC 作为对比案例 |
| 框架 | 先理解循环，然后在第 19 章将其职责映射到一个框架/平台；不做框架综述 |

作者必须在准备每个可执行实验时选择并锁定教学库版本。缺失的产品功能在需要时在隔离的教学适配器中实现。课程示例不导入未完成的应用内部或引入第二个产品运行时。产品架构变更仍是独立决策；贡献的代码遵循[工程规范](../../docs/12-engineering-standards.md)。

## 8. 范围边界

核心覆盖包括模型/提示词基础、Agent Loop 和 ReAct、工具/MCP、实用 RAG、上下文/记忆、Skill/Expert 预设、Harness、数据分析、全部三种文档输出格式、两个综合项目以及部署/迁移。范围是为从入门到独立构建者的连贯进阶而选择，不是从当前产品功能复制。

以下为方向性介绍或可选扩展，不是前置条件：

- 模型训练和微调：解释其定位；数学推导和训练基础设施是专业课题。
- 多 Agent 协调：在掌握单个 Agent 之后对比职责和失败模式；多 Agent 构建是扩展，不是入门前置条件。
- 浏览器/桌面自动化和通用工作流编辑器：讨论工具和控制的影响；掌握这些平台是独立的专业方向。
- 企业身份、租户隔离、部署和合规：教授要求和归属；生产认证不在课堂评估范围内。
- 重建完整的 Office 编辑器或所有 UI 组件：与演示可靠的文档生成 Agent 无关。

行业练习教授如何识别这些需求并明确责任归属。成功的本地实验不能作为生产级银行、能源或制造业就绪的证据。
