# 课程大纲：从场景到可靠的 Agent

状态：建议的课程大纲。所有章节和实验均为规划中，尚未编写或验证。受众和目的在[课程概述](README.md)中定义；可执行验收在[实验与评估](labs-and-assessment.md)中定义。

## 课程序列

二十个核心章节独立于产品发布进度。模块 00 补充缺失的软件基础；它不是通用的编程入门。两条入口路线完成[概述](README.md)中相同的 O1–O8 核心成果。

| 部分 | 章节 | 引导问题 | 掌握检查点 |
| --- | --- | --- | --- |
| 基础衔接 | 00 / F01–F04 | 我能处理文件、API、异步代码和测试吗？ | G0：独立完成诊断任务 |
| I. 模型、场景与首个 Agent | 01–05 | Agent 增加了什么，如何执行？ | G1：解释并构建有界循环 |
| II. 工具与工作上下文 | 06–10 | Agent 如何行动、检索和复用知识？ | G2：有根据的、可复用的能力，含度量检索 |
| III. Harness 工程 | 11–13 | 如何控制和评估执行？ | G3：可复现的边界、生命周期和评估测试 |
| IV. 数据与文档工程 | 14–16 | 如何产出正确且可用的工作成果？ | G4：Excel 分析加 Markdown、DOCX 和 PPTX |
| V. 综合应用 | 17–18 | 各部分能完成一个真实任务吗？ | 两个综合项目的集成证据 |
| VI. 交付与迁移 | 19–20 | 他人能否使用、适配和维护？ | G5：独立交付和答辩 |

默认顺序为顺序学习。前置条件标识概念依赖。预算 60 引导核心学时，加上概述中描述的额外基础/实践支持。各章时长不必相等。一次课程循环经过完整示例、引导修改、独立变体和失败分析；复杂实验可跨多次课程。

## 模块 00. 从基础编程到课程环境

入学诊断：编写一个使用循环和条件的小函数，解释其结果，并修正一个简单缺陷。尚不能做到这一点的学员需要先学习编程入门。

| 衔接模块 | 显式教授内容 | 诊断或退出任务 |
| --- | --- | --- |
| F01. 程序与项目基础 | 终端、模块、依赖、基础 TypeScript、文件路径、Git 变更 | 运行提供的项目，修改一个函数并解释变更 |
| F02. 数据与接口 | 对象、JSON、文件、HTTP 请求/响应、状态码、环境配置 | 解析本地响应并在不暴露密钥的情况下处理缺失/无效字段 |
| F03. 异步工作与错误 | Promise/await、超时、异常、取消、顺序与并发工作 | 追踪延迟操作、取消它并区分失败与有效的空结果 |
| F04. 测试与数据素养 | 断言、素材、可复现性、表格、键、求和、比率、缺失 vs 零 | 添加回归测试并根据提供的预期值验证小型表格计算 |

为每个衔接模块提供三小时引导课程和补救练习。有经验的学员可以通过展示衔接模块的退出任务代替参加。G0 要求全部四个退出，不接受自我报告的经验。银行、会计和专业知识不属于 G0 范围。

## 第一部分. 模型、场景与首个 Agent

### 01. 在选择 Agent 之前明确有用的任务

- 前置条件：编程基础；在实现实验之前完成 G0。
- 学习：用户目标、输入/输出、不确定性、脚本 vs 工作流 vs Agent、成功标准和人工责任。
- 实验 L01：对比校园研究/预算任务与对应的部门案例；定义非 Agent 基线和 Agent 候选。
- 交付物：一页场景简报、排除的操作、示例输入和可度量的验收案例。
- 失败与退出：识别缺失的来源或决策权限；另一位学员必须能从简报判断成功标准。

### 02. 理解模型、提示词及其限制

- 前置条件：01 和 G0。
- 学习：Token、上下文窗口、推理 vs 训练、概率输出、消息角色、指令/示例、结构化输出、幻觉和成本。
- 实验 L02：对比欠指定的提示词与显式任务/输出契约；在小型固定集上检查重复响应。
- 交付物：提示词变体、预期答案标准、观察到的差异和模型无法从输入中知道的事实列表。
- 失败与退出：流畅但不正确的响应和上下文遗漏；解释为什么更好的提示词不是权限系统或正确性证明。

### 03. 发起模型请求并完成一次工具交互

- 前置条件：02；F02–F03。
- 学习：Provider 边界、请求/响应、工具 Schema、调用标识、运行时校验、返回的观察结果和流式完成。
- 实验 L03：先调用脚本化 Provider，然后用教师提供的或个人的实时模型访问完成计算器交互。
- 交付物：时序图和分离请求操作与实际执行操作的测试。
- 失败与退出：拒绝格式错误的参数和不完整的流；检查实时交互而不暴露凭证。

### 04. 实现 Agent Loop

- 前置条件：03。
- 学习：模型 → 允许的工具 → 观察 → 下一次决策、消息/状态、停止条件、迭代限制、取消和事件顺序。
- 实验 L04：使用计算器和只读材料工具实现一个小型无头循环；起始代码提供传输细节，不提供循环逻辑。
- 交付物：可运行代码加正常路径、未知工具、工具失败、取消和轮次限制测试。
- 失败与退出：反复请求同一工具的 Provider 必须终止；每次运行恰好一个终态结果。无不受限的 shell 工具。

### 05. ReAct 与工作流设计

- 前置条件：04。
- 学习：推理/行动/观察、固定阶段内的自适应决策、规划 vs 执行以及何时需要人工审核。
- 实验 L05：对比同一任务的固定方法和观察驱动方法；使用度量行为修订 L01 设计。
- 交付物：控制流图、有界计划、对比结果和升级规则。
- 失败与 G1：处理冲突的观察和无效重复；独立解释和修改循环。不要求私有模型推理来演示 ReAct。

## 第二部分. 工具与工作上下文

### 06. 工程化确定性工具

- 前置条件：G1；F04。
- 学习：工具描述、Schema vs 运行时校验、结构化结果/错误、副作用、单位、确定性算术和测试标准答案。
- 实验 L06：实现期间/预算对比和有界的文件读取工具；先用学生社团表格，再用部门导出。
- 交付物：工具契约、独立预期值、验证测试和将计算留在模型之外的适配器。
- 失败与退出：缺失当前值、零分母、无效路径和单位不匹配保持显式，不产生看似合理的数字。

### 07. 通过 MCP 集成工具

- 前置条件：06。
- 学习：宿主/客户端/服务器角色、发现、Schema 映射、传输、选定工具访问、连接生命周期和取消。
- 实验 L07：通过本地 MCP 服务器暴露并调用合成的只读指标工具；与直接工具调用对比。
- 交付物：集成图和选择、参数、结果映射及连接正常关闭的测试。
- 失败与退出：处理不可用服务和未选定的工具请求；发现或连接性不授予权限。

### 08. 构建和评估检索增强生成

- 前置条件：06–07。
- 学习：文档提取、分块/定位器、关键词检索、嵌入和相似度、top-k 选择、证据、检索评估和有根据的生成。
- 实验 L08：在同一小型语料库上构建词法和嵌入检索；离线测试使用固定嵌入素材，实时练习使用文档化的嵌入适配器。
- 交付物：查询/相关性标签、检索对比、来源落地的回答和声明-来源映射。
- 失败与退出：无关命中、冲突来源和空检索不能变成捏造的证据；选定、已读和已引用是不同的事实。

### 09. 管理上下文和记忆

- 前置条件：08。
- 学习：上下文组装和预算、选择性读取、历史/摘要、知识 vs 记忆、范围、确认、新鲜度和删除。
- 实验 L09：在新任务中复用已确认的偏好同时替换当前数据；对比全历史输入与选定上下文。
- 交付物：上下文快照、记忆生命周期测试以及关于包含、排除或摘要内容的解释。
- 失败与退出：过时事实、已删除记忆和另一工作区的材料不能悄悄重新出现；摘要不替代来源证据。

### 10. 打包 Skill 和配置 Expert

- 前置条件：09。
- 学习：Tool vs Skill vs Expert、可复用指令/资源、任务特定事实、版本、配置解析和有效能力范围。
- 实验 L10：在一个引擎上配置研究和分析预设，验证解析后的方法、材料范围和工具。
- 交付物：两个预设、可复用方法、配置测试和展示组合而非独立引擎的完整示例。
- 失败与 G2：禁用/不受信任的方法和缺失依赖产生显式失败；独立将有根据的助手适配到未见过的输入。

## 第三部分. Harness 工程

### 11. Harness 架构与信任边界

- 前置条件：G2。
- 学习：运行时职责、模型 vs 宿主权限、能力白名单、不可信文档、提示词注入、输入快照、密钥和最小权限。
- 实验 L11：将每项控制映射到其执行组件；在工具/材料执行边界实现负面测试。
- 交付物：威胁/边界图和限于一次性合成输出的受控文件写入审批练习。
- 失败与退出：注入的指令不能扩展访问；准确区分宿主检查、进程隔离和操作系统沙箱保证。

### 12. 生命周期、持久化状态和人工检查点

- 前置条件：11；此处提供简短的状态机/SQLite 入门。
- 学习：Task/Session/Run 标识、持久化记录、终态、超时、取消、幂等性、安全重试、审核检查点和返工。
- 实验 L12：持久化状态、中断宿主、恢复审核检查点并从选定输入开始新 Run，不重复效果。
- 交付物：状态转换图和持久化、重复请求、取消和所有权测试。
- 失败与退出：区分恢复协作与中断的模型调用；不发布部分输出或盲目重试副作用。

### 13. 可观察性、评估和运行预算

- 前置条件：12；测试从 F04 起一直使用。
- 学习：脱敏结构化追踪、单元/集成/模型评估、相关性和任务成功率、延迟、Token/成本数据、回归集和预算策略。
- 实验 L13：在固定任务上对比两种指令/检索配置、注入一个回归并演示有界停止。
- 交付物：评估报告，含样本量、所有尝试、设置、预期/实际结果和模型/数据/工具/运行时错误分类。
- 失败与 G3：检测流畅但无支持的输出、分类受控回归并将缺失的使用数据标记为未知；脚本化 Provider 不是实时模型质量的证明。

## 第四部分. 数据与文档工程

### 14. 用确定性工具分析 Excel 数据

- 前置条件：G3；使用完整预算/项目数据集复习 F04。
- 学习：工作簿/工作表/范围、行和键、公式/值状态、粒度、关联、聚合、指标定义、单位、缺失值和对账。
- 实验 L14：检查两个工作簿、验证关联、计算期间/预算对比并产出质量报告和经验证的指标结果。
- 交付物：输入到结果的定位器、计算测试、预期总计和分离度量变化与因果假设的解释。
- 失败与退出：检测重复关联、不兼容单位、零分母和缺失公式缓存；不假设财务专业知识。

### 15. 生成 Markdown 和 Word 文档

- 前置条件：14；来自 08 的证据和内容契约。
- 学习：结构化内容模型、章节/标题、表格、引用、模板、DOCX 渲染、Artifact 版本和结构 vs 视觉验证。
- 实验 L15：将相同支持的内容渲染为 Markdown 和可编辑 DOCX，在办公应用中审核并在不覆写原始版本的情况下修订。
- 交付物：两个文件、来源映射、渲染器检查、可编辑性证据和版本溯源。
- 失败与退出：格式错误的内容、缺失模板、截断表格和尝试覆写均显式失败。Word 生成是必需的，不受产品进度影响。

### 16. 生成可编辑 PowerPoint 演示

- 前置条件：15。
- 学习：受众/故事线、幻灯片目的、大纲、图表/表格、主题/模板、PPTX 渲染、来源映射、视觉质量保证和修订。
- 实验 L16：将经审核的报告转为可编辑演示；变更一个数字或建议并重新生成受影响的输出版本。
- 交付物：大纲、PPTX、来源/输入溯源、结构检查和人工可编辑性/可读性审核。
- 失败与 G4：发现不匹配的数字、溢出和纯图片内容；Excel 结果、Markdown、DOCX 和 PPTX 均必须通过各自检查。

## 第五部分. 综合应用

### 17. 综合项目 A：从研究到可辩护的方案

- 前置条件：G4；使用[综合项目规范](labs-and-assessment.md)。
- 学习：研究范围、冲突证据、选项和可行性、审核决策、内容质量和端到端评估。
- 实验 L17：研究校园或业务 Agent 机会、获取大纲反馈并交付 Markdown、DOCX 和 PPTX 及可追溯证据。
- 交付物：方案、证据登记册、决策记录、三格式输出包和评估报告。
- 失败与退出：纳入方向变更并处理无支持的声明；录制的来源支持重放，实时模型/来源试用单独记录。

### 18. 综合项目 B：从运营分析到报告

- 前置条件：G4；基于 14 和[综合项目规范](labs-and-assessment.md)。
- 学习：集成质量检查、确定性分析、叙述、图表、审核者决策和重复期间工作。
- 实验 L18：分析一个期间、生成管理演示，然后用新数据和选定的前期 Artifact 重复。
- 交付物：质量报告、标准答案校验的指标、来源落地的叙述、两个期间特定的可编辑演示和生命周期证据。
- 失败与退出：重复行、缺失预算、过时上下文和无支持的因果解释被显式处理；第二期间使用独立任务。

## 第六部分. 交付与迁移

### 19. 打包应用并映射到另一平台

- 前置条件：17–18。
- 学习：核心/宿主/UI 边界、CLI/API 打包、环境/依赖、密钥配置、日志、部署责任和框架/平台能力映射。
- 实验 L19：在 CLI 和提供的薄 API/UI 适配器后交付 Agent；将其运行时职责与一个教师选定的框架/平台对比。
- 交付物：可运行包、操作说明、能力地图和校园、银行、能源或制造业场景的适配简报。
- 失败与退出：缺失配置或平台能力差距显式标注，含缓解措施/归属者。将多 Agent 协调作为架构对比讨论，不是强制重写。
- 边界：提供的 UI 避免要求 React/Electron 专业知识；产品源码是参考侧栏，不需要真实客户访问或生产认证。

### 20. 独立交付、评估和教学回顾

- 前置条件：19 和最终证据包。
- 学习：验收审核、可复现性、沟通限制、维护归属权和交付后评估变更。
- 实验 L20：另一位学员按照交付说明操作；作者处理未见过的输入、诊断提供的缺陷并解释适配方案，不使用复制的解决方案。
- 交付物：两个基线综合项目、一个更深入的项目答辩、评估证据和对 ReAct、Agent Loop 及 Harness 的简洁解释。
- 失败与 G5：演示正常执行、受控失败和修订；满足[实验与评估](labs-and-assessment.md)中的共享评分标准和关键门禁。

## 前置条件与掌握策略

G0 → 第 01–05 章/G1 → 06–10/G2 → 11–13/G3 → 14–16/G4 → 17–20/G5。第 01 章的讨论可以先于 G0，但可执行工作不行。G0–G4 包含纠正性反馈和使用新变体的重试；花费的时间不是通过标准。未通过 G4 的学员不因视觉上精美的综合项目获得全程完成声明。

## 概念纪律

| 术语 | 本课程中的工作定义 | 需要防止的常见误解 |
| --- | --- | --- |
| 模型 / Agent | 模型产出预测/响应；Agent 系统将模型决策与工具、上下文、状态和控制结合 | 单独的模型执行工具或强制执行应用权限 |
| Token / 上下文 | 模型处理的单元 / 请求可用的有界信息 | 对话历史无限或自动被记住 |
| RAG | 检索选择外部信息来落地生成；检索和回答质量需要分别检查 | 嵌入保证相关性或检索文本自动为真 |
| Agent | 一个有界的系统，使用模型决策、工具、上下文和反馈来推进任务 | 任何聊天机器人或任何工作流都自动是 Agent |
| ReAct | 一种可在循环内实现的推理/行动/观察模式 | 正确性保证或必须揭示私有推理 |
| Agent Loop | 协调模型调用、工具执行、观察和停止的执行循环 | 仅仅是提示词或无限制的循环 |
| Harness | 上下文、能力访问、生命周期、可观察性和评估的运行时及周边控制 | 行业通用的标准化组件名称或仅是系统提示词 |
| Tool | 具有结构化契约的可执行能力 | 描述期望动作的文本 |
| Skill | 带有指令的可复用工作方法，适用时包含脚本/资源 | 新引擎或自动授权的可执行代码 |
| Expert | 配置的角色和工作方法/能力预设 | 必然是独立的自主 Agent 进程 |
| MCP | 将宿主/客户端连接到工具和资源的协议 | Agent 引擎、授权策略或可信数据保证 |
