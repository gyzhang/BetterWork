# 附录 E 工程检查清单汇编

> **这份附录解决什么问题**：全书二十一章散布着几十条可执行的检查项。到你真的要交付的时候，你不想再翻一遍两百多页。
>
> 这里把它们按**闸门（gate）** 重新组织。**闸门的含义是：不过不往下走。** 不是"建议检查"，是**拒绝继续**。

---

## E.1 怎么用这份清单

这份清单有三条使用规则，都很重要：

| 规则 | 说明 |
|---|---|
| **闸门是二值判断** | 每一项只有"过"或"不过"。**"基本过了"不是一种状态。** |
| **不过就不要往下走** | 带着未通过的闸门继续，后面的工作会建立在错误的前提上 |
| **每一条都要能被机器或人**确切地检查 | 无法检查的项目不是检查项，是口号——**遇到这种，就把它拆到能检查为止** |

还有一条使用经验：

> **闸门里最容易被跳过的是"拒绝"类的那几条**（工具该拒绝什么、系统该拒绝什么动作）。<br>
> 因为"能做什么"看起来才是价值所在。而全书反复给出的结论是：**可靠性来自禁止集，不是来自功能集。**

## E.2 闸门一：立项（第 1–2 章）

**这一关要回答：这件事该不该做成智能体。**

| # | 检查项 | 通过判据 |
|---|---|---|
| 1.1 | 任务是否已写成**可验证的形式** | 能说出"什么结果算完成"，且能被第三方复核 |
| 1.2 | 是否比较过**四种做法** | 脚本 / 工作流 / 检索应用 / 智能体，四条都评估过 |
| 1.3 | 选智能体的理由是否**与不确定性有关** | 理由必须是"下一步做什么取决于中间结果"，而不是"听起来更先进" |
| 1.4 | 是否明确了**模型的边界** | 能指出哪些部分模型负责"想对"，哪些部分代码负责"错不了" |
| 1.5 | 是否列出了**不可知的几类** | 至少区分：上下文窗口之外的事实 / 需要外部验证的事实 / 需要人的判断的选择 |
| 1.6 | 是否设了**排除清单** | 明确不做什么，且至少一条落在**宿主**上而不是提示词里 |

**最常见的失败**：1.3 写成了"提升效率"或"减少人工"。**那不是理由，那是愿望。**

## E.3 闸门二：单次决策（第 3–5 章）

**这一关要回答：一次完整的决策，形状对不对。**

| # | 检查项 | 通过判据 |
|---|---|---|
| 2.1 | 工具交换的三步是否清晰 | 模型提出调用 → **代码校验参数** → 执行并返回观测结果 |
| 2.2 | 参数校验是否**在代码里** | 不是"提示词里写了要检查" |
| 2.3 | 每个工具是否有**禁止集** | 能回答"它在什么情况下会拒绝执行" |
| 2.4 | 循环是否有**明确的终止条件** | 完成 / 取消 / 失败 / 达到上限，四种都可判定 |
| 2.5 | 达到上限是否被判为**失败** | **不是成功，不是静默继续** |
| 2.6 | 循环是否有**轮次上限**与**成本观念** | 上限不是成本上限，这一点要写清 |
| 2.7 | 自由度是否被**阶段边界**约束 | 能回答"模型可以改变什么、不可以改变什么" |
| 2.8 | 推理展示是否**未被当作判断依据** | 判定依据只包括决策、调用与观测结果 |

**最容易漏的一项**：2.4。**一个"大部分时候会停"的循环，等于没有终止条件。**

---

## E.4 闸门三：能力（第 6–10 章）

**这一关要回答：循环需要的能力齐了没有，而且每一项都是可控的。**

| # | 检查项 | 通过判据 |
|---|---|---|
| 3.1 | 算术是否交给了确定性工具 | 模型不参与任何需要精确数字的计算 |
| 3.2 | 工具是否**不猜缺失值** | 缺输入即报错或返回明确标记，**不补、不跳、不取默认** |
| 3.3 | 数值边界是否检查了**累加之后** | 单值安全 ≠ 总和安全 |
| 3.4 | 外部协议集成是否区分了**"能连上"与"允许用"** | 协议层与授权层是两层 |
| 3.5 | 工具来源是否经过**选择与校验** | 不是"发现即可用" |
| 3.6 | 检索是否做了**独立于检索的检查** | "检索到了"与"内容支持结论"分开判定 |
| 3.7 | 检索评估是否有**分子分母** | 能说出精确率与召回率各自的定义 |
| 3.8 | 上下文是否被视为**有限资源** | 有预算、有取舍、有溢出策略 |
| 3.9 | 记忆是否有**作用域**与**有效期** | 能说出"这条记忆对谁、在什么范围内有效" |
| 3.10 | 是否明确"放进去 ≠ 用得上" | 上下文不会自动包含你需要的东西 |
| 3.11 | Skill 与专家是否**只是配置** | 不是进程、不是权限提升通道 |
| 3.12 | 有效能力范围是否写成**交集** | 声明 ∩ 阶段允许 ∩ 本次实际可用 |

**最容易漏的一项**：3.3。**一个能审计通过的单值校验，可能完全挡不住累加溢出。**

---

## E.5 闸门四：系统（第 11–13 章）

**这一关要回答：能力齐了，谁来保证它不乱跑、不丢状态、不被骗。**

| # | 检查项 | 通过判据 |
|---|---|---|
| 4.1 | 信任边界是否**由代码执行** | 提示注入的防线不在提示词里 |
| 4.2 | 外部输入是否**一律不可信** | 包括工具返回的内容、检索到的片段、文档里的文字 |
| 4.3 | 权限检查是否覆盖**"从检查到动作"的窗口** | 检查之后授权失效怎么办，有明确答案 |
| 4.4 | 是否有**沙箱 / 隔离**，而不是"检查了路径" | 能指出隔离的落实位置 |
| 4.5 | 状态是否**活过进程** | 进程死掉后，任务状态可恢复 |
| 4.6 | 检查点边界是否说清 | 检查点**不能**恢复被中断的模型请求调用栈 |
| 4.7 | 每一个终态是否都被**显式记录** | 完成 / 取消 / 失败，都能被指出 |
| 4.8 | 被取消的运行是否**不被报告为完成** | 不完整产物不得被提升为已完成交付物 |
| 4.9 | 追踪是否为**结构化事件** | 有运行标识、单调序号、类型 |
| 4.10 | 是否有**测量能力**（用量、成本、时延） | **无数据即未知**，不报 0、不估算 |
| 4.11 | 评估是否用了 **pass^k 而非 pass@1** | 且样本量足够，不是跑一次下结论 |
| 4.12 | 引用基准分数是否**带三样** | 发布日期 + 评测执行方 + 采样方式 |

**最容易漏的一项**：4.10。**没有用量数据，你后面的所有"优化"都无法被验证。** 参考实现在这一项上是**缺口**——必须自行补（见附录 B）。

## E.6 闸门五：交付（第 14–16 章）

**这一关要回答：产出的东西别人能改、能核、能签吗。**

### E.6.1 数据类交付（Excel / 表格）

| # | 检查项 | 通过判据 |
|---|---|---|
| 5.1 | 每张表是否有**颗粒度声明** | 能写出"这张表一个 X 一行" |
| 5.2 | 维度键是否**唯一** | 重复主键会放大合计，必须阻断 |
| 5.3 | 连接是否**不会放大行数** | 会放大就先聚合再连接 |
| 5.4 | 缺失与零是否**分开处理** | 缺失必须随结果一起被报告 |
| 5.5 | 单位与币种是否**一致** | **禁止隐式换算** |
| 5.6 | 百分比的分母是否写明 | 合计比例**不是**各分项比例的算术平均 |
| 5.7 | 每一个数字是否带**源坐标** | 能回溯到具体的单元格或记录 |
| 5.8 | 排除的行是否有**原因记录** | 不静默消失 |
| 5.9 | 是否做了**独立核验** | 用另一种方式算出至少一个汇总数并对上 |
| 5.10 | 公式缓存缺失是否被标记 | **缓存值不等于重新计算** |

### E.6.2 文档类交付（Markdown / Word）

| # | 检查项 | 通过判据 |
|---|---|---|
| 5.11 | 正文里的数字是否为**指标 ID 引用** | 一个直接抄写的数字都不留 |
| 5.12 | 标题是否为**真样式** | 导航窗格能看到层级 |
| 5.13 | 表格是否为**真表格** | 单元格可编辑，不是图片 |
| 5.14 | 四个维度是否**分别验过** | 结构 / 事实 / 可编辑性 / 可见版式 |
| 5.15 | 是否做了**可编辑性实测** | 改段落、改单元格、存、关、重开、改动还在 |
| 5.16 | 是否检查了**最后一页和最后一个表格行** | 不是只看第一页 |
| 5.17 | 是否实现了**哈希绑定** | 校验报告绑定到具体字节 |
| 5.18 | 输出**不得覆盖源文件** | 写入源路径在修改前就被拒绝 |
| 5.19 | 版本是否记录**血缘** | 被修订的是哪个版本、为什么改 |

### E.6.3 演示类交付（PPT）

| # | 检查项 | 通过判据 |
|---|---|---|
| 5.20 | 每页是否能写一个**动词** | 写不出的页先删或改写，**不先调字号** |
| 5.21 | 每个数字是否绑定**指标 ID**，每句陈述是否绑定**证据** | 绑定不上的标为未验证或删除 |
| 5.22 | 图表是否有**可编辑数据或已登记的源数据表** | **数字不能只存在于图里** |
| 5.23 | 必需内容是否为**原生对象** | 不得整册压平为图片 |
| 5.24 | 长标签、来源注是否**目视检查过** | 解析器查不出视觉重叠 |
| 5.25 | 文档样式是否与**应用界面主题分离** | 切换深浅色不得改变交付物颜色 |
| 5.26 | 改一个输入后，是否核对了**每一处重复数字** | 包括标题、页眉、备注 |

**最容易漏的三项**：5.8（排除原因）、5.16（最后一行）、5.22（数字只在图里）。这三项的共同特征是——**错了之后文件看起来完全正常。**

## E.7 闸门六：综合（第 17–18 章）

**这一关要回答：零件会用了，能不能拼成一条可靠的生产线。**

| # | 检查项 | 通过判据 |
|---|---|---|
| 6.1 | 是否有**主张—证据登记表** | 四类分开：当前事实 / 能力限制 / 用户需求 / 无支撑收益 |
| 6.2 | **无测量支撑的收益**是否被降级 | 只能删除或降为假设，不得作为结论 |
| 6.3 | 冲突信息是否做了**版本关系分析** | 不是做词频比较 |
| 6.4 | 政策适用性是否有**人确认** | 由决策所有者确认，不是检索结果 |
| 6.5 | 需求升级时是否**重开了可行性分析** | 不是只加强措辞 |
| 6.6 | 每期是否作为**新任务**、显式选择新输入 | 任务 ID 与输入清单都变了 |
| 6.7 | 上下文材料是否都带**角色字段** | 历史上下文/呈现结构/当前输入/方法/偏好，分开标 |
| 6.8 | 是否有**测试断言**："当前指标只能从当前输入派生" | 能被测试失败证明其有效 |
| 6.9 | 缺失数据是否有**固定报告句式** | 每次缺失都被说出 |
| 6.10 | 是否区分了**定量事实与因果解释** | 因果需独立证据，不能从账本推出 |
| 6.11 | 取消与重启是否演练过 | 终态正确、无重复发布、原有尝试保留在历史里 |
| 6.12 | 演示是否保留了**实质性限制** | 可以省略论述，不能省略限制 |

**最容易漏的一项**：6.8。**"提醒模型别用旧数字"是提示词；"当前指标只能从当前输入派生"是测试。** 只有后者是边界。

## E.8 闸门七：迁移与交接（第 19–20 章）

**这一关要回答：交到别人手里，还能跑、还能改、还能被解释吗。**

| # | 检查项 | 通过判据 |
|---|---|---|
| 7.1 | 界面层是否**没有**权限检查与指标计算 | 全部收敛到宿主 |
| 7.2 | 是否在**干净环境**里照说明装过一次 | 记录第一个失败的步骤 |
| 7.3 | 发布包是否完整 | 源修订、依赖锁、运行矩阵、安装命令、非机密配置模板、固定输入、启停测命令、数据与输出位置、已知限制 |
| 7.4 | 离线路径是否**用断网运行证明过** | 不是"应该可以" |
| 7.5 | 本地服务是否**绑定回环**并声明调用者 | 未认证服务不得暴露到网络 |
| 7.6 | 缺配置时是否**明确失败** | **不得静默换假提供方、不得用非预期服务** |
| 7.7 | 缺依赖时是否**明确失败** | **不得产出扩展名正确的空文件** |
| 7.8 | 是否有**交接工作表**六问的答案 | 含"怎么停""失败怎么查""谁维护" |
| 7.9 | 是否有人**独立复跑成功** | 你复跑成功不算 |
| 7.10 | 是否有人**独立解释**了关键决策 | 能回答"那次调用为什么被允许" |
| 7.11 | 是否在**未见过的输入**上改对过 | 不是复现已知步骤 |
| 7.12 | 是否做过一次**受控缺陷诊断** | 从"期望 vs 实际"定位最早被违反的契约 |
| 7.13 | 交付后的**七项维护责任人**是否指派 | 依赖 / 模型配置 / 固定输入 / 指标定义 / 模板 / 保留策略 / 事件处理 |
| 7.14 | 变更后是否**重跑相关评估** | 一次通过的报告不做永久担保 |

**最容易漏的一项**：7.7。**一个内容为空的文件被下游当成成功，它的破坏力比一次报错大得多。**

## E.9 红线：六件绝对不做的事

这一节是这份附录里最短、也最重要的一节。

| # | 绝对不做 | 为什么 |
|---|---|---|
| 1 | **编造支撑**（引用了不存在的来源、把摘要当成全文、把假设写成结论） | 它使整个交付的可信度归零，**不能用其他方面的得分补偿** |
| 2 | **虚假完成**（把取消/失败报告成完成，把不完整产物提升为交付物） | 它让错误进入别人的决策依据 |
| 3 | **静默降级**（缺配置换假提供方、缺依赖出空文件、缺数据填零） | **产出看起来正常，这是最危险的一类** |
| 4 | **覆盖输入**（用输出改写源文件） | 它抹掉可复核的基准 |
| 5 | **跳过缺失**（把说不清的数字留在材料里不提） | 说不清的数字在材料里会被当作事实用 |
| 6 | **用图像替代可编辑内容** | 它同时破坏可修订性、可核验性与可追溯性 |

**这六条的共同特征**：它们都能让交付物**看起来更好**。这是它们危险的原因——**它们不是能力不足，是选择。**

前三条在第 20 章有对应的硬规则：**高于某个分数，不能补偿这六条中的任何一条。**

## E.10 一份可打印的交付前自检

最后给一份**最小可用**的清单。真正的交付前，逐条打勾：

```
【数据】
□ 每张表的颗粒度已声明
□ 维度键唯一性已校验
□ 连接不会放大行数
□ 缺失未被填成零或默认值
□ 币种与单位一致，无隐式换算
□ 每个数字可回溯到源坐标
□ 排除的行有原因记录
□ 至少一个汇总数做了独立核验

【文档】
□ 导航窗格有层级（标题是真样式）
□ 表格是真表格
□ 改过段落和单元格，存关重开改动仍在
□ 检查过最后一页与最后一个表格行
□ 校验报告已与交付字节做哈希绑定
□ 未写回任何源路径

【演示】
□ 每页能写一个动词
□ 每个数字绑定指标 ID
□ 图表有可编辑数据或源数据表
□ 长标签与来源注已目视
□ 切换应用深浅色后交付物颜色不变
□ 全量重复数字已逐处核对

【系统与流程】
□ 终态被显式记录，取消未报为完成
□ 有用量/成本数据，或明确标注"无数据"
□ 评估用了 pass^k，样本量足够
□ 引用的基准分数带齐三样
□ 主张表四类分明，无支撑收益已降级
□ 上下文材料都带角色字段
□ 有"当前指标只能从当前输入派生"的测试

【交接】
□ 干净环境装过一次，知道第一个失败点
□ 断网运行验证过
□ 缺配置 / 缺依赖时明确失败
□ 有人独立复跑并独立解释过
□ 七项维护责任人已指派（＝第 19 章四类产出责任人去掉交付期专属的"代码"，再补入模型配置、固定输入、保留策略、事件处理）
```

**这张表全部打勾，不代表你的系统好。** 它只代表**它没有那一类会让交付物失去意义的缺陷**。

**一个可靠的系统还需要第四条：它在变化之下仍然成立。** 而那一条，只能靠**持续重跑评估**来维持——**没有一次打勾可以替代它。**
