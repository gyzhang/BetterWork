# 第 18 章 综合案例 B：从运营数据到可复用的期报

**本章承诺**：读完这一章，你能设计一条**每个周期都能重跑**的报表生产线——它保住方法、刷新事实，并且在下一期数据不完整时**不会用上一期的数字把它补上**。

**读完后你能回答**

- 为什么"把同一个提示词再跑一次"不是对重复性的有效检验？
- 上一期的报告作为上下文交给系统时，它扮演什么角色？哪些部分能用，哪些绝对不能？
- 数据能确立什么、不能确立什么？为什么"涨了 8%"能算，而"因为会员增长所以涨了"不能算？
- 一个被取消的运行，正确的终态是什么？

---

先看一次失败。

**第一期的报告看起来是对的。**数据对，计算对，幻灯片对，复核者也签了。

第二期来了。换了一批新输入，新条目、新期间。流程重跑了一遍。

**出来的报告有三处问题**：

| 问题 | 表面现象 | 根本原因 |
|---|---|---|
| **旧数字残留** | 幻灯片**标题**里还写着上一期的合计 | 标题不在"会重算"的那部分里 |
| **缺失被补上** | 本期的预算表缺了项目 B，报告里却出现了 B 的预算数——**用的是上一期的 8000** | 系统把"上一期有此数"当成了"本期有此数" |
| **因果被写死** | 正文写着"支出上升是因为会员增长" | **账本里没有会员数据** |

三条的共同点是一句话：**智能体重用了不该重用的东西。**

> **核心判断 1**
>
> **重复报告检验的不是"能不能再跑一次"，而是"能不能保住方法、同时换掉事实"。**
> 这比"把同一个提示词跑两次"强得多，因为同一提示词跑两次**根本没有换事实**——它检验的只是稳定性，而稳定性是重复性里**最容易的那一半**。
> 真正的难点在另一面：**哪些必须保持一致，哪些必须每期都变。**

---

## 18.1 重复的是过程，不是答案

先把两期任务的结构摆出来：

<div align="center"><img src="images/fig-18-1-refresh-vs-reuse.png" alt="图 18-1 两期任务的对照：哪些必须复用，哪些必须重算" width="1150"/></div>

**读图指引**：看右栏最后那一句——**违反右栏的时候，报告看起来完全正常。**这是这张图存在的全部理由。左栏可以跨期复用，右栏每一条都必须重取。

```
任务 P1：选定的总账 / 项目 / 预算 → 质量检查与口径定义
  → 确定性分析 → 已复核的叙述与大纲
  → 可编辑报告演示 → 校验与带版本交付

任务 P2：新的选定输入 + 已批准的方法 + 选定的 P1 产物
  → 全新的质量检查 → 全新的计算
  → 与已授权的上期证据对比
  → 已复核的叙述与大纲 → 新的本期专用演示
```

注意 P2 的**第一项**是"新的选定输入"，**第二项**是"已批准的方法"。这两项加起来是本章的全部要点：

| 项 | 语义 | 为什么必须是新的 |
|---|---|---|
| **输入** | 本期选定的总账、项目、预算 | 数据每期都变 |
| **方法** | 已批准的口径、映射、计算公式 | **方法不应该每期重新发明** |

**这两项必须分开对待。** 把它们混在一起，就会出现本章开头那种情况：**系统把"方法可以复用"理解成了"数字可以复用"。**

> **核心判断 2**
>
> **每一期都必须是一个新任务，输入必须被显式选择。**
> 不是"把上期任务改几个数"，而是"在上期方法的基础上，选一批全新的输入"。
> 这两句话在实现上的差别很大：前者是**修改**，后者是**新建**。而修改留下的是"一份被改过的上期产物"，新建留下的是"一份独立的本期产物"——**后者才能被审计。**

### 18.1.1 上一期产物到底提供什么

这是本章最容易做错的地方。上一期的产物提供**两样**东西，而且只有这两样：

| 提供 | 用在哪 |
|---|---|
| **历史上下文** | "上期是什么情况" |
| **呈现结构** | "上次这个报告是怎么组织的" |

**它不提供当前事实。**

如果本期需要和上期做比较，正确做法是**显式选择上期的已核验记录或源输入**，让它作为"已授权的上期证据"进入流程——而不是从上一期的幻灯片里读一个数字出来。

**一条必须写死的规则**：

> **一张图表图片不是独立的数值依据。**

上一期的 PPT 里有一根柱子写着"实际"，看起来很明确。但那是**像素**。它不知道四舍五入到几位、不知道单位、不知道它的分母是什么。**从一张图里读数字，等于从一个已经完成计算的、丢失了口径的产物里反推事实。**

### 18.1.2 一个具体的"该重用什么"

"该重用什么"这个问题有一个非常好用的答案模板：

> **重用一个已确认的偏好，而不是一个隐藏的当前值默认。**

举例：复核者上期说"**先讲异常，再讲整体**"。这是一个**偏好**——本期的报告也应该遵守它。

而"上期的实际数是 250"是一个**当前值**——本期绝对不能用它。

两者的区别是：**偏好是关于"怎么做"的，当前值是关于"是什么"的。** 前者跨期稳定，后者每期都变。

| 可以跨期复用 | 绝对不能跨期复用 |
|---|---|
| 叙述顺序的偏好 | 任何金额、数量、比例 |
| 指标口径定义 | 任何"实际值" |
| 图表类型的选择 | 任何期间标识 |
| 异常判定阈值 | 任何预算数 |
| 模板与版式 | 任何合计 |

**右列的共同特征：它是"这一期的世界长什么样"。** 世界每期都变，所以它每期都必须重新取。

## 18.2 P1 → P2：一个能对上的例子

继续用第 14 章那套合成数据。

**P1 的三个条目**：A 合计 `20000`、B 合计 `5000`、整体实际 `25000` 最小单位。预算 `30000`，偏差 `-5000`。

**P2 是新的条目身份、新的期间。** A 仍然是 `20000`，B 变成 `7000`，整体实际 `27000`。

**一开始，P2 的 B 预算缺失。**

<div align="center"><img src="images/fig-18-2-context-roles.png" alt="图 18-2 上下文角色：历史上下文与当前事实的分界" width="1150"/></div>

**读图指引**：看最右一列——**只有标着"绝对不能"的那两行才是跨期数字的真正陷阱。**它们看起来都是"一份完整的报告"，所以在上下文里和"本期输入"长得一模一样。本章开头那个"B 的预算被补成 8000"的错误，就出在这两行上。

正确的处理是：

| P2 的中间结果 | 期望的处理 |
|---|---|
| 实际合计 | `27000` 最小单位；**对已接受的总账而言是完整的** |
| 与 P1 的变化 | `2000` 最小单位；比例 `2000/25000 = 0.08` |
| A 的预算 | 如果 P2 输入里显式存在，则可用 |
| B 的预算 | **缺失** |
| **完整的整体预算偏差** | **在预算覆盖范围解决之前，不可用** |

那份合格的报告这样写：

> 本期实际支出为 270.00，比 P1 上升 20.00（8.00%）。**完整的预算对比暂不可用，因为项目 B 在本期的预算缺失。**

**它不能写"本部门在预算内"。** 部分覆盖的对比必须**明确标注覆盖范围**，并且**经复核者同意**。

第一行和第二行是同一件事的两面：**能算的都算了，不能算的明确说不能算。** 第 14 章那条"缺失就是缺失"的规则，在跨期场景下的形态就是这一节。

### 18.2.1 预算补上之后

假设复核者补了一份新的 P2 预算修订：A `22000`、B `9000`。

**注意"从新的选定修订重算"这句话。** 不是"把 9000 填进去"，而是**换一个输入修订，然后整条链重跑**。第 16 章那条"改一个输入，不是改一个文本框"在这里的形态就是它。

| 指标 | P1 | P2 | 解读 |
|---|---:|---:|---|
| 实际 | 25000 | 27000 | 上升 2000，即 8.00% |
| 预算 | 30000 | 31000 | **各自属于各自的期间** |
| 实际减预算 | -5000 | -4000 | 欠支收窄 1000 |
| 预算比率 | -1/6 | -4/31 | 约 -16.67% 与 -12.90% |

**注意第 2 行的注释。** P1 的 30000 和 P2 的 31000 并列在一张表里，看起来很自然，但**它们不是可以直接相减的同一类数**——除非你明确说明这是在比较"两个期间各自的预算规模"。

P2 的 A 和 B 的预算偏差**各自都是 `-2000`**。整体比率是 `-4000 / 31000`，**不是各项目比率的平均**。第 14 章那个"加权平均不等于平均"的教训，在跨期表格里再出现一次。

一句可接受的叙述是：

> P2 支出上升，同时仍低于**新提供的 P2 预算**。数据确立了**变化量**，没有确立**变化的原因**。在确认项目完成状态与活动变化之前，不要把这次欠支描述为效率提升。

## 18.3 能算的与算不出来的

这一节是本章最需要纪律的一节。

| 句子 | 能算吗 | 需要什么 |
|---|---|---|
| "支出上升了 8%" | ✅ **能** | 两期的实际数 |
| "欠支收窄了 1000" | ✅ **能** | 两期的实际与预算 |
| "支出上升受会员增长影响" | ❌ **不能** | **会员数据，而账本里没有** |
| "效率提升了" | ❌ **不能** | 完成状态与产出量 |

> **核心判断 3**
>
> **数据能确立变化的量，不能确立变化的原因。**
> 因果关系需要**专门的证据**：时间顺序、机制说明、以及对其他可能原因的处理。
> 一份账本能告诉你"多少"，它不能告诉你"为什么"——**这不是数据质量问题，这是数据种类的限制。**

这条纪律在实操中的形态很简单：**每一个发现都要带上期间、单位、源定位符和计算身份**；**定量事实和提出的解释必须分开写。**

分开写之后，那句话会变成这样：

> 支出上升 8%（**定量事实**）。可能的原因包括本期活动增加或计费时点变化（**待验证的解释**）。现有数据不足以区分。

**这三句话的信息量比原来那句话更大，而且它没有被削弱——它变得更可用了。** 因为读者现在知道该去查什么。

第 17 章讲"没有测量支撑的收益要降级成假设"，这一章讲的是同一个动作的另一个方向：**没有证据支撑的因果要降级成待验证的解释。** 两者是同一条纪律。

### 18.3.1 这一节也适用于"智能体自己"

有一个容易被忽略的应用场景：**当你解释智能体的行为时，同一条纪律也成立。**

"这一期回答质量变好了，因为换了新模型"——这句话里，"变好了"需要测量（第 13 章），"因为换了新模型"需要因果证据。两件事都不能靠观察一次推断出来。

## 18.4 上下文角色：一个字段的语义

本章开头那个"旧数字残留在标题里"的问题，根因不是程序有 bug，而是**上下文里的每一段材料没有角色标注**。

一个真实的运行上下文里通常混着好几种东西：

| 上下文里的东西 | 它是什么角色 | 能不能当当前事实 |
|---|---|---|
| 本期选定的总账 | **当前输入** | ✅ 能 |
| 本期选定的预算 | **当前输入** | ✅ 能 |
| 上一期的完整报告 | **历史上下文** | ❌ **绝对不能** |
| 上一期的幻灯片结构 | **呈现结构** | ❌ 不能（它只是版式） |
| 已批准的口径定义 | **方法** | ✅ 能，且必须用 |
| 复核者的偏好记录 | **偏好** | ✅ 能（用于"怎么做"） |

**问题出在第 3 行和第 4 行。** 上一期的报告里**看起来有数字**——它是一份完整的、格式规范的、可信的产物。如果系统没有"这是历史上下文"这个标注，那么"从上下文里取一个数"和"从本期输入里取一个数"在程序看来**没有区别**。

**修法**：给上下文里的每一段材料加一个**角色字段**，并且让"当前指标只能从当前输入派生"这一条成为**可测试的断言**。

**修法**：给上下文里的每一段材料加一个**角色字段**，并且让"当前指标只能从当前输入派生"这一条成为**可测试的断言**。

这就是本章开头那个错误的正确修法：**不是"提醒模型别用旧数字"，而是"给材料标角色，并加一条测试断言"。**

> **一条通用判据**：当你发现自己在提示词里写"注意不要使用上一期的数字"时，就应该想到——**这句话应该变成一条测试。**

## 18.5 取消、重启与恢复：终态必须显式

这一节处理一件在演示里最容易被跳过、在真实运行里最常出问题的事。

### 18.5.1 取消

一个运行被取消了。**它的正确终态是"已取消"，不是"已完成"。**

看起来显而易见，但这里有三个容易出错的地方：

| 出错点 | 正确做法 |
|---|---|
| 界面显示"完成" | 显式展示终态：完成 / 取消 / 失败 |
| 部分产出被当成完整产出 | **不完整的产物不得被提升为已完成交付物** |
| 取消后没有清理说明 | 说明清理语义：留下了什么、删掉了什么 |

**中间那条是本章的硬要求。** 一份跑到一半的报告，它不是"一份还差一点的报告"，它是**一份不完整的产物**。把它当作交付物，后果比"少了几页"严重得多——因为它会被当成完整依据使用。

### 18.5.2 重启与恢复

另一个运行被打断了。重启之后，需要恢复它的**任务与检查点上下文**，然后创建一个**新的尝试**，且不产生重复发布。

这里有一个必须说清的边界，参考实现里有一句很直接的注释：

```ts
// 参考实现源码（BetterWork · apps/desktop/src/main/services/discussion-checkpoint-service.ts，MIT）
/**
 * 任务/运行/产物归属校验。
 * 一个持久化的任务检查点并不能恢复被中断的那次模型请求的调用栈。
 */
```

**这句话是这一节的核心。**

| 检查点**能**恢复 | 检查点**不能**恢复 |
|---|---|
| 任务与对话的**持久状态** | 被中断的那次模型请求的**调用栈** |
| 已确认的决定与产物归属 | 半途的工具调用状态 |
| 下一轮从哪个上下文继续 | 上一次流式响应的中间结果 |

**理解了这条边界，你才能设计对的重启策略**：重启不是"接着上次那一句往下跑"，而是**"带着持久状态，发起一次新的尝试"。** 于是：

- **新的尝试要有自己的身份**，不能被当成上一次的延续去登记产物。
- **不能重复发布**：上一次的（不完整的）产出不能被本次当成已完成。
- **原来那次失败的尝试，作为尝试保留在历史里。**

### 18.5.3 一个可以照搬的阶段划分

把这一节变成一条可执行的流程：

| 阶段 | 动作 | 验收点 |
|---|---|---|
| 1 | 用干净的数据包跑 P1，核验质量、计算与演示校验 | P1 三份产出全部通过 |
| 2 | 为 P2 **新建任务**，显式选择新期输入 | 任务 ID 与输入清单都变了 |
| 3 | 使用"预算缺失"的变体，记录不可用的对比与澄清 | 报告明确说"不可用" |
| 4 | 选定修正后的预算修订，重算，渲染已复核的 P2 演示 | 全部重复数字一致 |
| 5 | 在发布前**取消**一个受控运行 | 终态显式，无产出被提升 |
| 6 | 打断另一个运行，重启，恢复上下文，**新建尝试** | 无重复发布 |
| 7 | 对比每一处重复的图表 / 表格 / 叙述数字与核验值 | 逐项一致 |

第 2 行的"任务 ID 与输入清单都变了"是这一节最实用的检查：**先对比任务 ID 和输入清单，再对比结果。** 如果第一步就不一样，后面的差异都有了解释。

## 18.6 行业视角：期报在机构里的三重约束

这一章的内容在机构场景下会更严格，原因不是技术，是**期报本身的性质**。

| 性质 | 含义 | 对系统的要求 |
|---|---|---|
| **周期性** | 同一方法、不同数据，反复出 | 方法与数据必须**可分离地版本化** |
| **可比性** | 本期要能和上期对照 | **口径变更必须留痕**，否则同比失真 |
| **留档性** | 历史期报是历史依据 | 已发布的期报**不得被改写**，只能出新版本 |

第二行是机构场景特有的痛点。**当口径在期中发生变更时，本期与上期就不可直接比较了。** 通用场景下的处理通常是"注一下"，而在需要审计的场景下，正确做法是**同时给出新旧两套口径下的数**，或者明确声明本期不与上期直接可比。

第三行对应本章 18.4 节那条"上一期的产物是历史上下文"。在机构场景下，**历史期报本身就是证据**，它不能因为"口误"或"算法修正"被回头改掉。要改，就出一份带说明的新版本，并且**保留原版本**。

还有一条与部署形态有关的：**数据分级**。期报往往涉及经营数据，而经营数据在不同分级下的处理路径不同（能否出境、能否上公有云、是否需要脱敏）。第 18 章的流程设计必须让**数据流向是可以被检查和被拒绝的**，而不是"取决于配置怎么填"。这与第 17 章"部署形态不能混用"是同一条要求。

**本章小结**
重复期间的能力意味着：**复用已批准的方法、替换事实、重跑质量检查、保留独立身份、核验变化后的产出。** 缺失的数据在获得授权来源之前，**一直是缺失的**。

**六道自检题**：

1. P2 一开始的整体预算比率为什么不可用？一份"部分覆盖"的对比需要什么条件才能给出？
2. `8.00%` 这个数由哪些事实支撑？要主张因果，还需要什么证据？
3. 上一期的幻灯片作为上下文时，它能提供什么、绝对不能提供什么？
4. 一张图表图片为什么不能作为独立数值依据？
5. 一个被取消的运行的终态应该是什么？为什么"部分产出"不能被提升为完成？
6. 检查点能恢复什么、不能恢复什么？这条边界决定了重启策略的哪个关键设计？

**想得更远一点**：你已经能产出一份可复核、可重复、可交接的期报了。但**"能跑"不等于"别人能跑"**。第 19 章会把这个问题挑明：你的应用在别人的机器上，装得上吗？

---

**行动清单**

1. 把你的流程拆成**两列**：一列是"跨期复用"（方法、口径、偏好、模板），一列是"每期重取"（所有数值）。照着这个划分检查一遍现有实现。
2. 给上下文里的**每一段材料加角色字段**。没有角色的材料，默认**不得作为当前事实来源**。
3. 加一条**测试断言**："当前指标只能从当前输入派生"。这一条必须能用测试失败来证明它有效。
4. 检查全部输出位置，**包括标题、页眉、备注**。旧数字最容易漏在这些不参与"重算"的位置。
5. 为"缺失数据"设计一条**固定的报告句式**，让每一次缺失都被明确说出，而不是被悄悄补上。
6. 演练一次**取消**和一次**重启**，记录终态与产物状态。
