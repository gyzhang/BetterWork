- 对象：在长期工作空间内持续完成研究、分析和周期交付的个人知识工作者。

## 3. 范围、优先级与可测目标

### 3.1 分阶段交付

- **MI-M0：先修正确性**。来源继承、可解释的选区定位、独立排除恢复。
- **MI-M1：再让关键规则稳定出现**。少量用户明确标记的「优先带入」规则＋原有相关经验检索；未标记记忆维持旧召回行为。
- **MI-M2：降低治理与换期负担**。并列来源和并存条件、换期恢复指引、连续两期验证。
- **MI-M3：证据收口**。离线自动化、真实 UI、另行授权的真实模型语义验收，分别记录。

不进入：记忆 Embedding/向量库、自动同义词扩写、重排模型、全量聊天扫描、定时反思、自动确认、自动提升为优先、跨空间复制、自动摘要恢复旧历史、知识图谱、全局使用开关、商业数据上传、自动修复历史错误来源。

### 3.2 目标与采集

以下是验收目标，不是已取得的业务数据；实际基线、完成日期和模型结果待执行后填写。

| 目标 | 分母与方法 | 通过条件 |
| --- | --- | --- |
| 普通保存不丢来源 | MI01/02 全部来源正反例 | 成功记录完整依赖；未知来源拒绝；零静默 manual 降级 |
| 排除可逆 | MI03 的重算、切任务、重启、预览失败四种旅程 | 四种均能在原任务找到排除项并取消排除 |
| 关键规则不靠关键词碰运气 | MI09 的 8 个同义/无词面合成查询，每个适用优先规则均满足安全与预算条件 | 8/8 在实际请求中携带；不将其等同于模型遵从 |

## 4. F1 回答保存：确认不等于洗掉来源（P0）

**用户故事**：我希望把一段回答保存为可复用经验，同时仍知道它来自哪次工作、依赖哪些材料与记忆。

### 4.1 正常流程

1. 在已完成回答中点击「记住这段经验」。入口绑定这条回答的最终消息事件，不读取别的回答或页面选区。
2. 选区能与该事件原文唯一精确对应时，预填来源摘录；不能对应时，打开只读原文选择区，明确提示重新选取，不猜测 Markdown 渲染后的坐标。
3. 来源摘录与最终记忆正文分开：摘录只读，正文允许编辑；普通编辑不会解除依赖。
4. 表单显示来源任务、原始摘录、依赖数量、使用仍需满足材料范围；默认当前工作空间，专家工作空间可选，全局范围不提供给派生内容。
5. 点击「保留来源并记住」后，Main 重查来源与依赖，原子写修订和回执；成功才关闭表单。
6. 未选择原文时不把整段回答默认保存，不擅自截取开头充当来源。

### 4.2 自主要求另走显式路径

本期回答捕获表单**不提供一键解除来源**。确需抽象成独立要求时，先保存有来源记忆，再从记忆详情进入已有「作为我的工作口径重新保存」，重述正文并确认范围；新记录保留重述操作关联，不声称原事实已核实。独立手工输入入口仍保留。

### 4.3 异常与历史

- 空选区、重复文本、多段选区、选中别处、超长摘录：要求在原文重新选取，保留当前表单，不自动变成人工来源。
- 未完成、已取消/失败、非最终工具轮消息、跨空间或来源缺失：拒绝保存，给出可操作错误。
- 来源依赖缺记录、超限、循环或无法验证：拒绝，不裁掉依赖；编辑后换范围仍需 Main 校验。
- 关闭未提交表单不写库；提交已成功后关闭不表示撤销，传输超时按原 operationId 重试。
- 既有错误 manual 记录没有可靠 Run/Event 反向关联，不能自动找回、批量作废或按相似文本补造来源。提供验收中的人工核对指引；重新保存正确记录后，明确删除旧记录，确认旧内容不再重放。

## 5. F2 本任务排除：恢复入口独立存在（P0）

**用户故事**：我暂时不用一条记忆后，无论换 prompt、刷新或重启，都能在这个任务恢复它。

- 上下文面板「记忆」内分为「下次运行可用」「本任务已排除」「本次运行记录」。已排除列表来自持久化任务上下文，不依赖 selectedItems、词面命中或排除摘要前 50 项。
- 点击「恢复参与选择」只移除本任务排除，不强制注入、不重新确认过期记录、不取消其他任务的排除。重算后可能显示「仍未入选：无关/来源待复核/已失效/预算不足」。
- 当前范围可见的行显示正文和状态；超出范围或不存在的行只显示「此项当前不可查看」及「移除此排除」，不泄露别的空间正文、标题或来源。
- 保存期间禁用同任务重复操作。冲突保留用户意图，刷新最新 TaskContext 后让用户重试，不自动用旧快照覆盖材料和模型绑定。
- 无 prompt、预览失败、切换专家后范围变化都不影响管理排除列表；列表读取失败与预览失败分开反馈。
- 运行中的快照不变，调整影响下次运行；需要当次生效则用户取消重跑。关闭面板不取消已经提交的保存。

## 6. F3 关键规则「优先带入」（P1）

**用户故事**：少量明确的长期工作要求不应因我换一种问法就消失。

- 在记忆详情显式设置「按相关性选择 / 优先带入」。只允许已确认、来源已核实的自主工作要求，限定合适的规则分类；事实与经验仍按相关性选择。
- 不按分类自动提升，不自动替用户选重要规则，不把旧候选升级。四作用域不变，优先不代表全局适用。
- 通过范围、有效期、排除、来源/依赖和冲突门禁后，优先池不要求词面命中；然后保留通用偏好小池，再选相关经验。每条只计算一次。
- 预算有限；优先表示免词面门槛、先分配预算，不表示无条件必带。超预算、冲突、排除等在预览中可见，不悄悄按更新时间决定业务真假。
- 当前指令与本期材料仍优先；优先带入不赋予工具权限，不表示模型已读或一定遵从。
- 调整策略追加修订并影响新 Run；沿用保守历史规则，即使正文不变，旧修订依赖也可能使历史截断，详情确认文案须说明。
- 若 D3 暂缓，先独立交付 MI-M0；不为赶进度用 prompt 硬编码代替策略。

## 7. F4 冲突裁决：看清来源再决定（P1）

**用户故事**：我希望区分互补规则和真正矛盾，不因「可能冲突」标签误删正确规则。

- 保留现有确定性潜在冲突算法，不新增 LLM 判定。明确展示「同议题、适用范围与时间重叠；尚未判定业务矛盾」。
- 并列展示两侧正文、适用范围、有效期、来源摘要；可按需展开精确来源，不展示原始事件载荷。
- 「保留两条」必须填写适用说明；保存后可在同一位置查看说明。没有条件的「忽略所有冲突」不是可选项。
- 替代、编辑、并存仍走现有原子写入和并发校验。修订变化使旧裁决失效，不能把旧说明显示成新修订已获裁决。
- 另一侧不可查看时只提示需在合法管理范围处理，不显示其正文；失败不自动替换、不自动给模型任选一条。

## 8. F5 换期连续性：重建合法工作上下文（P1）

**用户故事**：换用本期数据后，我希望保留方法，明确知道哪些历史不再发送，以及怎样继续工作。

- 历史调整区解释「旧记录仍可回看，但此次不发送」，列出安全原因；不声称对话被删除。
- 缺少本期材料：提供「查看本次材料」入口；已有的材料选择流程由用户明确选择，不自动把旧版换成 latest。
- 需要沿用结构：打开精确成果版本详情，再由用户「引用到当前任务」或「从此版本开始新任务」，用途沿用已有枚举，标记参考不等于已读取。
- 希望跨期保留方法：进入记忆详情，使用既有自主要求重述路径，而不是把旧回答自动总结成空依赖记忆。
- 从成果开始新任务的默认专家身份依据来源 Run 的执行快照，不依据旧 Task 当前草稿；当前专家配置已更新则先确认使用当前版，不恢复旧权限或复制旧任务绑定。快照缺失/专家不可用时明确提示并让用户选择通用或可用专家，不静默顶替。
- 不复制旧聊天、不默认带入旧期间事实、不新增「一键恢复全部历史」。所有跳转可返回原任务，保留 prompt、专家和现有选材；不自动发起 Run。

## 9. 低保真结构与拍板点

原型仅演示交互，不连接真实资料、IPC、模型或数据库；范围细则以本文和契约为准。

| 决策 | 推荐 | 可选取舍 |
| --- | --- | --- |
| D1 来源 | 普通保存一律保留来源；原文重选解决定位不确定；自主重述在详情另走 | 不把回答表单变成默认人工来源 |
| D2 恢复 | 独立「本任务已排除」，动作称「恢复参与选择」 | 不承诺恢复后一定注入 |
| D3 稳定规则 | 显式「优先带入」＋小预算；默认按相关性 | 可先只开工 MI-M0，延后 MI-M1 |
| D4 冲突 | 保持算法，先补并列来源与并存条件 | 语义冲突算法留后续，不减少安全门禁 |
| D5 换期 | 解释历史截断＋复用精确成果与本期选材 | 不摘要绕回旧依赖；保留原任务上下文 |

2026-09-25，光哥查看评审原型后明确「批准 D1～D5 的建议」，以上五项推荐均已批准。此次仅记录设计批准，MI00–MI10 尚未开工；ADR 正式接受、单卡开发、真实模型调用及提交发布仍分别记录。后续明确「按推荐方案执行 MIxx」可构成指定范围的实施授权，方案未变无需重复确认已批准细节。

## 10. 验收与风险

每个功能至少三条 Given–When–Then 和细分技术负例见[任务板 §4–§6](../development/tasks-memory-improvements.md)；没有自动化证据的原型点击不算产品验收。

| 风险 | 处理 |
| --- | --- |
| 小模型一次改动跨太多层 | 一卡一个结果；协议/服务/UI 的必要垂直切片不拆成空壳；固定文件边界与停止条件 |
| 历史错误 manual 无法自动追源 | 明示遗留风险，人工重存与删除旧条；不宣称升级修复了过去数据 |
| 优先规则过多或冲突 | 有限预算、稳定顺序、可见排除；仍要求用户裁决 |
| 新策略破坏旧 Run 回看 | 版本化解析保留真实 v1 快照，不重写历史或伪造新字段 |
| 严格来源使旧捕获被拒绝 | SOURCE_REVIEW_REQUIRED，而非接受无法证明的空依赖；独立自主输入仍可用 |
| 真实模型不遵从 | 与上下文装配问题分开；记录模型/参数/请求阶段，不能靠调测试期望冒充修好 |
| 并行 KM/CF 争迁移号和共享文件 | 每卡重新查 HEAD、迁移号和未提交文件；冲突处停，不覆盖并行会话 |

质量自检：需求源于当前评审；无虚构业务数据；目标与分母明确；产品行为与技术契约分离；正常/失败/取消/并发/恢复均有定义；现有角色只有个人使用者及宿主/模型边界，不引入企业角色；排期按完成门槛推进，不承诺一个下午完成全部改进。
