## 2. 保持的契约与推荐方案

### 2.1 已接受的边界

- 数值策略只覆盖 `builtinToolPolicy` 明确 allow-list `analyze_business_metrics` 的 Run；普通 Run 的数值输出不套用该策略，原有定性检查保持。依据 [ADR-0020](../adr/0020-deterministic-business-analysis.md)。
- 输入核验同一指标、数值、单位、期间和当前 Run 已读来源；派生值只能来自确定性工具。最终数值主张沿用 ADR-0020 的同一行显示指标、单位与全部相关期间的要求。
- 事实只驻留当前 Run。来源 ID、Knowledge Evidence、材料授权范围、读取足迹及来源哈希保持既有语义，不扫描未读材料、不回填历史 Run、不修改用户文件。
- Office 继续消费已选快照/精确版本；保留 Sheet、A1/行列定位、缓存值和缺缓存警告，不计算公式、不刷新外部连接。依据 [ADR-0018](../adr/0018-office-input-parsing-boundary.md)。
- 成果修订继续产生新版本，保留精确 Run、Evidence 与输入关系；已提交的原成果保存不因用户切换而撤销。依据 [ADR-0005](../adr/0005-artifact-version-evidence.md)。
- Renderer 成功、失败、busy、反馈和编辑态均按操作归属与请求代次收口；一次结果只有一个呈现出口，复用 `InlineError`、`TransientToast` 与现有页面骨架。

### 2.2 QI01 定稿的关联契约

QI01 将 ADR-0020 第 5 项中的“数值、指标、单位、期间、来源”落实为以下宿主校验规则。它不新增工具输入定位字段、IPC Schema、数据库表或迁移：`sourceId` 继续标识本 Run 中一次实际读取结果的来源片段；文本通过片段内局部主张定位，Office 通过解析结果中的结构化记录定位。定位不足以唯一证明时，明确拒绝，不退回整段关键词搜索，也不让模型选择冲突值。

| 范围 | 定稿规则 |
| --- | --- |
| 来源身份 | 每项直接事实只能引用本 Run 实际读取的精确 `sourceId`；用户原提示只用保留 ID `user-prompt`。同一来源 ID 的内容冲突使 Run 失败。不同来源之间不互相补字段，未读取的选中材料、历史 Run 和旧 Evidence 都不能支撑事实。 |
| 文本主张单元 | 同一 sourceId 的换行和句号/问号/感叹号/分号是硬边界；仅数值与紧邻单位之间的换行空白按同一个单位 token 处理，以保持既有空白规则。其余在一行或句内按显式指标名分开并列断言，每个指标片段必须唯一对应一个数值/单位对。只有一个明确期间时，可在同一行/句内共同修饰这些片段；多个期间必须各自明确落到指标片段。不能唯一切分的多指标、多数字或多期间拒绝，不跨段落补齐。否定、缺失、假设或待确认内容不支撑已发生的直接事实；角色为 budget 的输入仍须在来源中明确对应预算口径。 |
| Office 主张单元 | 以本次读取且实际返回的表格记录为单位：PPTX 同一表格行；CSV/XLSX 同一行，并只可关联该记录所属且已读到的明确表头。保留 section locator、Sheet/单元格地址、行列和值；不跨行、跨 Sheet、跨页、跨 sourceId 组合。无标题、重复/冲突表头、合并区域或记录边界不明时拒绝；公式只使用现有解析器返回的缓存值。 |
| 重复与冲突 | 按口径区分实际事实（`current`/`previous`）与预算事实（`budget`）；同口径的同指标、规范化期间必须一致，重复断言仅在数值和单位一致时可合并。同期间实际值与预算值可不同，不能据此拒绝。某一口径内出现跨来源的冲突时，当前输入批次整体拒绝，不能择首/择末或按来源顺序猜测；失败发生在计算及记账之前，不留下部分事实。 |
| 规范化 | 数值必须是有限直接值，不做单位换算或推算；单位只做 NFC、首尾空白和全角百分号归一，其他拼写必须一致。期间先做 NFC/首尾空白归一；明确的年月格式（如 `2026-10` 与 `2026年10月`）可归为同一月，明确的年月日只与同一天匹配，季度/财年等其他标签按规范化后的完整文本比较。不给模糊日期或“最近一期”等相对说法推断期间。 |
| 确定性派生 | 只有成功的 `analyze_business_metrics` 结果可以新增差额、变化率、预算偏差或偏差率事实；保留所有输入期间、来源与单位。模型手算的派生值、没有对应已核验输入的结果、零基数下不存在的比例都不登记。 |
| 最终输出 | 逐个审计每条数值业务主张；每个数值只能由自身主张单元中的指标、单位和全部相关期间匹配一条无冲突的已核验直接或派生事实。预算事实只能支持同一主张单元明确标成预算的数值，不能给实际数值背书，反之亦然。每个显式指标名界定本行/句的一个指标片段；一个期间可在该行/句唯一时共同适用于并列片段。多值、多指标或多期间无法唯一分配时拒绝。候选数值包括与已知指标/分析主张相邻的数值（即使缺单位），以及含数值和计量单位的业务表达；表格行若包含已知指标或指标列即进入审计。表头可以帮助发现待审计表格，但不能补给任何主张字段。同一行的另一个主张、其他行或段落级数字都不提供许可。缺单位、缺期间、无指标的业务值和 Markdown 表格裸业务值必须被识别为待审计主张并拒绝。 |
| 非业务数字 | 日期/期间组成部分、列表序号、版本/标识符、代码与 URL 中的数字不自动视为业务主张；排除这些语境后仍需按指标、单位或业务变化词识别数值，不把所有裸数字一概拒绝，也不能靠改成表格、列表或代码样式隐藏业务值。 |
| 失败语义 | 任一输入事实失败时整批拒绝，不调用确定性计算、不写入事实账本；Run 沿用既有失败终态及清理。输出审计失败不发布候选成功或登记成功成果。普通 Run 不启用数值策略，材料范围内既有定性事实检查保持独立。 |

按此规则，文本“2026年10月收入为100万元。2026年10月成本为80万元。2026年9月收入为90万元。”仅支持 10 月收入 100、10 月成本 80、9 月收入 90；不能用 80 或 90 冒充 10 月收入。“2026年10月实际收入100万元；2026年10月预算收入80万元”可同时提供同期间的实际与预算输入；实际/预算差异本身不是冲突。Office 表头 `期间,指标,单位,数值` 下的记录 `2026-10,收入,万元,100` 可支持该事实。账本只有 10 月收入 100 时，最终输出“2026年10月收入已核对。2026年10月成本为100万元。”、“2026年10月收入为999。”及表格行 `| 收入 | 万元 | 999 |` 均拒绝；正确行不能替错误行授权。

上述局部定位是 QI02–QI04 的实现验收契约，不表示这些关联已经全部落地。最终输出继续执行 ADR-0020 的同一行规则：表头可以帮助解释输入表格记录，不能替最终输出行补指标、单位或期间。QI05/QI06 按 ADR-0005 保留已提交版本与精确来源关系，只让当前导航代次更新 Renderer 状态。

### QI02：文本输入事实精确关联

- 目标：当前指标事实只从它自己的已读来源位置取得，不因来源中其他数字相同而获得许可。
- 工作：先补混合指标/期间、同期间实际与预算口径、同口径冲突和否定/待确认负例，再实现局部定位与全维度校验；同一行多主张分别定位；整批输入先核验后登记，失败不留下部分事实。工具输入若变化，JSON Schema、Zod、调用说明与宿主校验同轮一致。
- 落点：Application 事实策略；必要的工具输入变更只在 `packages/tool-runtime/src/business-metrics.ts` 及既有消费者接入，不把宿主来源逻辑放入 Agent Core。

- 失败/取消：拒绝输入不计算派生值、不污染账本；取消仍走现有终态与清理。数值主张支持失败与工具调用失败的呈现层次依定稿契约，不新增反馈通道。
- 必测：事实策略与业务工具 functional；RunService heavy 中显式经营分析与普通 Run 适用边界。算法规模改变时补/跑既有事实策略 bench，不在功能测试写墙钟断言。
