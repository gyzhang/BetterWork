# 定时任务待办（SC00–SC11）

- 登记日期：2026-09-25；依据：[定时任务设计 v0.3](../designs/scheduled-tasks.md)。本文件是 SC 系列唯一任务状态板。
- 当前授权：形成设计并登记待办；未授权本轮编码、安装依赖、执行真实模型或提交发布。技术方案仍为 Proposed，不能因登记待办自动改为 Accepted。
- 候选推进窗口：光哥考虑在 2026-09-25 测试其他功能后，于 **2026-09-26** 开始推进。是意向，不是确定排期、完工承诺或到时自动启动的指令。
- 既有顺序：专家能力稳定后推进；SC00 核对本功能实际依赖与测试结果，不擅自关闭或重排 E/WM/MI/KM/CF/A/B0 的卡片，不把所有历史验收尾项泛化为调度开发门槛。

## 1. 已确认产品基线

1. 一个定时任务长期使用同一个工作目录；连续六个月是同一 Workspace 下的六次工作记录，不是六个项目。
2. 生成物在该目录持续积累，人可手动增减资料；下一次按当时目录和已选知识范围取材。单次材料版本固定，目录不被锁死。
3. 创建时选择已有专家、工作目录，按需添加知识资料或知识库范围。附加资料配置属于 Schedule，不修改专家定义。
4. 上月、上季度、上半年等历史资料可用于当前分析；本期统计期间不等于资料时间下限，不自动继承整段聊天。
5. 错过只提醒，不自动补跑；后台执行不抢界面，结果由人检查，通知复用原机制。
6. 使用成熟 cron 解析库；导航入口在专家下方、业务主导航最后；专家有新版本必须提示，应用既有版本只改调用绑定。
7. Workspace 的“项目”文案以后统一处理，不新增 Project 实体或平行目录体系。

完整行为只维护在设计文档；下表记录工作范围与证据，不复制一份 Schema 或技术标准。

## 3. 逐项完成定义

### SC00：开工基线与依赖复核

- 阅读设计、当前工程规范、专家/材料/知识契约和相关任务板；重核 git 状态、实际协议、迁移及 ADR 编号，不使用旧 v33 推断下一迁移。
- 复核专家调用、模型/信任/依赖、Office 与知识读取、成果、通知、主进程生命周期；区分已实现、未接后台、仍需实际验收。
- 列出影响本次工作的具体缺口及归属，不趁机重做专家/知识模块，不要求光哥重复确认已明确的长期目录语义。
- 完成证据：基线与阻塞清单、保留的用户改动、后续文件边界；不写业务代码、不调用真实模型。

### SC01：精确契约与技术决策收口

- 定稿 Schedule/Occurrence 的状态、CAS、自动时刻唯一键、人工请求回执及与 Task/Run 的原子关联；Run 仍是执行终态真相源。
- 定稿目录与知识文档/集合/库的选择映射、动态成员/修订策略、固定专家参考冲突、精确范围快照、读取预算与来源记录。大范围来源不得强塞现有材料数组，也不得偷偷降级为仅少量文件；超限行为需可解释。
- 明确快照/审计保留不授予下一期读取权，目录删除不从旧存档复活；实现级扩展必须保留已有人工任务范围与来源治理。
- 定稿成果输出位置、命名、防覆盖、版本与目录回执关联、单独重试保存；明确目录副本编辑后作为新输入而非改写旧版本。
- 明确 cron 库版本/API、时区、迟到窗口、主期间默认值、后台能力适用性，以及退出/恢复/无窗口通知行为。业务期间有歧义才请光哥确认，不增加复杂配置表。
- 完成证据：可执行的契约及必要 ADR 提案、与现有契约的差异清单、关键决策批准范围；不预占编号、不以文档落地代替批准。

### SC02：低保真交互评审

- 在后续授权下制作列表、创建/编辑、来源选择、历史、专家版本提示、缺材料及目录保存失败原型；本次归档仅有文档草图，不算此卡完成。
- 主流程必须是选择已有专家、持续工作目录、添加知识/知识库、设定周期与要求；不内嵌专家定义编辑，也不每期重复索要目录。
- 展示一个规则下的多期记录和历史对比来源，保留当前对话/草稿；导航位置和反馈服从 UI 规范。
- 完成证据：光哥的原型评审记录及与 SC01 一致性结论。未通过前不进入页面实现。

### SC03：共享协议、规则与实例持久化

- 协议先行，版本化迁移与仓储随后；规则保存 Workspace、专家引用、知识来源，实例保存配置与范围引用、计划时刻和运行关联。
- 真实 SQLite 覆盖 CAS、自动时刻去重、人工请求幂等、无 Run 的错过/失败事实、归档不级联删除历史、通知/目录保存回执。
- 先登记事实再广播；明确 Workspace/历史 Task 删除后的关联处理。不得把实例结果再存成一份独立的 Run 终态。
- 完成证据：协议、仓储与新旧库迁移/重开/回滚/外键测试；源码无未使用的未来占位字段。

### SC04：工作目录与知识范围解析、单次快照

- 读取既定目录当时的业务资料及已选知识范围，兼顾本期、历史对比和稳定参考；不强制按月改造目录。
- 精确记录文件快照、知识成员与修订、用途和来源；正文按需检索/读取，目录/库的更新只影响后续实例。
- 覆盖新文件、手动改动/删除、空来源、集合变化、缺失、版本冲突、非法路径、符号链接、元数据排除、超预算及取消。
- 完成证据：临时目录与真实仓储集成测试，证明未选择知识库不可读、被删除内容不从旧存档隐式注入、当前 Run 不跟随更新。

### SC05：调度时钟、错过记账与应用生命周期

- 使用库统一生成预览与实际计划；固定时区、非零分钟、月末/跨年/支持时区边界按契约处理。
- 单一调度所有者先于中断恢复；初始化就绪才派发；启动/唤醒只记错过，不补跑；暂停/归档前结算已到期记录。
- 同规则重叠跳过、不排队；暂停不隐式取消活跃 Run，退出先停止新派发；旧 timer 和异步准备不可绕过状态变化。
- 完成证据：注入时钟和数据库测试，覆盖多周期错过、重复回调、时钟跳变、重启、退出与恢复，不等待实际日历时间。

### SC06：既有专家后台装配与原子 Run 关联

- 将与人工召唤一致的装配收进 Main 可复用入口；绑定既有专家修订、能力、参考及 Schedule 附加来源，不能调用 Renderer 开始工作。
- 每次工作新建 Task/Session 但沿用同一 Workspace；正确提交上下文 ID 与 expectedRevision，在 Run 创建事务内关联实例，提交后派发。
- 全部调度操作保持专家定义只读；指定模型缺失不回落教学模型，信任/依赖/凭据失效不放行；不实现第二套 Agent 引擎。
- 完成证据：真实服务链路的 Fake Provider 集成测试，覆盖关联前后崩溃、重复触发、预检失败、取消及独立任务历史隔离；无真实模型流量。

### SC07：成果登记与同目录持续交付

- 复用 Artifact/版本/来源登记，把实际生成的目标产物保存到原 Workspace 的已约定成果位置；不新增 Workspace、不覆盖前期成果或个人文件。
- 文件与版本有可追溯回执；同名、重复保存、保存中断及人已修改副本时保持幂等和非覆盖。
- 目录不可写时保留内部成果，只重试文件保存；下期可从目录使用历史产物作对比，人工编辑副本视作新的输入快照。
- 完成证据：合成 Markdown/PPTX 与目录集成测试，证明登记成功不伪装目录保存成功、失败重试不发第二次模型请求。

### SC08：结果分层、通知去重与恢复导航

- 区分缺资料、无约定产物、已生成且保存到目录、目录保存失败、Run 失败/中断；产物存在不等于业务验收通过。
- 复用 NotificationService 的统一收口，每个结果幂等持久化；初始结果需包含目录保存结论，不先报完整成功再由第二条重复通知纠正。
- 目录保存的后续人工重试可产生独立可追溯结果，但不能重做 Run；通知清空/淘汰不导致旧结果反复重发。
- 覆盖无窗口通知、点击后恢复/导航、已不在最近列表的历史任务、错过实例目标；后台不抢当前编辑上下文。
- 完成证据：仓储、服务与路由测试，加受控生命周期验证；原人工 Run 通知行为不退化。

### SC09：定时任务页面及调用绑定更新

- 实现已评审原型、统一页面骨架、专家下方最后一个业务入口、目录选择和知识/库选择、周期、启停、手动触发、历史及取消。
- 专家新版本提示只更新 Schedule 引用，完整保留目录与附加知识；不得生成/保存专家定义或嵌入专家编辑器。
- 展示持续目录及多期记录、期间与实际来源、目录交付情况；失败保留草稿、IPC 使用统一 Hook 收口，不自造通知。
- 完成证据：组件/Hook 回归和真实窗口走查记录；按实际授权执行 UI 验证，未走查不能以类型检查替代。

### SC10：连续六期及失败路径离线联合验收

- 用注入时钟模拟六期，始终同一 Schedule/Workspace；中途新增/修改/删除文件，改变知识集合成员，产生历史报告并参与月/季/半年对比。
- 断言主期间不排除合法历史资料、当前版本固定、来源与成果可追溯、目录新旧文件不覆盖、专家定义全过程未被修改。
- 覆盖错过不发包、启动前后崩溃、人工双击、取消、目录保存失败、通知恢复；对关键去重和越界守卫做反向用例。
- 完成证据：设计 §11 矩阵逐项对账、相关测试和 `npm run verify` 的真实退出码；并行负载导致基准异常时按既有纪律定位，不改阈值凑绿。

### SC11：实际专家与人工业务验收

- 光哥确认模型配置与调用预算、可用业务材料和人工走查窗口后执行；本待办不构成这些授权。
- 调研、工作周报、月度经营分析分别验证技术链路与可交付性；需多轮确认的专家停在可继续协作的位置，不代人批准、不假报完整 PPT 已交付。
- 验证长期目录实际增减、知识引用、跨期对比、查看/修改成果、取消与重启；真实用例不复制到 Git 仓库。
- 完成证据：实际运行/成果/来源与人工结论，分开记录自动化、真实窗口、真实模型三层；未具备条件保留待验状态，不代光哥验收。
