# A18–A21：PPTX 成果与产品分发

共同遵守 [执行手册](README.md) 和 [共享契约](contracts.md)。本组完成后才可认定阶段 A 整体完成。

## A18 文件成果协议、存储与验证

- 前置：A17。
- 必读：ADR-0005、artifact-repository、共享 Artifact Schema、docs/12 §6/7、执行器设计 §10。
- 目标：新增 presentation 文件型 Artifact/Version、分项验证状态和文件登记服务；Markdown 继续兼容。
- 允许改动：agent-protocol、Artifact 仓储/新迁移、file-artifact-service、必要工具工厂及测试。
- 实施：文本和文件详情判别联合；不可变文件落盘→DB 事务关联→广播；文件 URI 不直接暴露任意读取能力。artifact_register_file 输入 executionId/outputId，校验 Run/Task 归属、本次输出 hash、校验报告、取消状态。文件缺失显示错误，不能临时生成空 PPT 冒充恢复。
- 必测：历史 Markdown 数据升级；跨任务引用拒绝；报告与输出 hash 不同拒绝；符号/硬链接借道拒绝；旧产物/迟到输出拒绝；取消与登记竞态；文件写成功 DB 失败清理；DB 引用文件丢失；重复请求不重复登记；结构失败不交付；结构通过视觉未检查标草稿。
- 验收：同一 PPT 重新生成新增版本，不覆盖旧版本；两种 Artifact 的测试和完整 verify 通过。
- 不做：应用内 PPT 编辑器、来源推断/伪造 Citation；A 样本来源为空则如实保存。

## A19 文件成果 UI、打开与导出

- 前置：A18。
- 必读：ArtifactView/use-artifact-viewer、ContextPanel、docs/10、docs/12、执行器设计 §10/11。
- 目标：成果页展示 PPTX 版本、验证状态、来源与生成执行；支持打开、导出指定版本。
- 允许改动：文件成果 IPC/Preload、Artifact hook/view、报告组件、必要 icons/styles、对应测试。
- 实施：Main 根据 artifactId/versionId 找文件，系统保存对话框决定导出目标；IPC 不接收任意机器路径。应用主区域显示内容说明/验证状态和可用预览，不把二进制按 Markdown 渲染；无渲染后端时明确系统打开，不给虚假缩略图。
- 必测：旧版本导出正确；取消保存不报成功；文件缺失可见；异步切换不串版本；打开白名单；重复请求状态；Markdown 查看编辑导出回归；视觉未检查状态不变为 passed。
- 手工验收：公司样本 PowerPoint 打开无修复提示、文本/图形可编辑、另存后可再次打开；原模板未改。系统应用缺失则明确提示，不写已通过。
- 验收：成功导出通过既有通知体系反馈；相关 UI/IPC tests、verify、手工报告齐全。
- 不做：自动把用户办公软件修改过的文件当作已登记新版本，外部修改回收留给后续明确任务。

## A20 内置资源与依赖制品打包

- 前置：A19，平台 helper/运行制品已通过对应实际平台探测。
- 必读：docs/11 §3、ADR-0011、electron-vite 配置、执行器设计 §4/5.1、A11 的依赖锁报告。
- 目标：源码 resources/skills、安装资源 skills、用户数据 skills 三处行为一致；包含固定 runtime/依赖资源准备入口。
- 允许改动：electron-builder/根构建脚本及 package 配置、资源定位器、制品清单、通用内置 Skill、CI 测试与文档；发布动作不在本卡授权内。
- 实施：先增加本地打包配置 → 清单校验 → extraResources 复制完整 Skill → 平台 runtime/helper 资源寻址 → 安装后环境准备 → 升级数据路径验证。解释器和 wheels 通过制品获取/构建流程，不将二进制或绝对开发路径硬写入源码。
- 必测：开发/安装模式寻址；缺资源或 hash 失配拒绝内置信任；相同名字的 user 与 builtin 并存；升级保留副本/disabled/revoked；旧绑定资源可回看；无 .workbuddy 或 Downloads 隐式依赖；包内无 Key/数据库/私有模板/历史项目。
- 验收：本地构建安装包，实际解包核对文件清单；冷环境准备无需手工 git/pip；在线下载若必需需走显式准备流程。记录包路径/hash/大小/平台，不上传公共渠道。
- 不做：自动发布 GitHub Release、自动更新服务、代码签名密钥申请或系统安装工具链的隐式操作。

## A21 安装验收、回归与阶段 A 收尾

- 前置：A20；全部前置完成或用户明确接受的限缩平台范围已有文档（不能据此把未测平台标通过）。
- 必读：任务板、ADR-0009/0011、产品定义、运行设计验收、前序任务交接。
- 目标：证明普通使用者可从安装到运行 Skill 再到可编辑 PPT，不依赖开发环境。
- 允许改动：验收报告、发现的本范围缺陷及回归测试、当前能力/交接文档、任务板和日志；缺陷需要跨主题改动时单列补救任务，不混入 B。
- 必做旅程：新用户数据目录启动 → 内置列表/默认信任 → 导入样本 → 明确信任 → 准备环境 → 最小真实任务 → 校验 → 成果/版本 → 导出/PowerPoint 编辑 → 再修改生成新版本 → 重启回看。
- 必做反向旅程：未信任拒绝执行、停用拒绝、撤销在途清理、超时、子进程异常、缺依赖、校验 exit=0 但 issues 失败、旧文件误认拒绝、更新不恢复撤销、用户模板和副本不变。
- 平台：macOS、Windows 分别记录真实结果，不能用一个平台推断另一个；未支持的平台不计入完成声明。
- 验收产物：新增 `docs/reviews/phase-a-acceptance.md`，列环境/版本/制品 hash、测试命令与退出码、手工步骤、失败修复、仍存在限制、明确完成范围；更新 docs/11 当前能力表和路线图状态。
- 完成判据：A01–A20 对应范围有证据，verify 通过，核心/失败/取消路径可解释，安装后不依赖开发机路径，私有内容未进入 Git。全通过才标阶段 A done。
- 不做：发布、提交、专家配置或研究流程。用户需要提交/发布时另按明确授权操作。
