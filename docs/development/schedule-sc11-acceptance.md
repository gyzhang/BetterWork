# 定时任务 SC11：人工与真实业务验收

## 当前状态

SC03-1 至 SC10-2 的代码、离线测试、生产页面 Electron 检查及完整 `npm run verify` 已有证据；应用库 schema v38、Knowledge Vault v7。SC11 的真实窗口/专家/资料/模型调用和业务质量判断尚未执行，必须由光哥提供本清单的真实验收授权后再开始。六期 Fake Provider 旅程证明技术链路，不代替真实模型的语义效果或人工批准。

任务入口是应用侧栏「定时任务」和[SC 唯一任务板](tasks-schedules.md#sc11人类最终验收)。产品交互以[定时任务设计](../designs/scheduled-tasks.md)与[实施契约](schedule-contracts.md)为准；已批准的 P1–P6 不需重审。ADR-0037 继续保持 Proposed。

## 开始真实调用前必须由用户确定

缺少任一项时，只能完成本地预检和暂停态配置，不启用自动执行、不点「立即执行」、不做会触网/计费的模型连通性测试。

| 授权项 | 需要提供的值 |
| --- | --- |
| 模型 | 设置中已配置模型的显示名；不提供或记录 API Key、密钥和凭据内容 |
| 专家 | 实际验收的 Expert 名称与当前 Revision；如需比较多个 Expert，逐个指定 |
| 工作空间与资料 | 用户明确选定的 Workspace 和允许读取的目录/知识文档/集合；日志中只记脱敏标签、数量和容量，不复制正文或路径 |
| 验收任务 | 月度经营分析、周一调研、工作周报等实际样本、统计期间、时区、预期成果类型与人工判定要点 |
| 调用许可 | 允许执行的 occurrence 数，以及可接受的模型请求数/费用上限和测试窗口；说明模型连通性测试是否计入 |
| 运行方式 | 选择先做一次人工立即执行，或另外授权一次真实计划时刻触发；两种方式会创建不同 occurrence，不能在单次额度下都执行 |

Schedule 没有独立的累计费用/请求数熔断配置；一次 Run 也可能因工具调用产生多次模型请求。用户给出的限额必须由所选 Provider 的账户额度/外部限额落实，并把连通性测试计入授权。取消或失败不保证退回已发生的模型费用。没有可靠外部限额时，应先使用可封顶的模型账户并只批准一个低风险 occurrence。

## 本地预检

以下检查不调用真实模型：

1. 确认代码处于用户指定的 BetterWork 实例；启动/停止遵守[交接说明 §3](../11-qoder-handoff.md)，不对其他实例或用户数据做清理。
2. 确认 SC-M4 `npm run verify` 退出 0，应用库 schema v38、Knowledge Vault v7；离线 UI/进程恢复数据位于临时目录，不与真实验收 Workspace 混用。
3. 在「定时任务」创建一条**暂停**规则，核对 Workspace、固定 ExpertRevision、时区/周期/期间规则、工作要求、期望 Artifact 类型、成果子目录及知识范围。
4. 核对来源候选：只选择本次获准的 Workspace 目录和 Knowledge 项；确认目录预算（500 个文件、单文件 100 MiB、合计 500 MiB、深度 12）、实际清单上限 2,000 项和来源描述上限 50 项。确认不需要读取的个人/客户资料不在所选目录或集合内。
5. 检查界面预检返回的模型/凭据状态、Expert/Skill/MCP 授权、工具链和来源问题；任何 blocked/warning 或未知目录都先停在暂停态并记录原因。不要通过切换到教学模型或扩大资料范围来绕过阻塞。
6. 确认成果目录中已有文件和当前版本；保存采用新版本与非覆盖路径。准备一份不含密钥、正文和客户信息的证据记录。
7. 用户确认上述授权表后再启用或手动执行。若做真实计划触发，使用当前真实时钟与用户批准的时区，将下一次计划安排在可观察的短窗口；不改系统时钟、不注入测试时钟。应用需保持运行且电脑不休眠。

## 真实窗口操作与判定

每次只执行授权表中批准的 occurrence 数；模型调用或预算接近上限、发生资料越界/覆盖风险、结果意外时，立即暂停规则并使用既有停止入口，保留 Run/Occurrence 证据。

| 步骤 | 在真实窗口执行 | 通过时可观察到的事实 |
| --- | --- | --- |
| 1. 创建规则 | 侧栏进入「定时任务」→「新建定时任务」；选择已指定 Expert 与 Workspace，添加获准知识来源，填写期间、时区、要求和成果类型；先保存为暂停态 | 规则历史固定显示所选 ExpertRevision、来源范围、期间与时间；没有 Run 或 Provider 请求 |
| 2. 预检 | 查看并处理规则预检；核对模型显示名和能力阻塞，确认目录/集合边界及成本提示 | 有效时才允许显式启用；被撤销能力、丢失来源或不匹配 fingerprint 会阻止启动，不回落到其他专家/模型 |
| 3. 执行一个已授权 occurrence | 按授权选「立即执行」或等待唯一一次短窗口计划触发；观察任务历史和执行状态，不重复点击、不另造 request | 新 occurrence 关联独立 Task/Session 和固定来源快照；只对选定范围执行。后台完成不抢焦点、不清 Composer；每个 Run 进入 completed/failed/cancelled 等终态 |
| 4. 检查来源和成果 | 打开该期详情，核对实际读取/采用来源与期间；在成果页打开关联的 ArtifactVersion，并检查保存回执和新文件 | 本期实际 Run 和版本可追溯；成果保存到指定 Workspace 子目录、不覆盖已有文件。`generated` 只代表运行及登记/保存事实，不代表业务内容通过 |
| 5. 检查通知与接续 | 从消息中心/系统通知回看原 occurrence；从详情打开本期原 Task，继续修改或补料 | 同一结果只生成一个持久化通知；通知点击定位到稳定目标。人继续协作沿用原 Task/Session，人工修订形成新版本，不改写 Schedule 固定快照或早先产物 |
| 6. 评估周期质量 | 到下一真实期间后按同一业务口径重复授权与检查；对比来源版本、期间边界、结论和人工修订 | 只用自然发生的真实周期判断连续质量；不以注入时钟的六期离线旅程冒充真实连续业务结果 |

### 验收记录模板

每个 occurrence 单独记录以下脱敏事实；真实文档正文、客户名、绝对私人目录和凭据不写入仓库日志：

```text
日期 / BetterWork 版本或提交：
Schedule 名称（脱敏）：
Workspace 标签 / Expert Revision / 时区 / 统计期间：
触发方式（计划 / 立即 / missed 人工补做）：
获准来源类型与数量、快照状态：
Occurrence ID / Task ID / Session ID / Run ID（本地记录）：
Run 终态 / ArtifactVersion ID / 保存回执状态：
Provider 实际请求数与费用（按 Provider 用量页核对）：
通知可回看且未重复：是 / 否
业务人工判定：通过 / 有条件通过 / 不通过 / 尚待下一期
需要修复的问题、是否暂停后续规则：
光哥最终结论与日期：
```

只有光哥明确给出业务结论后才能更新 SC11 状态；部分期数、模型未授权或人工未审阅时保留 todo/doing，并记录缺口。自动化通过、AI 查看截图和真实业务通过必须分开陈述。

## 故障/取消的人工边界

- 暂停或归档只阻止未来自动执行；停止已开始 Run 是单独动作。若测试真实 Run 取消，也必须在授权请求数内执行。
- 错过的计划时刻只记为 missed，不自动补跑；用户可从原 missed 项明确发起人工补做。它沿用原期间、使用当前有效配置与新的来源快照，原记录不改写。
- Run 失败/启动中断不会自动重试 Provider。成果保存失败允许只重试保存到新路径，不重新调用模型；已有文件和早期 ArtifactVersion 应保持原样。
- 不要为验收故意篡改生产来源、撤销线上凭据、制造数据库/磁盘故障或强杀真实用户窗口。这些路径已在隔离合成数据与进程中验收。

## 已知限制

- 自动计划由本地 Main 进程运行；电脑休眠、应用退出或错过容许窗口时不补跑。应用恢复后可查看 missed 并由人决定是否补做。
- 来源清单在每期准备时固定；目录新文件/改写、知识修订或集合成员变更影响后续期，不改变旧期。人工补做使用现在可读的新快照，不保证还原当时网页或已删除文件。
- ExpertRevision 固定不代表模型文本、外部网页/MCP 状态、记忆和业务结论完全可复现。
- Scheduler 不设规则级总费用/请求预算；Run 按既有 Provider/Run 策略执行，成本需依赖 Provider 的账户限额与人工观察。
- 系统通知受 macOS 权限影响；通知中心与持久化历史是回看依据。应用自动生成和保存不构成专业或业务审核。
- 本地 Skill/工具若产生外部副作用，系统不承诺 exactly-once；不确定的副作用不会因恢复而自动重试。
