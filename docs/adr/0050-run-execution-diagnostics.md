# ADR-0050：Run 执行诊断与双来源事实投影

- 状态：Proposed。2026-10-16 用户接受[调研建议](../reviews/2026-10-16-agent-execution-tracing-analysis.md)，授权编制 GPT-6 Luna 开发卡；本次不构成产品代码开工、真实模型调用或发布授权。后续开发目标明确采用本文及实施契约时，可在其授权范围实施；不由 AI 自动改写 Accepted 状态。
- 日期：2026-10-16，来自本机 `date`。
- 关系：延续 ADR-0003 的 Core 边界、ADR-0005 的成果来源、ADR-0039 的任务分支与 ADR-0046/0049 的验证纪律；不替换已有 Run 终态、材料/记忆权限或 Skill 执行协议。
- 实施字段、口径和故障规则只定义于[执行追踪契约](../development/execution-tracing-contracts.md)；状态只记 [AT00–AT25 任务板](../development/tasks-execution-tracing.md)。

## 背景

算台已有有序 Run Journal、工具进度/结果、过程旁白和历史回看，但缺逐轮模型调用的完整持久记录。Provider 已解析的 usage 尚未进入主 Run 事件；准备、清理与脚本发布阶段也缺统一诊断投影。

AgentScope 2.0 的类型化生命周期和历史/实时交接可借鉴；Studio 的调用树/详情查询可借鉴。二者不作为运行依赖，不替换本项目引擎，不移入 Python 服务、Redis、通用 middleware 或多 Agent。

## 提议决策

1. **沿用 Core 有序事件。** Core 增加模型调用生命周期与工具关联，仍由现有生成器分配 AgentRuntimeEvent.sequence。Main wrapper 不并行向该序列插入事件；已有终态恢复的下一序号机制保留。
2. **宿主诊断使用单独事实流。** 准备、审计、清理、脚本校验/发布等事实由 Main 的 Run 诊断记录器写入同一应用 SQLite 的 `run_diagnostic_events`，使用独立 `diagnosticSequence` 和 operationId。它只记录 Core Journal 尚未拥有的宿主边界，不复制每个模型/工具事件，不拥有业务终态。该选择避免为观察功能重写整个 Core 定序协议。
3. **查询时构造一条执行链。** 以 runId、modelCallId、toolCallId、executionId、operationId 和精确修订关系联查，形成只读节点/时间轴。两个序列不拼成伪造的全局因果顺序；调用关系来自显式关联，横向位置来自有口径的时间数据。Span 是诊断概念，不是领域 Step 或恢复节点。
4. **最终结果由 Application 决定。** Core 候选成功后仍需审计、Skill/MCP 清理、最终取消裁决和成果提交；诊断根节点读取持久 Run 终态。失败的局部工具不自动把成功 Run 改为失败；未闭合记录不补造成成功。
5. **最小内容采集。** 新增模型/宿主诊断只保存白名单元数据、必要错误类别、摘要哈希和来源引用。既有消息/工具载荷继续由原入口管理；不把它们整体复制到新诊断流或导出文件，不展示私有推理。
6. **观测故障分层处理。** Core Journal 和授权审计的写入失败保留当前失败语义；新增可选宿主观测与后续 exporter 的故障不得改变已执行的业务结果，必须留下可解释的缺失/错误读数与安全宿主日志。无法记录时展示未知，不承诺诊断完整。
7. **先本地交付，再选配互操作。** AT01–AT22 交付离线可验证的原生诊断、统计和问题样本基础；真实 UI/模型另验。OTLP exporter 是 AT25 的独立可选范围，不是前置依赖；完整请求捕获、自动修改 Expert/Skill/Memory、自动付费重跑均不在范围。

## 否决的替代方案

- Core、Provider wrapper 与 Main 各写同一 sequence：与现有唯一约束和事件顺序冲突。
- 直接重写所有事件为全局 EventEmitter/总线：扩大变更与取消语义风险，违反现有 Core 协议。
- 只在 Renderer 记录耗时：重启后丢失事实，也看不到无窗口运行与宿主收口。
- 只接入 OTel 后端：先增加服务依赖仍无法补回没有采集的数据，也不能承担 Run 业务状态。
- 新建所有模型/工具的第二份 Span 真相表：与 Journal 形成重复状态；统计缓存如后续有必要，应明确可重建及失效规则。

## 影响与验证

- 需要扩展共享 Zod/DTO、Core 模型事件、Main 查询/宿主记录、IPC/Preload 和工作页详情；新增表必须使用连续版本迁移，不固定未来迁移号，不回填未知历史。
- 第一阶段只有 Core 模型/工具链路，暂不为宿主阶段追加表；后续卡再加入宿主事实流。
- 历史记录保留可证明的信息；旧 Run 的逐轮模型用量/时间显示未记录，用户数据不重置。
- 验证覆盖正常、tool-only、拒绝参数、流中断、取消、清理失败、候选成功后取消、历史/实时交接、重装配与启动中断收口。全部先使用 Fake Provider、注入时钟和临时 SQLite；具体矩阵见契约与任务板。
