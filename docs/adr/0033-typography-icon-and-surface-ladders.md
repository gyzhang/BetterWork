# ADR-0033：排版、图标与表面档位（批次②）

- 状态：Accepted（2026-10-01，按光哥对六条新轴档位表「确认照单采纳」的拍板实施；同日接受「页面标题 20px」与「批次顺序 ①→②→③」）。
- 日期：2026-10-01。
- 依据：[UI/UX 体系 §9.7／§9.10／§9.13](../10-ui-ux-system.md)、[ADR-0031](0031-button-base-and-skin-closure.md) 的「唯一出口」判据、[ADR-0032](0032-catalog-entry-card-facts.md) 的「一份事实、两种排布」，以及 2026-10-01 的全仓家底核查（起因是技能页与专家页页头按钮不一样大）。
- 关系：**不替代** ADR-0031／0032，也不改 [§9.10](../10-ui-ux-system.md) 的控件几何档位。它把 ADR-0031 用在同一张高度表上的做法推到另外六条轴上，并**取代** §9.7 里那张与代码不符的推荐字号层级表（该表同日撤销）。

## 背景

2026-10-01 的核查把「按钮为什么不一样大」追到三条根因，其中第二条不是执行问题而是**规范缺件**：高度、内距、圆角、gap 四条轴有档位表并被遵守，而**字号、行高、表面内距、图标尺寸、标记方块、输入框几何六条轴从来没有档位表**。没有表就谈不上遵循，于是同一件事在每个表面各被记了一遍。当轮实测（`styles.css` 与生产 TSX，逐条取证）：

| 轴 | 实测家底 | 形状 |
| --- | --- | --- |
| 字号 | 171 条声明／14 种取值 | 12px 111 条、13px 36 条是绝对多数，另有 9／10／14／15／16／18／20／21／22／24／28 各散在各表面 |
| 行高 | 65 条声明／10 种取值 | 1.4／1.45／1.5／1.55／1.6／1.65／1.7／1.8／1.35／1 —— 相邻两档差 0.05，肉眼读不出，评审要逐条判 |
| 表面内距 | 27 件独立表面 | 12px／13px／14px／11px 12px／13px 15px／10px 11px／25px／32px／40px 各写一遍；`.modal-panel` 本体 24px 而它的 sheet 变体 25px |
| 图标字形 | 50 个调用点／9 种数字 | 12／13／14／15／16／17／18／10 并存，`NavList` 画 15px 而它的 CSS 槽宽 16px |
| 标记方块 | 10 种边长（22／24／28／30／32／34／36／38／40／54px） | 其中 30／32／34／36 是同一类「图标底座方块」，差的 2–6px 没有任何设计含义 |
| 输入框几何 | 37 个 `input` ＋ 13 个 `textarea` | 只有零星几处写了 `min-height`，字号 12／13／14 混用，且全部游离在动作排门禁之外（`rowControlOf` 认不出原生输入控件） |

同时，§9.7 自己就是**第二份档位表**：它推荐「12／14／15–16／20／28」，而代码真正承载正文与控件的是 13px；它还写着「落地现状：字号层级已全面达标」。一份与代码不符、又盖了达标章的规范，比没有规范更糟——它让所有人以为这件事已经有尺了。

另一处已经付过代价的对比来自 ADR-0031：按钮的 `size` 之所以稳，是因为**档位写进了类型**，不依赖任何人记得选对数。本记录把同一手段用在剩下五条轴上。

## 决策

1. **档位表只有一张，住在 [docs/10 §9.13](../10-ui-ux-system.md)**，六条轴各一档表；§9.7 的推荐层级表与「正文基线 14–15px」同日撤销，§9.7 只保留字体族、展示字体的唯一位置与 12px 下限。
2. **字号六档、行高四档，全部 Token 化**：`--font-size-caption/body/emphasis/heading/page/hero`（12／13／15／18／20／28px）与 `--line-height-tight/normal/body/loose`（1.4／1.5／1.6／1.7）。171 条 `font-size` 里的 163 条、65 条 `line-height` 里的 63 条一次性换成 `var(--…)`（其余按决策 8 登记为例外）；调某一档今后只改 `:root` 一行。
3. **区块标题取 18px，21px 出局**。页面标题已由光哥定为 20px，再留 21px 等于同时供着只差 1px 的两个档，而且版心里的小节会喊得比自己所在的页面响。层级由「页头带／版心内」与字重承担，不由 1px 承担。
4. **图标档位是类型不是数字**：`icons.tsx` 导出 `ICON_SIZES`，`IconProps['size']` 收敛为 `IconSize = 12｜13｜16｜18`，省略即 16。写 `size={14}` 是编译错误。`IconButton` 的 `GLYPH_SIZE` 改为引用 `ICON_SIZES`（`md` 那档 14 → 13，与它服务的按钮文字同档）；`ComponentType<{ size?: number }>` 的四处透传（`NavList` 两处、`SourceRow`、`IconButton`、`workspaceIcons`）同步换成 `IconSize`，让类型链没有缺口。
5. **标记方块三档**：`--mark-row` 24／`--mark-card` 32／`--mark-hero` 40。30／34／36／28 一类边长并入最近的档，`.error-page-icon` 32 → 40 是唯一一处「整页占位」与「卡片标记」的分界修正；`.notification-list` 行前方块本就 24px，也换成 Token——裸值恰好等于档位值仍然算脱档，因为调那一档时它不会跟着走。控件几何（`.switch-track`）、外观预览（54／38px）、窗口拖拽带与品牌算珠标／字标容器不属这条轴，按理由登记为不测对象。
6. **表面内距四档只管「一块独立表面的内缩」**：卡片档**沿用 §9.8 已有的 `--card-padding`（12px 16px），不另起别名**——两个名字指同一份几何正是这张表要消的东西；新增 `--surface-padding-panel`（16px）／`-modal`（24px）／`-page`（28px 0 48px）。27 件表面迁移，含 `.modal-panel[data-variant='sheet']` 25 → 24、`.empty-page` 40 → 24、`.loading-page,.error-page` 32 → 24、`.message p` 13px 15px → 12px 16px、`.toast` 11px 12px → 12px 16px。**定宽列的段落内缩**（`.context-section`／`.brief-panel`／`.activity-list`）已由 §9.8 与 `components/ContextPanel.test.tsx` 的 `INSET_OWNERS` 钉住，本记录不动它——一处有测试钉着的清单不该被另一条轴的批量迁移顺手改掉。
7. **成果文档正文不吃应用字号档位**：`.markdown-preview` 的 22px／对话内预览 24px 保留为登记例外（§9.6 已规定应用主题不得改 Artifact 的配色，同理不替它重定字号）；它的行高 1.8 并入 `loose` 1.7，因为行高是排版而不是文档语义。
8. **例外只降不升、且必须写理由**：图形化标识（品牌字标 16px 与其 10px 副标、格式徽标 10／9px、未读数徽标 10px）与两处绝对定位微标的 `line-height: 1` 共 10 条声明，逐条登记在护栏的 `TYPE_LADDER_EXEMPTIONS`。§9.7 的「不得用小于 12px 承载产品信息」不变——这些全是徽标。
9. **每条轴配一支护栏**（`standards/coding-standard.test.ts`「排版与图标档位纪律」）：字号档位、行高档位、图标档位（含 `ICON_SIZES` ↔ `IconSize` ↔ `GLYPH_SIZE` 三处一致性）、标记方块三档、表面内距清单 ↔ `:root` 档位表双向比对。**规矩写在槽位与档位上，不写在组件名上**，与 ADR-0031／0032 同一判据。
10. **输入框几何归批次③**：本记录只登记档位口径（与 §9.10 的 `--control-height-*` × `--control-padding-*` 成对使用），实现是 `TextField` 基座收编 37 个 `input` ＋ 13 个 `textarea`；落地后输入控件才开始被动作排门禁计数。**同日落地**：批次③于同日做完，实现与实测家底记在 [ADR-0034](0034-input-control-base.md)（41 处迁入基座、基座之外那 30 条规则收到 6 条、`rowControlOf` 已认得 `TextField`），本条的判断与措辞不改写。

## 后果

- **可见变化**：区块标题 21 → 18px（唯一一处能被读出来的字号变化）；整页错误图标 32 → 40px；消息气泡与 Toast 内距上卡片档；抽屉内距 25 → 24px；图标按钮 `md` 的字形 14 → 13px。其余都是 ≤2px 或肉眼不可辨的并档。待光哥在真实界面回看。
- **一次性 diff 大**：273 条声明（163 字号 ＋ 63 行高 ＋ 20 方块 ＋ 27 表面内距，全部按护栏同一口径实测）＋ 11 个 TSX 调用点 ＋ 6 处类型透传。这正是批次②「改动最大、一次性」的预定形状——分小批做，每批都会留下两套并存的状态。
- **`parsePixels` 判不了 Token**：护栏里读像素值的断言必须能回查档位 Token 的定义，否则「老实用了档位」会被判成「没写」，反过来逼代码退回裸值。本批次补了 `resolvePixels()` 并把 `<small>` 基线那条断言改到它上面。
- **规范自身从此可被机器比对**：§9.7 那次「文档 20px、代码 19px、还盖了达标章」的失真，由「档位表 ↔ 代码」比对与撤掉整节盖章这两件事共同堵住。
- **不做的事**：不为了 Token 化去动 `@media` 里的响应式数值与外观预览色板；不把 `--text-*`（颜色）与 `--font-size-*`（尺寸）混进一个前缀——同前缀两种量纲会让人读错。

## 验证

护栏五条全部做过变异验证（探针值即本轮迁移前的真实裸值）：字号 `21px`／行高 `1.55`／图标 `size={14}`／方块 `34px`／表面 `25px` 各打红一次，还原后复绿。第六条探针验的是**档位表封闭**：在 `:root` 另立一档 `--font-size-mini: 11px` 与一个别名 `--surface-padding-card`，字号与表面内距两道门同时报红——给同一份几何起第二个名字，正是这张表要消的对象。护栏用例由 108 增至 113。全量 `npm run verify` 结果见 [2026-10-01 工作日志](../logs/2026-10-01.md)。
