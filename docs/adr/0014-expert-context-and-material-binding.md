# ADR-0014：专家、任务准备与运行材料快照

- 状态：Accepted（2026-09-14 用户通过设计 v0.2 评审）。E11–E15 已落地专家持久化、执行注入、召唤对话、配置 UI 与内置分发；E20 已定案材料、快照和来源契约，E21–E25 已落地；E30 的记忆治理由 [ADR-0015](0015-memory-scope-and-governance.md) 细化，见[开发计划](../development/tasks-experts.md)。
- 日期：2026-09-13。
- 2026-09-14 交互修正已确认：专家页“召唤”直接进入对话，缺少业务材料通过对话补充；TaskContextRevision 是宿主保存的对话草稿配置，不要求独立任务准备页。本文关系决策随用户对 v0.2 的整体评审通过而接受；具体实施技术由任务卡落实。
- 依据：[专家与任务材料设计](../designs/experts-and-task-materials.md)。
- 关系：扩展 ADR-0008 的配置化专家、ADR-0012 的显式 Run 能力绑定；补充 ADR-0005 的成果来源关系。保留 ADR-0003 的核心边界与 ADR-0011 的信任规则。

## 背景

用户要求专家用选定知识、历史成果、本期文件和外部资料完成重复工作，并在下一期复用。仅增加 expertId 和系统提示词不足以保证材料范围、历史版本、记忆适用性与成果来源可追溯。

现有 RunService 从此前完成 Run 重建用户输入与助手回复；只从工具清单移除材料不能排除它在旧回复中的内容。现有本地知识刷新可更新内容，单独记录知识 ID 无法重现运行时版本。现有 PPT 预览也不等于 PPT 内容读取。

## 决策

1. 专家为版本化配置，不创建独立 Agent 引擎。通用助手是无专家绑定的工作模式，使用同一运行协议。
2. 一个 Task 在首次执行后固定执行者身份。换专家创建新 Task/Session，显式选取要沿用的材料与目标，不带入旧专家的完整消息与私有记忆。
3. 引入 TaskContextRevision 保存下一次运行的可见准备状态，包括专家修订、输入参数、材料选择、能力草稿与上下文段。它不授予执行权；启动必须显式提交修订引用，并原子核对期望版本。
4. Run 的 Skill 绑定继续使用现有 run_skill_bindings，遵守数量、顺序、启用、信任与依赖校验，不走专家专属旁路。第 3 条扩展 ADR-0012 中只由最近 Run 推导任务选择的策略，避免无历史 Run 的新任务丢失材料准备；此变更不覆盖旧 ADR 的已实现事实。
5. 材料采用类型化引用：Knowledge 内容修订、ArtifactVersion、本地输入快照；用途与来源类型独立。候选、选择、读取和成果输入关系分别记录。网页由运行工具发现后登记来源。所有私有材料通过显式清单控制，不将 Workspace 目录等同于读取全部文件的许可。字段、跨空间选择、恢复和入口校验见[材料、快照与运行来源契约](../development/material-contracts.md)。
6. 运行准备阶段对文件和知识生成不可变内容引用；文件存于受管目录、哈希去重，SQLite 保存真相记录。快照准备可取消；失败不得留下半个 Run，孤立制品可恢复清理。具体版本化迁移与跨文件/数据库恢复任务在实现卡中设计。
7. 实际 RunContextSnapshot 固定专家、材料、工具、模型配置引用与记忆适用范围。动态按需读取的记忆须固定记录修订并记录读取足迹，不将可变当前记忆反复注入运行。实时撤销始终优先于快照。
8. Application 在工具装配、调用、检索与文件读取边界实施范围；Agent Core 仅收到解析后的配置。范围不是提示词约定，也不声称是原生进程沙箱。脚本继续受 ADR-0011 的本机用户权限限制说明约束。
9. 任务缩减材料或记忆范围时切换上下文段，之后不重放旧段助手回复；保留用户确认的目标和明确选择的成果。历史 UI 与审计保留，不声称移除可以撤回已发送内容。原始历史永远不作为权限继承依据。
10. 记忆以 User、Workspace、Expert 及同时限定 Expert/Workspace 的适用关系筛选；仅有效 confirmed 可用，内容作为有来源的上下文，不得获得系统指令权限。SQLite 负责修订状态，Markdown 投影可重建；双向编辑与恢复细节另立记忆实现 ADR。
11. 分别记录选择材料、实际读取片段、输出来源关联。新 ArtifactVersion 可关联输入 ArtifactVersion；该关系不自动把上期所有 Evidence 伪装为本期已读取来源，也不宣称已有逐句 Citation。
12. MCP 连接由宿主管理，专家/任务绑定具体工具，新增工具不自动获准。传输、认证、连接生命周期、取消和工具 ID 映射在独立 MCP ADR 中落实，不以占位字段作为完成。
13. 讨论节点持久化在 Task，保存审阅材料版本和下一步。暂停讨论时当前 Run 结束；继续/返工创建新 Run，首版不引入 run.waiting 或通用 DAG。
14. 召唤只进入专家对话草稿，用户发送后创建 Run；材料清单可为空以完成理解与澄清，所需业务输入约束依赖它的动作。执行依赖、授权、修订与现有绑定校验仍在发送边界生效。系统预检和快照不产生独立的配置向导或强制工作依据预览。

## 备选方案与取舍

| 方案 | 不采用的原因 |
| --- | --- |
| 专家直接读取整个知识库和目录 | 违背按任务选材，并使跨项目上下文混用 |
| 所有规则、资料、历史成果塞进专家提示词 | 无法独立追踪版本、选择范围与本期事实，且易超上下文预算 |
| 每个专家复制一套知识与工具安装 | 增加重复维护，不能表达共享引用和统一连接状态 |
| 只记录路径/文档 ID，运行时始终读最新 | 外部修改后无法解释旧成果依据 |
| 移除材料仅修改工具白名单 | 旧助手消息仍可能包含材料内容 |
| 一条 Session 包含所有月份 | 本期事实与历史结论难分，且逐期选择不可审计 |

## 结果与实施前置

代价是需要专家修订、任务草稿、来源修订、运行快照、上下文段与成果输入关系的版本化迁移，并为文件快照增加恢复与存储回收策略。收益是能力、材料、记忆和成果复用遵循同一条可解释的运行链路。

实现前按 E1–E5 拆为独立任务卡，先定义共享 Zod 协议、迁移与失败/取消语义。PPTX/XLSX 输入处理、记忆实现、MCP 和讨论节点均需明确验收；本 ADR 已接受，不能据此声称任何功能已落地。具体任务、前置与证据门槛以[开发计划](../development/tasks-experts.md)为准。
