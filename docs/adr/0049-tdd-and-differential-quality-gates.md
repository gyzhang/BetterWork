# ADR-0049：测试先行证据与差异质量门禁

- 状态：Accepted（2026-10-14 用户下达“改进，全面改进”，授权落实本轮 TDD 与门禁评估中的工程改进）。
- 日期：2026-10-14；时间来自本机 date。
- 关系：补充 ADR-0046 的日常代码检查，保留其手动/夜间 UI 分工和 ADR-0039 的合并保护；不扩大产品能力或真实模型授权。

## 决策

1. 新增领域行为与缺陷修复先写最小行为反例，确认预期失败后实现，再记录绿跑及重构回归。特征测试和已有实现补测如实标记，不伪造失败。证据记入现有任务日志，工程规范仍是唯一标准。
2. 日常相关测试补充动态消费者映射：内置 Skill/Expert 资源、依赖锁、子进程入口、检查脚本与迁移必须执行对应行为测试。UI 夹具变化记录需要专项 UI 验证，日常只执行不启动 Electron 的逻辑回归，遵守 ADR-0046。
3. 代码快检复用已选择的行为测试收集覆盖率，functional 后接 heavy，保留重档串行；多次调用按执行行的命中并集合并。新增/修改的可执行生产 TypeScript 行整体覆盖至少 80%，恰好 80% 通过。缺报告、损坏报告和应纳入却缺失的文件失败。删除行、纯类型、测试及合成夹具不计入分母；明确的宿主启动/纯视觉入口例外在覆盖率配置逐项说明，不对业务文件整类豁免。
4. 完整覆盖率入口复用同一 Vitest 配置和档位；覆盖率不代表独立 Electron/安装态的执行证据。CI 保存测试、差异覆盖和检查计划，并记录 base/head、选中的路径和失败阶段，避免只留下一个绿灯。
5. pre-commit 拒绝本次检查路径的部分暂存状态，防止工作树的修正替暂存版本通过。其他路径未暂存不影响聚焦提交，不使用自动 stash 或修改用户内容。
6. 进程恢复夹具只对仍由本次运行持有且未成功终止的进程组发送强杀；已退出或已经成功发送强杀后不再重复发送。权限拒绝继续失败，超时和清理失败均由 Promise 收口，并保留阶段诊断及原始失败。
7. IPC 编译器契约在独立 Node 进程运行相同的 15 个正例与 17 个反例，父测试核对退出状态、信号和用例数，保留原 20 秒上限。全量 V8 采样下原夹具超过上限，限制 worker 和重档串行仍不能解决；用户明确选择独立进程方案，不以提高超时或删除断言解决。

无执行语句的纯类型及声明性 import/export 转发模块不计执行行；这是语义判定，不恢复按文件名豁免 index。代码快检仍对其执行格式、类型与相关行为测试。

## 验证与边界

- 行覆盖算法验证命中并集、删除/重命名/未跟踪文件、80% 边界、缺失/损坏报告及纯类型排除；不能以未运行测试或旧报告通过。
- 部分暂存、动态资源、脚本消费者和已退出进程重复清理先以隔离反例证明原实现失败，再验证修复。
- 不提高夜间调度准时保证，不以环境权限错误推导产品缺陷；历史 EPERM 归因与可证明的重复清理缺陷分别交接。
- 完整 verify、真实 UI、真实模型、提交/推送及发布继续按已有独立授权规则执行。
