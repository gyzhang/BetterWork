# ADR-0051：模型配置支持多个角色

- **状态**：Accepted（2026-10-16 用户人工验收通过）
- **背景**：[UI/UX 体系 §7.5、§11.4](../10-ui-ux-system.md) 已允许同一模型承担多个角色；旧实现却在协议和 `model_profiles` 中只保存一个角色。多模态模型（例如 DeepSeek 4.1）需要同时用于语言与视觉配置。
- **相关记录**：[系统架构 §9](../03-system-architecture.md#9-模型提供层)、[知识与记忆 §10](../04-knowledge-and-memory.md#10-模型角色)、[路线图](../07-mvp-and-roadmap.md#模型配置支持多角色)。

## 决策

1. 一个 ModelProfile 至少选择一个、最多选择全部三个已落地角色：`language`、`vision`、`embedding`；重复项无效。
2. 角色关系与默认顺序存入 `model_profile_roles(profile_id, role, priority)`。每个角色各自排序和设默认；同一配置可以成为不同角色的默认配置。
3. 数据库迁移 v47 从旧 `model_profiles.role` 与 `priority` 复制现有配置，角色和顺序保持不变。旧标量列留作兼容快照；新查询以角色关系表为准。
4. Provider、语言执行、视觉配置、嵌入索引和知识设置按角色集合检查资格。修改/关闭配置仍作用于同一个 ModelProfile。
5. 连通测试按所选角色执行：语言和视觉共用一次 Chat Completions 请求；嵌入角色另执行 Embeddings 请求。只选视觉仍是聊天端点连通测试，不表示已验证图像理解能力。
6. Renderer 的角色筛选显示所有包含所选角色的模型；每个角色的默认状态和默认操作相互独立。

## 取舍

- 角色优先级独立存储，避免一个全局优先级无法同时表达多个角色的默认顺序。
- 不复制模型配置来模拟多角色，避免 Provider、Endpoint、凭据和模型参数在用户编辑时分叉。
- 本决定只扩展配置分类与默认选择，不新增视觉请求协议、图像输入或 Agent 视觉执行链路。

## 验证与边界

- 协议限制角色集合非空、唯一；默认请求显式携带角色。
- v47 迁移应验证旧数据保留、角色优先级映射和外键完整性。
- 保存、编辑、默认选择和删除均需覆盖角色关系的持久化与隔离。
- 连通测试必须覆盖聊天与嵌入端点各一次，并确认密钥不进入错误消息。
- 人工验收应确认编辑器可多选、至少保留一个角色、角色筛选和每角色默认操作清晰。
