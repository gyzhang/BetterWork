# ADR-0011：Skill 信任授权与本地目录分发

- 状态：Accepted（产品规则；实现尚未落地）
- 日期：2026-09-08
- 背景：用户认可受信任 Skill 在授权范围内默认执行，以及源码/安装包/用户三个本地目录的分发与管理方式，要求完善文档。
- 关系：落实 ADR-0008/0009 的内置分发与脚本支持要求；确认 ADR-0010 中信任及目录相关产品规则，不将其余执行技术提案整体转为 Accepted。

## 决策

1. Skill 配置提供「受信任」选项。信任有效时，已授权范围内的脚本和必要子进程无需逐次审批；超时、取消、日志、质量门与成果版本继续生效。
2. 产品审查并随包分发的内置 Skill 默认信任。用户导入 Skill 提供明确的信任选项；导入和查看不会执行代码。包自称 builtin/trusted 不能获得默认授权。
3. 信任、启用与依赖就绪独立；停用项不可执行，缺依赖项不可显示可运行。用户可以撤销信任。
4. 信任绑定实际内容、依赖及范围，更新后发生变化时展示差异并重新确认。产品已审查的内置新版本可获得发布默认策略，但用户停用或撤销选择持续优先。
5. 信任不扩大对源文件覆盖、新依赖安装、外部发送和新增访问范围的授权。本地原生脚本仍具有当前用户权限，不承诺恶意代码文件/网络沙箱。
6. 源码使用 `resources/skills/`，安装包携带 `skills/` 资源目录，用户数据目录 `skills/` 保存导入、自建及用户副本。Skill 保留完整指令、脚本与资源结构。
7. 内置资源只读使用，修改通过用户副本，产品升级不覆盖个人修改。共享 Python/依赖/工具链可以单独分发，避免重复打包。
8. 公司模板等私有资产默认留在本地；加入特定分发包由用户明确选择。信任授权及 API Key 不随 Skill 包导出，接收端独立判断信任。

## 设计落实

[执行器设计](../designs/skill-executor-and-dependencies.md) §5.1 和 §7 补充目录发现、内容核验、升级、授权状态与撤销收口。拟用修订/范围指纹登记授权，启停或撤销与新进程启动串行裁决；撤销后停止相关活跃脚本并保留成果。

具体数据库列、IPC 名称、OS helper 与 Python 制品仍按 ADR-0010 的提案推进，不在本次产品确认中视为已验证技术方案。

## 验收要求

- 内置默认信任、导入显式信任、禁用不执行、撤销后不启动新脚本并清理活跃执行。
- 内容或依赖变更不继承旧授权；伪造内置来源不获信任；用户撤销不被升级覆盖。
- 完整目录可分发，安装位置不依赖开发机路径，用户副本不被升级覆盖。
- 导出不携带授权或密钥，公司资产不会自动进入公开包。

本轮仅文档修订，尚未创建运行目录、复制 Skill 或实现上述功能。
