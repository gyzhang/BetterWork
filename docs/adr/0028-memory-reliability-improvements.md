# ADR-0028：记忆来源可靠性与显式优先召回

- 日期：2026-09-25
- 状态：Proposed（ADR 正式接受状态未变）；光哥已批准 Spec 的 D1–D5 推荐方案，不改变 ADR-0026 的状态，不构成开工、真实模型调用或提交发布授权。
- 产品：[记忆改进 Spec](../designs/memory-improvements.md)
- 实施真相源：[记忆契约 §11](../development/memory-contracts.md#11-mi-改进契约proposed)
- 推进：[MI00–MI10](../development/tasks-memory-improvements.md)

## 背景

现有记忆确认、作用域和修订治理可复用，但回答捕获没有保留来源，手工来源解析缺少完整依赖，任务排除的恢复入口依附入选列表。确定性词面召回不能保证明确工作要求在不同问法下出现。严格历史依赖保护撤销，却缺少换期恢复引导。

## 决策提案

1. 来源捕获由 Main 校验真实最终事件与完整依赖；Renderer 只提供选择器。来源未知不得转换为空依赖。普通确认与显式自主重述保持两条路径，历史错误 manual 不自动猜测修复。
2. 已排除列表直接投影持久化 TaskContext，使用范围受限的只读 IPC；修改仍走原 TaskContext CAS 保存，不新增排除表。
3. 记忆修订新增 `recallPolicy`，默认 `relevant`，显式 `pinned` 只用于可证明的自主规则。新运行采用 `memory-recall-v2` 的优先池、偏好池、相关池；安全过滤、总预算及冲突组原子性保持。具体字段、值、排序和上限仅由契约 §11 定义。
4. 保留 v1 历史快照的准确解析，不批量重算历史。策略变动追加记忆修订，继续沿用修订变化使依赖历史待复核的保守语义。
5. 冲突仍为提示可能性，补足来源与条件展示，不增加语义模型判定；换期通过显式选材、精确成果引用及自主方法重述恢复，不复活不安全历史。
6. 技术装配、真实 UI、真实模型工作收益分开验收。应用使用哪个模型仍由既有配置决定，与编码智能体选择无关。

## 替代方案

- 只给回答表单加 sourceSelector：否决；Main 目前还可能漏记依赖或接受非最终事件。
- 对所有偏好/约束自动置顶：否决；用户未选择重要性，且会挤占预算、放大误用。
- 立即把知识向量检索复用到记忆：暂不采用；仍需独立的记忆授权与治理设计，不能解决来源和可逆性缺陷。
- 召回前调用模型扩写查询/判断冲突：暂不采用；引入额外网络、费用和不确定性，本增量先做可解释闭环。
- 新建固定规则表：不采用；本期沿用修订审计，接受策略修改可能截断历史的代价，避免双真相源。
- 默认忽略旧依赖以维持连续对话：否决；会绕过删除、排除及材料撤销。

## 影响与兼容

新增一批版本化记忆列迁移，不预占应用库版本号；新增只读排除查询、精确成果版本来源执行器查询与少量 DTO 增量，不公开完整运行快照，不新增模型接口、数据库种类或通用权限。来源专家身份取自历史快照，新任务仍使用经确认的当前配置，不复活旧授权。不修改旧迁移与历史请求阶段，不改变 Knowledge 算法，不替代 WM16。
