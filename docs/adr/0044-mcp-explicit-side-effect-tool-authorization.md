# ADR-0044：MCP 有副作用工具的显式用户授权

- 状态：Accepted（2026-10-09；用户明确指出，愿意自行承担后果时也应能使用写入/破坏性工具，并授权按此调整产品行为）。
- 延续：[ADR-0016](0016-mcp-transport-and-lifecycle.md) 的 MCP 工具身份与生命周期、[ADR-0043](0043-mcp-multi-transport-and-oauth.md) 的多传输与 Run-owned client。
- 替代范围：前述决策及 [capability-contracts](../development/capability-contracts.md) 中“写入/破坏性工具不可用”的限制；其他连接、凭据、网络、运行隔离与来源边界保持不变。

## 背景

当前实现把服务标记为非只读或破坏性的工具在界面、持久化审阅和 Run 装配三处一律拒绝。用户指出，即使明确愿意承担后果也不应被应用永久禁止。MCP 的工具声明和描述确实不能证明行为，但这不足以替用户作决定；权限边界应由明确、可追溯的用户授权表达。

## 决策

1. 新发现或合同变化的工具默认未允许、未选择。用户可以逐项允许当前精确合同；服务声明为只读的工具可使用现有批量动作。
2. 服务标记为 `readOnlyHint: false` 或 `destructiveHint: true` 的工具可逐项允许；设置页另外提供一次批量允许这些有副作用工具的动作，并在执行授权前显示单独确认框、工具名和数量。
3. 允许提示说明助手在之后选用该工具的 Run 中可以直接调用，不会每次调用前再弹确认；工具可能创建、修改或删除 MCP 服务可触达的数据，服务描述和 annotations 不构成安全保证，远端副作用未必能撤回。
4. 没有说明读写性质的工具不参加批量允许，必须查看工具说明、输入/输出 Schema 和 annotations 后逐项决定。
5. 每项授权仍保存为精确的连接修订、工具 ID、合同 hash 与审阅时间。合同任何语义变化仍要求重新允许；新授权不自动启用连接或选择专家/任务工具。
6. IPC 请求字段用 `userConfirmed` 表达用户动作，不再假定每个 MCP 工具都是只读。主进程仍校验连接修订、目录新鲜度、工具身份与合同 hash；Run 只执行已绑定且仍有效的审阅记录。
7. 所有其他风险边界保持原样：服务运行权限由 MCP server 本身决定；stdio 工作目录不是 OS 进程沙箱；HTTP 目的地与凭据校验不因工具授权放宽；失败不自动重放不确定的业务调用。

## 取舍

永久封禁把产品政策强加给用户；完全按发现结果自动信任又会让服务端内容扩展权限。本决策采用用户明确授权的中间路径。批量授权会覆盖所列的整组风险工具，因此必须和只读批量操作分开确认。逐次审批需要新的运行时等待、取消与恢复协议，当前没有这一套能力，也不是用户提出的使用方式。

## 兼容与验收

无需数据库迁移：现有 review 表已经按 revision/tool/hash 存授权。共享 IPC Schema 将 `readOnlyConfirmed` 改为 `userConfirmed`，持久化记录形状不变。人工验收分别检查单项允许、高风险批量确认取消/完成、合同变更后需要重新允许、连接停用和专家/任务选择仍独立；本决策不代表已对真实业务服务调用过写入工具。
