## 背景

ADR-0015 与 E30–E32 已经交付可用的最小记忆闭环：SQLite 修订化存储、四种作用域、candidate/confirmed 状态、有效期、Markdown 只读投影、运行注入预算和管理界面。产品北极星要求的是「让下一次工作继承已确认的工作积累」，而当前实现做不到其中最重要的一步——**按任务相关性召回**，因此记忆在实际交付中近似于「按范围和时间取前 N 条」。

静态核查同时暴露三类无法靠小修解决的边界问题（详见设计文档 §2.2）：来源 `sourceId`/`sourceLocator` 是自由字段，不能证明归属与当前可访问性；`run_memory_reads` 在模型准备前写入，被当成「模型已收到」；历史重放只处理材料严格子集缩小，遗漏记忆删除/过期/排除与材料替换。此外记忆写 IPC 存在 `{ memory: Promise }` 的异步收口缺陷。

本 ADR 要固化的是**边界与真相源归属**，不是提示词或界面细节。

## 决策

### 1. 保留 SQLite 记忆修订为唯一真相源

`MemoryRecord` 的内容修订仍是唯一事实。Markdown 只读投影不参与运行读取，模型永远不从投影读取。投影在数据库提交之后重建，因此投影失败是「已提交成功 + 可见警告」，不得再被报告成保存失败（契约 §5.6）。

### 2. 保留四作用域与 kind，新增治理维度

`user` / `workspace` / `expert` / `expert-workspace` 四种作用域与 `semantic` / `episodic` / `procedural` / `preference` 四种 kind 不变。新增的是细分类 facet、结构化来源 `provenance`、幂等操作回执与审计、跨记录替代关系 `replacesRevisionId`（与既有、指向本身份上一修订的 `supersedesId` 严格区分）。字段定义只在契约 §5.2–§5.3 出现一次。

### 3. 自动提炼是 Main 层无工具单轮作业

模型提炼复用现有模型 profiles、默认模型解析与 Main 的凭据访问，不新增模型设置分区、不新增 Agent 引擎、不给提炼作业任何工具。Agent Core 不导入数据库。提炼走 `requireConfiguredLanguageModel` 语义，禁止生产 FakeProvider 回退（契约 §7.1）。

### 4. 首期在 SQLite 范围过滤后使用内存确定性文本匹配

不引入 FTS、Embedding、向量库或分词依赖。分词与打分是纯函数、固定过滤词、固定算法版本 `memory-recall-v1`；未来任何索引都只是可重建优化，不改变语义（契约 §6.1）。

### 5. 任务相关性优先于作用域桶排序

排序为 `score DESC` → 作用域特异性（`expert-workspace` / `workspace` / `expert` / `user`）→ `updatedAt DESC` → `id` 字节序 `ASC`；`confidence` 不参与排序。同时保留一个**小额通用偏好预算**（仅 verified + user-instruction + user + preference，最多 2 条 / 600 code points），使「先列异常再列总体指标」这类偏好不被相关性排序挤掉（契约 §6.2）。

### 6. 新 Run 固定记忆修订与安全历史

普通治理变化（编辑、确认、删除、过期、改范围）影响下一 Run，不热改活跃 Run；活跃 Run 需要刷新时由用户取消并重跑。历史上下文只重放「连续安全后缀」，采用**直接 + 传递依赖**判定，缺依赖事实即不推断安全（契约 §6.3）。

### 7. 区分选中、请求装配与调用尝试

三个阶段事实必须分开持久化：`selected` → `request-prepared` → `dispatch-attempted`（旧记录为 `legacy_unknown`），阶段时间单调。Provider 包装器在装配出首个实际 `ModelRequest` 后计算规范化 `requestHash` 并核对记忆块修订；任一阶段持久化失败都不发起该次请求。不保存第二份完整模型请求、不记录密钥、不把调用尝试当作网络已成功（契约 §6.4）。UI 文案禁止出现「模型已收到/已阅读」或声称因果影响。

### 8. 简报为只读派生视图，参考标记为版本级用户选择

工作空间简报由查询生成，不用 LLM 二次总结、不持久化简报正文、不整体注入模型。「指定为参考版本」只是用户的参考选择，固定 `artifactVersionId` + `contentHash`，不跟随 latest，**不表示内容正确、审批通过或已被本期读取**。

## 与其他 ADR 的关系

**延续 [ADR-0004](0004-hybrid-memory.md)**：文档、结构化记录与派生索引的混合记忆边界不变，本 ADR 只是把「派生索引」推迟到确定性召回被证明不足之后。

**细化并拟替代 [ADR-0015](0015-memory-scope-and-governance.md) 的三处条款**（用户批准本 ADR 后才生效）：

1. **固定范围优先的排序**：ADR-0015 §4 的取候选顺序把「范围匹配 → 内容命中 → `user`、`expert-workspace`、`expert`、`workspace` 的稳定优先级」排在内容相关性之前，实际效果是作用域桶决定入选。本 ADR 改为决策 5 的 `score` 优先 + 偏好小池。
2. **Unicode 长度的含糊表述**：ADR-0015 §4「6,000 个 Unicode 字符」与 §失败语义「超出 2,000 字符」未指明计数单位。本 ADR 统一定义为 **Unicode code points**，并要求正文、摘录与预算共用同一计数函数（契约 §5.1）。
3. **「选中即实际注入」的解释**：ADR-0015 §4「最多注入 16 条」与「读取足迹记录实际注入的记录」把选择、请求装配与调用尝试压成一件事实。本 ADR 按决策 7 拆成三段可审计状态。

**补足** ADR-0015 §5 的范围收缩要求：原条款只覆盖「移除记忆或缩小适用范围时创建新上下文段」，未规定材料替换/换版本/哈希不符、记忆过期/被替代、来源不可用、传递依赖继承以及「遇首个不安全轮次即停止、不跨过它拼接更早对话」的连续安全后缀要求（契约 §6.3）。

**明确自然语言「记住」的边界**：未经用户核对的模型提炼**不是**用户确认原文。模型只能写 `candidate`/`pending`，不存在公开的「模型确认」API；用户在最终保存表单明确提交后才可 `confirmed`（契约 §5.4）。

**保留不动**：[ADR-0014](0014-expert-context-and-material-binding.md) 的材料范围与 TaskContext/RunContextSnapshot 边界、[ADR-0005](0005-artifact-version-evidence.md) 的成果版本与来源继承、[ADR-0019](0019-discussion-checkpoints-and-rework.md) 的讨论节点事实边界。本 ADR 只在它们之上追加记忆的来源与依赖判定，不重定义材料授权。

**一处显式安全变更**：现有「无 TaskContext 的旧通用入口按全库兼容访问」收敛为由 Main 生成明确的 `general` + 空材料范围上下文，不代表整个 Workspace 或整个知识库可读。这是安全收紧而非产品承诺变更，必须让老用户可解释，不静默改变行为语义。

**旧 Accepted ADR 的处置方式**：只在其文件内追加指向本 ADR 的替代关系说明，不改写原接受历史、不改原状态行、不把 E30–E32 的 done 回退。本 ADR 获批准前，ADR-0015 全部条款仍然有效。

## 关键取舍

| 备选方案 | 为何不选 |
| --- | --- |
| 引入 Embedding / 向量库做相关性召回 | 需要新依赖、索引生命周期与隐私面；先用 SQLite 范围过滤后的确定性内存匹配验证语义，可复现、可固定 fixture、随时可替换。 |
| 让模型自行判断该带哪些记忆 | 选择结果不可复现、无法审计，且模型可能借「相关」之名越出材料范围。 |
| 沿用 ADR-0015 的作用域桶优先 | 无关但范围匹配的记录会稳定占满预算，用户观察到的是「记了但没用到」。 |
| 按 UTF-16 长度或估算 token 计预算 | 计数含糊会同时影响去重、预算与 emoji/非 BMP 正确性；code point 计数与实测 token 是两件事，后者只记录模型真实返回的 usage。 |
| 把 `run_memory_reads` 当作「模型已收到」 | 该记录发生在准备阶段，网络失败或取消后仍会留下足迹，属于对用户的错误陈述。 |
| 保存完整模型请求副本以证明注入 | 放大存储与泄密面（可能含凭据与全文）；改用规范化 `requestHash` + 精确修订引用。 |
| 让模型自动确认高置信度候选 | 置信度是模型自评分，不能建立用户意图；所有自动结果必须停在 candidate。 |
| 用定时作业判断到期与冲突 | 需要后台调度与状态同步；到期由查询派生，冲突只在同一 `topicKey` + 作用域交集 + 有效期交集时提示「可能冲突」，不判定真假。 |
| 重放整段历史以获得连续性 | 已撤销/替代/过期的记忆会经历史回答回流进模型输入；只取连续安全后缀，宁可上下文变短。 |
| 简报用 LLM 二次总结 | 会制造一份新的、无来源的「事实副本」，并让整份简报自动进入模型；简报必须是可重建的查询视图。 |
| 复用 `supersedesId` 表达跨记忆替代 | 它实际指向同一记忆的前一 `revisionId`，复用会让历史解释错乱；新增 `replacesRevisionId` 承载跨身份替代。 |
| 一次性禁用所有 legacy 来源记忆 | 会把用户的既有积累读成空白；改为保留历史、标记「来源待复核」、不自动注入新 Run，并在同一张卡提供复核入口。 |

## 影响与边界

- **模块影响**：`packages/agent-protocol`（共享 Schema/DTO/错误码）、`apps/desktop/src/main`（记忆仓储与服务、召回纯函数、运行审计、Provider 工厂、提炼作业、简报与参考仓储、IPC 注册）、`preload`（最小类型化 API）、Renderer（记忆页、上下文面板、建议区、简报区，均经 hooks 收口）。Agent Core 仍不依赖 Electron/SQLite/React，只多可选的 `maxOutputTokens` 与 `finishReason`/`usage` 字段。
- **迁移影响**：版本化迁移分四批，各批开工时取当时的最新连续版本号，不预填固定号码与并行 CF 系列争号；旧迁移不改写，legacy 数据只追加标记不补造来源（契约 §8.4）。
- **不在本 ADR 范围内**：Embedding 与向量检索、全量聊天扫描与定时反思、模型自动确认、依据置信度自动覆盖、通用 Agent 引擎或 DAG 作业平台、新 Project 实体、企业权限与多租户、自动成果差异学习与经验自动转 Skill、DOCX 新增生成、云同步、完整历史物理擦除、把记忆提升为工具或材料授权。
- **不承诺**：性能实测基线、开发工期、采纳率或质量提升比例。规模压测先用 1,000 条有效记忆的合成集合记录排序耗时；若超出可接受主线程开销，返回设计评审，不擅自引入向量库或长期后台扫描。
