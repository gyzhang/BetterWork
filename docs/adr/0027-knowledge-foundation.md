# ADR-0027：固定知识修订、受限读取与可重建混合检索

- 日期：2026-09-24。
- 状态：Proposed；本轮只写文档。产品方向已接受，不代表下面的技术选型、UI 结构或编码已批准。
- 关联：[产品规范](../designs/knowledge-foundation.md)、[实施契约](../development/knowledge-contracts.md)、[KM 任务板](../development/tasks-knowledge.md)。

## 背景

已有 Vault 当前投影、不可变知识修订、Task 材料、Run 快照、关键词搜索和来源足迹。缺口不是没有知识系统，而是研究入口没绑定资料、模型只能搜索摘要、嵌入配置没有业务消费者，以及来源访问与成果采用混淆。

`vault.sqlite` 与应用库分别管理知识和任务事实，没有跨库事务。现存修订记录了 parser/chunking 版本；旧规则把整个 Vault 称为缓存的简写不能用于删除已被 Task/Run 引用的修订。现有 Office 解析器可以复用，但限额、取消、幻灯片顺序与定位往返必须先补证据。

## 决策提案

1. **保留既有领域与分层。** 不新增 Knowledge Agent、新 package 或第二套材料身份。Tool Runtime 只通过注入函数调用 Main 服务；UI 经 Hook/Preload/类型化 IPC，Agent Core 不感知数据库。
2. **区分不可变文本与派生检索块。** 知识修订的原始文件哈希保持原义；另记提取文本哈希。既有页/段落是正文定位单元，派生小块仅供检索和嵌入，映射回固定单元和码点范围。索引重建不改修订；解析升级可在相同文件哈希下产生不同提取版本。
3. **以 Run 快照为读取边界。** 新增知识正文工具；空材料集合必然空搜索、拒绝读取，取消时不能回落到全库。旧无 TaskContext 的兼容 Run 不再隐式获得全库搜索，改为可解释的空结果；全库查找只属于知识页管理操作。
4. **嵌入独立于对话 Provider。** 复用 embedding profile、endpoint 解析与凭据入口，Main 持有可注入 fetch 的批量嵌入适配器。不把向量塞进聊天 Provider，不新增第二处 API Key。
5. **第一版采用有规模上限的本地精确向量扫描。** Float32 向量存在 Vault 普通 SQLite 表，归一化后余弦相似度检索；扫描/解析在独立工作执行单元，按批处理，主进程不跑长同步循环。不增加 sqlite-vec 或 LanceDB 原生依赖。关键词与向量用确定性排名融合，所有过滤在截取前完成。
6. **区分向量空间与单修订代次。** 模型指纹与共享空间代号隔离向量，维度跨修订统一锁定；暂存代次只有完整校验后才发布。普通同空间重建可保留旧可用代次；强制重建先退役整个旧空间，再逐修订发布，避免同名同维度模型换代后混用。配置切换使不兼容空间不可检索。持久化作业支持取消、失败、重启 interrupted，不自动付费重试。
7. **精确来源，不推断采用。** Knowledge Evidence 关联固定修订和实际返回范围；保留旧来源但不伪造精确位置。成果自动关联的访问来源只表示运行访问记录；采用关系需模型或用户声明，新旧版本显式区分。历史未核实关联经人工编辑仍未核实，不能由继承自动变为声明。
8. **复用 Office 能力。** 知识导入 XLSX/CSV/PPTX 复用现有解析服务和 ADR-0018 的依赖，不复制另一套解析器；Knowledge 输入限额独立且不放宽任务输入已定边界。必须防止读取和计算哈希使用不同文件字节。
9. **单层集合属于组织，不属于授权。** 分类存在 Vault；任务仍显式选材。移除当前资料不删除历史修订和证据，物理清理另行设计。

精确字段、预算、算法、错误码、状态迁移和 IPC 仅由[实施契约](../development/knowledge-contracts.md)定义，本 ADR 不复制。

## 选择理由与备选方案

| 方案 | 判断 |
| --- | --- |
| 继续只有提示词和摘要 | 无法读取长资料，也无法证明所选材料进入任务；不满足产品目标 |
| 全库正文直接注入模型 | 混淆资料组织与运行范围，并失去读取预算和定位；不采用 |
| sqlite-vec | 更适合扩大检索规模，但当前没有本项目 Electron 打包/平台兼容证据；本轮不引入原生依赖 |
| LanceDB 或独立向量服务 | 增加部署与依赖面，超出个人桌面基础闭环；后置 |
| SQLite 普通向量表＋受限精确扫描 | 复用现有数据库，无新增依赖，确定性可测；规模及延迟上限必须实测，不声称能承载无限知识库 |
| 仅关键词，不接嵌入 | 保留为可解释的降级与离线模式，不作为语义检索完成的替代 |
| 重新设计全部 Evidence/Artifact | 扩大范围；只给知识增加精确来源，并给采用声明增加明确事实，不更换 web/MCP 来源协议 |

如果契约指定规模下不能满足延迟或内存门槛，停止在性能证据与 ADR 修订处，不静默降低数据量或自动安装新向量依赖。工作执行单元的开发/打包入口变更须在对应任务列明；不得放宽 sandbox、preload 或 lint 规则。

## 与已接受决策的关系

- 延续 ADR-0003 的内核边界、ADR-0014 的显式材料与固定 Run、ADR-0018 的只读 Office 解析、ADR-0023 的材料用途/关系枚举。
- 拟细化 ADR-0005 的“实际使用 Evidence”：保留运行访问证据，但采用必须显式声明；旧自动关联记录不被事后改写为已确认采用。
- 不替代 ADR-0004/0015/0026 的记忆设计。Knowledge 混合检索的批准不会让 WM 记忆召回自动变为向量。
- 只收窄旧无 TaskContext 分支的隐式全库搜索，不改变知识页全库查找。批准前不修改现有实现。
- 旧 docs/04 对 sqlite-vec 的“优先考虑”不是已完成技术选型；本 ADR 获批准后，该知识增量采用此处方案。

## 后果、迁移与验证

需要 Vault 和应用库各自版本化迁移，但不能一次事务跨两库。先保证修订可读，再在应用库记录绑定；失败不能清空旧任务或发布半成品索引。旧修订 ID、材料哈希和来源全部保留。

必验：旧库升级、同哈希不同解析版本、受限读取、Unicode 分页、去重、跨 Run 来源隔离、显式采用、模型指纹变化、向量校验、取消/迟到、部分覆盖、Office 定位、重启与打包入口。自动测试、人工 UI、真实模型效果三栏分开记录。
