# ADR-0041：文件成果在工作空间中的交付副本

- 状态：Accepted（2026-10-07 用户确认交付约定并授权实现）
- 日期：2026-10-07
- 相关：[ADR-0005](0005-artifact-version-evidence.md)、[ADR-0029](0029-workspace-identity-and-sidebar-groups.md)、[文件成果与 Skill 执行设计](../designs/skill-executor-and-dependencies.md)

## 背景

文件型 Artifact 的不可变原件保存在应用数据目录 `artifact-files/<versionId>/output`。该存储键没有文件扩展名，也不位于用户选择的工作空间中。成果页的「打开」和「打开所在文件夹」此前直接使用这个内部路径，导致系统无法按 `.pptx` 等扩展名选择应用，用户也无法在工作空间目录中找到已完成的交付文件。

## 决策

1. **保留不可变原件，另生成工作空间交付副本。** 内部版本仍是校验、预览、版本历史和导出的权威来源。登记成功后，在 Artifact 所属工作空间的可见 `成果/` 目录创建一个可继续使用的副本。
2. **文件名与扩展名由通用宿主规则生成。** 文件名包含成果标题和版本号，扩展名优先取宿主已验证输出文件的扩展名，缺失时按 MIME 类型映射常见扩展名。该流程不检查 Skill ID、名称或目录。相同文件名已存在时保留原文件并尝试带数字后缀的新名称。
3. **原子创建且不覆盖。** 宿主在目标目录写入唯一临时文件，再以同文件系统的原子非覆盖发布创建交付副本。路径检查拒绝逃逸与符号链接；已有副本可由用户继续编辑，宿主不会用内部原件覆盖它。
4. **记录每个版本的工作空间相对路径。** `artifact_files.workspace_relative_path` 通过 schema migration v44 持久化，使成果标题变化后仍能打开该版本原位置。历史版本在首次打开或显示时按需补建副本；副本丢失时可从不可变原件重建。
5. **打开与定位指向工作空间副本。** 成果页的「打开」由系统应用打开交付副本；「打开所在文件夹」在 Finder 中显示这个带扩展名的副本。独立「导出」仍使用保存面板，从不可变原件复制到用户另选的位置。
6. **文件系统与 SQLite 没有共同事务。** 内部 ArtifactVersion 与文件原件先完成登记，交付副本随后生成。交付失败必须呈现明确错误；ArtifactVersion 保留，用户再次打开或定位时可重试，不重新执行 Skill。
7. **交付副本的人工编辑不改写不可变版本。** 工作空间副本是供用户使用的普通文件；对该文件的手工修改不会静默覆盖内部版本，也不会伪装成新的 `user-edit` ArtifactVersion。

## 后果

- PPTX、DOCX、XLSX 等已知 Office MIME 类型在工作空间中保留可识别扩展名；Skill 输出契约提供的文件扩展名可由通用宿主直接沿用。
- 新增 Skill 不需要专属的文件复制或打开逻辑。运行时仍负责验证输出、工作空间边界、原子落盘与错误反馈。
- 工作空间目录会多出可见的 `成果/` 文件夹。每个成果版本占用一份用户可访问副本；内部不可变原件继续由应用数据目录维护。
- 已存在但尚未记录路径的旧文件成果在首次打开或定位时迁移式补建副本，不批量扫描或改写用户工作空间。

## 验证边界

验证实现覆盖 schema v44 的路径字段、已验证输出扩展名保留、MIME 后备映射、同名冲突不覆盖、旧版本懒补建、路径边界与 Finder/系统打开目标。真实应用中需确认普通文件出现在 `成果/`、扩展名正确，且两项按钮都操作该文件。
