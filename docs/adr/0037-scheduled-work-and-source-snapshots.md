# ADR-0037：周期工作实例与本期来源快照

- 状态：Proposed（产品原型已于 2026-10-03 获光哥批准；本记录是随后细化的技术提案，不代签技术批准）。
- 日期：2026-10-03（本轮 `date`）。
- 依据：[定时任务设计](../designs/scheduled-tasks.md)、[已通过原型](../prototype/scheduled-tasks/README.md)、[实施契约](../development/schedule-contracts.md)。
- 执行入口：[SC 唯一任务板](../development/tasks-schedules.md)与 [GPT-6 Luna 编码交接](../development/schedule-coding-prompts.md)。

## 背景

已有 ExpertRevision、TaskContextRevision、Run、输入快照、KnowledgeRevision、ArtifactVersion 和通知可以承接周期工作，但没有规则、计划实例或后台派发关系。Renderer 召唤流程不能作为无窗口执行入口；先启动 Run 再补记实例关系，会在崩溃时丢失关联并重复执行。

普通任务的材料必须显式选择，且草稿材料最多 50 项。定时任务已批准选择长期工作目录与知识文档、集合或个人资料库，并在每次执行时固定届时内容。不能把这项授权扩大到全部普通任务，也不能把整个资料库塞进 50 项草稿或模型提示词。

## 决策提案

1. **新增 Schedule 与 ScheduleOccurrence，继续使用现有工作实体。** Schedule 固定 Workspace 和已有 ExpertRevision，配置版本不可变；每次自动计划或人工执行有独立 Occurrence。允许没有 Task/Run 的 missed、overlap、blocked；有工作时分别创建 Task/Session，最多关联一个首个 Run。后续人工协作仍是原 Task 的新 Run。
2. **自动派发至多一次。** 自动实例以 `(schedule_id, scheduled_at)` 唯一，人工以 requestKey 唯一。占用实例与推进下一计划在同一 SQLite 事务；Run 及其上下文、实例首个 Run 关联在另一启动事务内共同提交，然后才消费异步执行。不能把已开始消费的 Run 外包进事务，也不承诺外部副作用恰好一次。
3. **范围授权在每期转为具体材料。** 配置保存动态来源描述，Main 每期生成不可变来源清单，引用已有 MaterialReference。TaskContextRevision 增加由 Main 校验归属的本期来源快照引用；Run 启动解析成有界具体材料并沿用读取、检索、记忆依赖及成果来源机制。普通任务的 50 项显式材料上限不变，范围引用不能由 Renderer 拼 ID 获得权限。
4. **不热换历史，也不从历史扩大下一期权限。** 本期快照不随原文件、集合成员或知识当前修订变化。下一期重新解析有效范围；已删除/撤销的来源不能从旧聊天、记忆或成果传递依赖复活。人工继续原 Task 可以使用原快照及新补充材料，范围收缩仍走现有安全历史规则。
5. **固定时间规则、错过只记账。** Main 使用同一个 `cron-parser` 适配器供预览和调度调用。首版每日/每周/每月、分钟精度，只开放已核验的固定偏移时区。进程退出、休眠、恢复、时钟跳变造成的历史时刻只形成 missed，不自动补跑。暂停不累积欠账，恢复只计算未来计划。
6. **应用宿主负责生命周期。** 在数据库与既有恢复工作完成后启动调度；同一 userData 只允许一个调度所有者。关窗可以继续，退出先同步关闭派发并取消准备，再等待既有 Run/Worker 收口，最后关库。调度不进入 Agent Core，不增加 OS 常驻服务。
7. **无人值守沿用现有授权并检查适用性。** 不自动信任、安装依赖或接受交互审批。不把 MCP 名称或脚本信任解释为只读证明。首版能力支持与拒绝规则见实施契约 §6；未能证明符合本地读分析/成果边界的绑定整次阻塞，不静默删掉能力，也不新增通用权限平台。
8. **成果文件是版本的交付副本。** 先登记真实 ArtifactVersion，再保存到同一目录的「定时成果」。通过版本键、内容哈希和持久化回执实现非覆盖与恢复；失败仅重试保存原版本，不能重新调用模型。文件系统与 SQLite 不假装有共同事务。
9. **通知只收口一次。** Occurrence 完成事实、通知记录和防重复回执在同一应用库事务落地，广播在提交后。定时首个 Run 使用定时结果收口，普通 Run 的通知保持原路径；清空消息不清回执。无窗口系统通知点击需恢复窗口并等待 Renderer 就绪后消费目标。
10. **UI 只组合现有基座。** 页面/Hook/纯函数按现有层级增加；不新造定时任务专属按钮、卡片、字段、Toast、Dialog、页面骨架或通用 CRUD 工厂。确有跨页面稳定语义缺口才扩展现有基座，并同卡更新 docs/10 台账与测试。

## 延续与细化关系

- 延续 ADR-0003 的宿主边界，不新增调度 Agent 引擎。
- 延续 ADR-0005 的版本与来源，不把文件副本或「产物已生成」解释为内容验收。
- 在 ADR-0014 的显式材料授权上增加**仅定时 Task 可持有的范围快照引用**；普通任务仍遵守原规则。生效后同步补充材料契约，不改写 Accepted ADR 历史。
- 延续 ADR-0026 的材料传递依赖、安全历史与遗忘约束，不做定时反思或全量历史扫描。
- 延续 ADR-0029 的 Workspace 身份与隐藏语义，不增加工作空间删除。
- 不以本提案接受或替代 ADR-0024/0025，也不等待其全部能力实现；复用当次实际可用能力。

## 代价、风险与验证

新增实例、来源清单、成果保存与通知回执的持久化及恢复；Run 启动事务需要一个窄的 Application 关联入口。源码已有材料数组与记忆依赖消费点必须一起核对，不能只改工具入口。

`cron-parser` 的发布版本、Electron 打包、月末行为由 SC05-1 实测锁定；本轮只查阅上游 API，没有安装依赖或执行生产调度。来源预算是防失控技术上限，不是业务内容质量保证。可信脚本仍不是原生进程沙箱。

SC10 必须以临时 SQLite、注入时钟、Fake Provider 和受控文件验证连续六期、所有事务断点、撤销、非覆盖、清空通知后的恢复。真实模型、真实业务与发布分别记录授权。任何代码尚未实现，本 ADR 保持 Proposed。
