# ADR-0020：经营分析的确定性数值边界

- 状态：Accepted（E53，2026-09-14）
- 前置：[ADR-0014](0014-expert-context-and-material-binding.md)、[ADR-0018](0018-office-input-parsing-boundary.md)。

## 决策

1. 期间变化和预算偏差由 `analyze_business_metrics` 确定性工具计算。模型负责从已读取材料提取并映射指标，不能在提示词中自行心算、补齐缺失值或刷新表格公式。
2. 工具输入显式区分 `current`、`previous` 和 `budget`，保留原始数值、变化额和比例；零基数比例不输出伪造百分比，而是写入结构化 warning。缺少当前值直接失败。
3. 首个内置 Skill「经营分析方法」只提供口径核对、材料选择和工具调用约定；公司财务规则、期间定义、单位和预算来源必须通过 Task 材料进入，不硬编码到 Agent Core 或工具。
4. 输出仍是 Run 临时结果。报告/PPT 是否采用结论由用户通过讨论节点确认，不能因为工具计算成功就自动发布 Artifact 或业务系统写入。
5. R02 的数值事实防护只用于 `builtinToolPolicy` 明确 allow-list `analyze_business_metrics` 的经营/数值分析 Run。其输入值必须同时带数值、指标（映射键）、单位、期间与来源 ID；来源 ID 必须对应本 Run 实际读取的材料片段、当前用户提示，或 Knowledge 搜索/读取产生的 Evidence。当前值期间必须等于分析期间；同一指标跨期间或对预算比较时单位必须一致。宿主先核验来源内容，再运行确定性计算。结果保留直接值的来源、单位与期间；差额/比率只能由工具结果登记，并保留所用期间和来源。最终数值主张须在同一行带出指标、单位和全部相关期间，才可通过事实审计。普通 Run 不启动这套数值策略。

### QI01 技术澄清：事实的局部关联与歧义拒绝（2026-10-12）

本节把第 5 项的来源核验和输出审计细化为 Application 宿主必须满足的契约，不改变其 Run 范围、工具输入字段、持久化模型或 Evidence 关系。

- `sourceId` 指向本 Run 的一次实际读取片段；验证只检查该片段，不能从另一来源、未读取的选择、历史 Run 或旧 Evidence 补齐字段。用户提示中的事实仅使用保留 ID `user-prompt`。
- 文本事实必须在同一 sourceId 的断言单元中同时出现完整指标名、数值、单位和期间。换行及句号/问号/感叹号/分号构成硬边界；在同一行/句内按显式指标名界定并列片段，每个指标片段只能对应一个数值/单位对。仅有一个明确期间时可在该行/句内共同适用；多个期间必须各自落到对应指标片段。无法唯一切分或配对时拒绝，不增加 `sourceLocator` 工具字段或猜测映射。否定、缺失、假设或待确认语句不支撑已发生的直接事实；`budget` 项还须有明确预算口径。
- Office 输入按本次实际返回的结构化记录核验。PPTX 只在同一表格行组合；CSV/XLSX 只在同一数据行内组合，并可引用该已读取记录所属且明确的表头。宿主须保留 section locator、Sheet/单元格地址、行列和类型化值；不跨行、跨 Sheet、跨页或跨 sourceId 拼接。表头、合并区域或记录归属不明确时拒绝。公式只使用已有解析结果的缓存值。
- 同一指标与规范化期间下的直接事实只有在数值和单位一致时可合并。一个来源、一次工具输入批次或当前 Run 已核验直接事实中出现冲突值/单位时，整个待验证输入拒绝，不能择首、择末或按来源优先级解决；在所有输入通过前，不运行确定性计算或部分写入账本。
- 单位只归一 Unicode NFC、首尾空白及全角百分号；不做单位换算或同义词推断。年月的明确格式可以归一为同一月，年月日只与同一天匹配；其他期间标签按 NFC、首尾空白归一后的完整文本比较。值必须是有限直接数值。
- 显式经营分析 Run 必须使用带 `value/unit/period/sourceId` 的来源型工具输入；校验失败不能回退到旧无来源输入。无该来源校验器的通用工具实例继续接受原有无来源形状，保持其非经营分析用途兼容。
- 输出审计逐个绑定数值主张的位置和维度。每个主张必须在自身行/句的指标片段含值与单位，并在该行/句带出全部相关期间，匹配无冲突的已核验直接事实或确定性工具结果。每个显式指标名界定一个并列片段；唯一期间可共同适用于该行/句，多个期间必须各自明确关联。候选数值包括紧邻已知指标/分析主张的数字（即使缺单位）及带计量单位的业务表达；包含已知指标或指标列的表格数据行也进入审计。表头可以识别待审计表格，不能补给主张字段。不得借用其他行、同一行另一指标或全局数字池。缺失单位/期间的明确业务值和表格裸业务值仍属于待审计主张，不能因正则未提取而漏过。
- 日期/期间组成数字、列表序号、版本/标识符、代码与 URL 中的数字不自动构成业务主张；识别器按指标、单位或业务变化词及断言上下文定位业务数值，不把所有数字一概拒绝。对无法判定是否属于业务主张的含数值内容，若它位于明确指标断言单元内则按缺少维度拒绝；否则由原有非数值内容处理。
- 校验失败沿用 Run 失败与清理语义；拒绝的输入不得运行计算或留下部分事实，失败的最终审计不得发布候选成功或登记成功成果。普通 Run 与材料驱动的既有定性检查保持各自边界。

这项澄清规定预期行为。QI02–QI04 分别完成文本、输出和 Office 实现与回归；实施前不得把文档契约当作缺陷已修复的证据。

## 验证边界

合成数值覆盖正负变化、零基数、预算偏差、缺失指标和取消。Skill 以内置资源分发，引用真实存在的确定性工具；真实财务规则与两期业务输入留 E55 桌面验收。

R02 的实现将读工具返回的 `sourceId` 透传到事实输入；Knowledge 工具使用其返回的 `evidenceId` 作为来源 ID；明确写在当前用户提示中的事实使用保留 ID `user-prompt`。来源与结构化事实只驻留在当前 Run 内存账本，不新增持久化表或 IPC Schema。
