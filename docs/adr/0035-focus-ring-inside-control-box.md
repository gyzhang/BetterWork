# ADR-0035：焦点环画进控件自己的盒子

- 状态：Accepted（2026-10-01，按光哥「走 A，加 1px 分隔缝」的拍板实施；同日 20:15 他量出左右环比上下细一倍，偏移由 `-1px` 改为 `-3px`，见「第二轮」）。
- 日期：2026-10-01。
- 依据：[UI/UX 体系 §9.10／§12](../10-ui-ux-system.md)、[ADR-0034](0034-input-control-base.md) 决策 4（「聚焦环归基座」的那半句在本记录里被纠正）。
- 关系：**替代 ADR-0034 表第 7 行「聚焦环 → 1 处出口」的结论**——那次收口把输入控件基座内的三种处置并成一种，但 `.composer textarea { outline: 0 }` 作为「Composer 输入区两条」例外留了下来，全仓最重要的输入区因此从来没有焦点指示。不改写它其余结论。

## 背景

光哥在设置页「记忆」发现：搜索框聚焦后**左右两条边框不见了**，知识页的搜索框却完好。

原因不在那个 `<input type="search">`，也不在那一页。焦点环是 `outline: 2px solid` ＋ `outline-offset: 2px`，画在边框盒**之外** 4px；记忆页那一层 `.memory-settings` 是本页的滚动区（`overflow-y: auto`，而 `overflow-y` 非 `visible` 会把 `overflow-x: visible` 强制成 `auto`），它自己没有任何水平内距，工具栏里的输入框又 `flex: 1` 顶满——于是左右那 4px 落在裁剪边之外被切掉，上下方向还有兄弟块留着空间，就长成「只有两条横线」。知识页的搜索框住在 `.page-body` 里，版心取 `min(860px, 100% - 48px)` 且居中，环有二十几 px 余量，所以看不出问题。

**这是一条通用不变量被违反了 N 次，不是一页的样式写错。** 把 `styles.css` 解析成规则块，53 条 `overflow` 声明里至少 8 处会吃到外扩的环：

| 裁剪容器 | 被吃的是谁 | 症状 |
| --- | --- | --- |
| `.memory-settings` | 本页顶宽输入框、页签 | 环左右不见（报告的那处） |
| `.model-sheet form` | 480px 抽屉里的输入框 | 同上 |
| `.knowledge-drawer-body` | 索引抽屉内控件 | 同上 |
| `.scroll-region` | 知识文档列表、成果版本列表、资料详情 | 同上（覆盖面最大） |
| `.workspace-groups` | 侧栏工作空间与任务行 | 同上 |
| `.notification-list` | 消息中心行 | 同上 |
| `.app-shell` | 顶到窗口边缘的一切 | 边缘处被切 |
| **`.segmented-control`** | **它自己的每一档按钮** | 按钮填满容器且 `border: 0`，**环四边全被吃** |

最后一行不是美观问题：Tab 到「卡片／列表」切换组时焦点指示器**根本不存在**，这是 WCAG 2.4.7 失败。同一轮还抓到 `.composer textarea { outline: 0 }`——任务输入区聚焦时同样毫无反馈，而 ADR-0034 与 §9.13 当时都已写下「聚焦环现在各只剩一处出口」。**文档结论与代码现实分叉**：那 6 条例外里有一条正在关掉环，护栏看不见它，因为「页面不得替输入控件发几何与外观」那条只扫选择器含 `.text-field`／`.text-area` 的规则。

仓库其实已经撞见过一次：`.scroll-region:focus-visible` 用的就是 `outline-offset: -2px`——唯一一个「自己就是裁剪容器」的元素早就改成内收了。这是第二次。

## 决策

1. **焦点环一律画在控件自己的盒子里**：`outline: 2px solid var(--focus-ring)` ＋ `outline-offset: var(--focus-ring-offset)`，Token 值 **`-3px`**。判据不是符号而是环带落点：Chromium 的环带 = `[-偏移, -偏移 + 环宽)`，2px 的环配 `-3px` 落在边框盒往里 `[+1, +3)`——**整个 2px 都在盒内**，祖先的 `overflow` 无处下嘴；配 `-1px` 只有一半在盒内（第二轮的红字就是这个），配 `0` 或正值整条在外。画在盒外的任何一段都可被祖先裁掉——`outline`、外扩 `box-shadow`、`inset: -Npx` 的伪元素同罪，CSS 里没有一种外扩写法能逃出祖先的 `overflow`。把环搬回盒内，不变量就从「每个容器都要记得留余量」换成「环不依赖任何容器」，新页面不需要重新遵守任何约定。
2. **1px 分隔缝由「裁到 padding 盒的背景」＋「环不盖住边框槽」两条一起让出，不新增颜色 Token**：`--focus-ring` 与 `--brand`／`--danger` 同色系（暗色 jade 下 #7ec6a6 压在 #65a990 上约 1.3:1），环直接贴在实心填充上等于看不见。`.btn` 本来就带 `1px solid transparent` 的边框槽（ADR-0031 为的是与带边框控件同盒几何），聚焦时把背景裁到 padding 盒，那一格就露出控件所在表面的底色。**但环带必须从这一格往里起画**——第二轮实测 `-1px` 时环正好盖住它，缝宽 0，这句话在当时只是设计意图。带不透明边框的控件（输入框、下拉、picker）不受影响：那一格本来就是它的边框，聚焦时读作「边框 + 环」。**不走 `box-shadow` 双描边**：那条通道已被 `.memory-row.memory-candidate` 的 `inset 2px 0 0` 状态标记条占用，两个用途抢一个属性迟早互相覆盖。
3. **原生表单元素的自写环规则删除；`summary` 由基座的类承接，不进元素名清单**：`.switch`（`<button>`）与 `.text-field`／`.text-area`（`<input>`／`<textarea>`）本来就落在全局那条的元素名上，那两条只是把偏移从 2px 改成 1px，等于在同一种控件上供着两种几何，随本轮删除。`summary` **曾一度被加进全局那条**，随即被「样式表不再点名 `details`／`summary` 元素」这条护栏打回——它是 `Disclosure` 基座自己的牙（防的是页面在外面按元素名再起一套行几何），把 `summary` 写进全局那条等于用一条治理换掉另一条，还要为它在那条护栏里开一个例外。取舍回到基座一贯的「用类不用元素名」：那一行的环继续由 `.disclosure-label:focus-visible` 承载，本轮只把它的偏移换成同一个 Token。覆盖面不受影响——生产代码不出现裸 `<details>`／`<summary>`（同一族的另一条护栏），所以这个类就是全部 `summary`。
4. **五个出口，一种几何**：全局元素规则 ＋ `.disclosure-label`（`summary`，见上一条）＋ `.scroll-region`（`div[tabindex]`）＋ `.single-select-picker-option`（`input` 被 `opacity: 0` 盖住，环要画在 label 上）＋ `.composer:has(textarea:focus-visible)`。五条全部引用同一个 Token、同一条 `outline` 几何。
5. **复合表面可以把环搬到外层，但必须指名搬到哪**：`.composer textarea` 的 `outline: 0` 保留，环改由卡片自己承载——`textarea` 在卡片里是透明底无边框，环落在它身上会长出第二个盒子。用 `:has(textarea:focus-visible)` 而不是 `:focus-within`：后者会在焦点走到卡片里的附件、能力选择器与主行动按钮时把整张卡点亮，那是「谁被聚焦」的假消息。
6. **五条护栏**（见「验证」），并修掉「焦点环只有一种写法」那条对 §9.11 的错引（§9.11 是叠放层级，环属 §9.10 控件几何）。

## 实现边界

- 不给 `.memory-settings` 等 8 处补水平内距、不改它们的 `overflow`。方案 B（容器留余量）单独用不成立：它治不了 `.segmented-control`（补内距会破坏控件外观）与 `.app-shell`（窗口边缘），也拦不住第 9 处。
- 环宽 2px、环色 `--focus-ring` 不变——那是 §9.6 的色系契约，八处（4 色系 × 明暗）都已定义，本轮不动。
- `--focus-ring-offset` 与色系无关，只住在 `:root` 基础块一处，不进那 8 个色系块，避免「一个数被复制八遍」。
- 环带往里推到 `[+1, +3)` 的代价是它盖掉控件自己那 1px 边框**之内**的 2px 填充带：带边框的控件聚焦时读作「1px 边框 + 2px 环」，比原先厚一点，这是「完整」换来的，不再单独为聚焦态另立一档环宽。
- 首末两档与圆角外壳（`.segmented-control`：`overflow: hidden` ＋ `border-radius: var(--control-radius)`＝6px，档自己 `border: 0`）：第二轮按同一条几何量过——夹具 d 行照抄这组取值，把首档左上角 11×8 CSS px 的区域逐像素打出来，环带的横段与竖段各自完整 4 设备像素（＝2 CSS px），外壳那道弧**没有切到任何东西**。先前记的「≤2px 弧角可能被刮到」是推理，不是读数；量完之后这条从「已知取舍」改成「已验证无影响」，代价是环从档的边缘往里缩 1px，读起来比原先更贴内容一点。
- 不做的事：不给 `PopoverMenu` 的菜单项补环（它是 `role="menuitem"` ＋ `aria-activedescendant` 模式，当前项由 `--selection` 底色表达，属另一条轴）；不把环改成半透明外发光；不为「焦点时边框变色」再留一条第二通道。

## 后果

- **可见变化**：所有输入框、按钮、开关、页签、侧栏行、卡片行的焦点环从「盒外 2–4px 光晕」变成「盒内往里 1–3px 的一条」，四边同粗细、不再随容器宽度忽隐忽现；`primary`／`danger` 实心按钮多出一道 1px 所在表面色的缝；**任务输入区与「卡片／列表」切换组第一次有了焦点指示**（此前为零）。待光哥在真实界面回看。
- `outline-offset` 在 `styles.css` 里只以 Token 形式出现：改前六处各有取值（四处 `2px`、一处 `1px`、一处 `-2px`），改后五条环规则同一处几何，第六处即红。
- **「一处出口」这句话必须能被计数验证**：ADR-0034 写下它时，例外清单里就躺着一条正在关掉环的规则。今后凡「已收口到一处」的结论，护栏要能同时回答「剩下几处、每一处在写什么」，不能只回答「有几处不合规」。
- **「画在盒内」这种几何结论必须由像素证明，不能由符号证明**（第二轮）：`-1px` 是负值、护栏当时判它通过，而它只有一半在盒内。凡涉及渲染落点的取值，要么量、要么写「未量」；本轮起这类取值都要附一张渲染表（见「第二轮」）。
- **两条治理相遇时，让位的是新加的那条**：本轮想让全局元素规则多覆盖一个 `summary`，代价是在 `Disclosure` 的元素名护栏上开例外。例外一旦登记，那条护栏从此不能按元素名一刀切——第 9 处按元素名点名的 `details` 规则就混在合法例外里读不出来了。基座的类是同一件事的另一个出口，且不削弱任何一条护栏。

## 第一轮验证

`standards/coding-standard.test.ts`「界面观感基线」新增与改写四条：

1. **环必须画在盒内**——`styles.css` 里任何 `outline-offset` 必须是 `var(--focus-ring-offset)`；该 Token 只在 `:root` 定义一次且解析为负值。改前六处全红（`2px` 四处、`1px` 一处、`-2px` 一处）。
2. **带环的规则必须同时带偏移**——凡声明 `outline: 2px solid var(--focus-ring)` 的选择器块，同块内必须有那条 `outline-offset`，缺一即红（漏写等于退回初始值 0，环又跑到盒外）。
3. **环的出口与清单等量**——`RING_OUTLETS` 五条（全局元素规则、`.disclosure-label`、`.scroll-region`、`.single-select-picker-option`、`.composer:has(...)`）与实测的多集合比对，多一条要写明它为什么落不到全局那条元素规则上，少一条即红。这条是给「一处出口」这句话装的牙。
4. **关掉环要指名搬到哪**——`outline: none`／`outline: 0` 只允许出现在登记清单里，且清单每一项必须能在同文件查到一条真正承载环的规则；存量与清单等量，防止悄悄多关或悄悄失效。

变异验证六发，逐一转红、还原后 sha256 一致（第一轮收口时 `c1d156823bf5`）：

| 打进去的那一发 | 转红的断言 |
| --- | --- |
| `--focus-ring-offset` 翻成 `2px` | 「画在盒内」＋「docs/10 档位表 ↔ `:root` Token 同值」 |
| 删掉 `.scroll-region` 那条 `outline-offset` | 「带环必须同块带偏移」 |
| 追加一条几何全对的第六条环规则（`.capability-search input:focus-visible`） | **只有**「数出口」红——另三条全绿，证明这条补的正是它们的盲点 |
| 删掉 `.disclosure-label:focus-visible` 整块 | 「数出口」红（少一条＝文档在讲一件不存在的事） |
| 摘掉 `.composer textarea` 的 `outline: 0` | 「关掉环必须指名搬到哪」红（存量与清单不等量，清单里不许留着已改掉的） |
| 摘掉承载者 `.composer:has(textarea:focus-visible)` | 「数出口」＋「关掉环必须指名搬到哪」同时红 |

把 `styles.css` 换成 HEAD（改前）那一份再跑，四条断言**全部转红**（外加档位表同值那条），确认它们钉的是本轮改掉的那件事，不是自我循环。

## 第二轮：偏移从 `-1px` 改到 `-3px`

光哥回看时量出：记忆页搜索框聚焦后**上下环带 4 设备像素、左右只有 2 设备像素**（截图 2940×1698，DPR 2）。换算回来就是上下 2 CSS px、左右 1 CSS px——「画在盒内」这句只做到了一半。

诊断不能停在推理上，因为推理想象不出 Chromium 怎么摆这 2px。做法是**用自己的像素复现**：仓库自带的 `node_modules/electron`（44.1.1）起一个 `show: false` ＋ `paintWhenInitiallyHidden: true` 的窗口，渲染一份最小夹具（120×28 的盒子、1px 实边框、8px 圆角、`outline: 2px`），四种偏移各渲染两遍——一遍塞在**贴边的 `overflow: auto` 容器**里（复现 `.memory-settings` 那种「自己就是裁剪容器」），一遍放在不裁的容器里——`capturePage()` 出 PNG 后用 PIL 逐像素读。没有动他那个正在跑的应用。

| `outline-offset` | 环带（相对边框盒，CSS px；负＝盒外） | 贴边 `overflow: auto` 容器里实测 | `.btn`（1px 透明边框 + `background-clip`）实测 |
| --- | --- | --- | --- |
| `0` | [-2, 0) | 环**整条不见**（19/24/19 一路到边框） | 环在盒外，缝 1px |
| `-1px`（第一轮落地值） | [-1, +1) | **只剩内侧 1px**（环色只有 2 个设备像素宽） | 环盖住边框槽，**缝 0** |
| `-2px` | [+0, +2) | 完整 2px | 环贴填充，缝 0 |
| `-3px`（本轮定档） | [+1, +3) | **完整 2px** | **1px 表面色的缝 + 完整 2px 环** |

两条附带读数，都是第一轮没量过的：

- **左右都被裁，不止左边**。回到光哥那张 2940×1698 的截图逐像素复量：上边环带 4 设备像素（y745–748）、下边 4（y812–815），而左边只有 2（x1080–1081）、右边也只有 2（x2778–2779）。原因不是「左裁右不裁」，是那一行**折过行**——环右侧紧邻的 18px 全是面板底色（`19/24/19`），说明「刷新」不在同一行，输入框此时占满整行、两条竖边同时贴在 `.memory-settings` 的裁剪边上。上下的外半边留着，因为那个方向有兄弟块与 `gap` 给它留了地方。这条修正了第一轮日志里「左右被切、上下还在」的那句因果猜测。
- **圆角外壳切不到盒内的环**。夹具 d 行照抄 `.segmented-control[data-size=md]` 的取值（外壳 `overflow: hidden` ＋ `border-radius: 6px` ＋ 1px 边框，档 `border: 0` 填满），首档左上角 11×8 CSS px 区域逐像素打出来：横段与竖段各 4 设备像素完整。第一轮写的「首末两档环角可能被弧刮到 ≤2px」是推理不是读数，量过之后撤回。

于是两条结论同时被像素定死：`-1px` 既没保住环也没保住缝，`-3px` 两者都保住。

护栏加第 5 条断言（并回写进第 1 条）：环带的**向内可达**必须 ≥ 最大环宽 + 1px 分隔缝（现算 3 ≥ 2 + 1），并按同一公式取 Token 值——符号为负不再算通过。变异验证两发，还原后 `styles.css`＋`docs/10` 的 sha256 与打前一致：把 Token 与档位表**一起**打回 `-1px`（这样「docs/10 ↔ `:root` 同值」那条不干扰），红在第 1 条的新文案「向内只走 1px，环宽 2px：环带跨在边框盒边线上」；同样两处打 `-2px` 也红（「向内只走 2px」）——那一档保得住环、保不住缝。反向一发：只把 `styles.css` 改成 `-3px` 而档位表留着 `-1px`，红在「docs/10 档位表 ↔ `:root` Token 同值」。

夹具与像素读数留在 `/tmp/ring-lab/`（一次性验证产物，不入库）；本表是它的结论存档。
