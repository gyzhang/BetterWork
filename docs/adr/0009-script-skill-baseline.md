# ADR-0009：以真实脚本型 PPT Skill 作为首个兼容基线

- 状态：Accepted（用户要求的支持范围；具体执行技术方案待另立 ADR）
- 日期：2026-09-08
- 关系：补充 ADR-0008，不改变 Skill → 专家 → 完整工作路径的顺序；撤回产品修订稿中的脚本后置建议。

## 背景

用户提供正在 WorkBuddy 使用的 `ppt-generation-expert`，明确要求算台从一开始支持。该目录含 SKILL.md、参考材料、公司模板与三个 Python 脚本，并依赖本地 ppt-master 工具链。仅支持提示词和已注册工具引用不能执行其工作流。

## 决策

1. 该类文件夹 Skill 是阶段 A 的必需兼容基线，不能要求先重写为算台专有 Skill 或以自建 PPT 工具替代后声称兼容。
2. Python 脚本/CLI、子进程、依赖与环境准备、外部本地工具链引用、任务目录文件创建/修改、质量门和最小 PPTX 成果登记随 A 建设。
3. 保留原始样本；宿主路径、环境及结果契约适配可在导入副本或宿主层进行，并记录差异。支持不等于在所有机器上原封不动执行其 WorkBuddy 命令。
4. A 的验收必须执行最小真实 PPT 管线；B 验证专家绑定；C 验证真实研究到汇报与修改。不能把 A 的脚本运行推迟到 C。
5. 本样本没有 MCP 依赖；MCP、其他解释器与在线市场范围独立确定。

## 约束与影响

既有 Agent Core 解耦、原件只读、成果版本、取消和终态原则保持。新增执行器的文件/网络限制、进程管理、依赖安装、凭据、报告适配及 Artifact 协议需先写实现 ADR；不能把 cwd 和输入路径检查称为完整沙箱。

公司模板用于用户本地验收，不因支持 Skill 而自动进入开源仓库或默认分发包。

样本静态核对、运行需求、已发现的契约适配点及验收标准详见 [运行边界](../reviews/2026-09-08-skill-runtime-boundary.md)。本轮只修订文档，不宣称已导入、已执行或已通过 PPT 验收。
