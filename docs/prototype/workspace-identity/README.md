# 工作空间身份与侧栏分组低保真评审原型

**评审原型 / D1–D10 待拍板 / 模拟数据。** 打开同目录 [index.html](index.html) 即可回看，无需启动应用或服务。所有数据为合成示例，交互只改变当前页面内存；刷新或关闭页面即清空，不使用数据库、localStorage、IPC、网络或模型。

依据：现状证据来自 `apps/desktop/src/main/db/app-schema.ts`、`apps/desktop/src/main/persistence/workspace-repository.ts`、`apps/desktop/src/main/ipc/register-ipc.ts`、`apps/desktop/src/renderer/src/App.tsx`、`components/WorkspaceSelector.tsx`；规范依据是 [领域模型](../../docs/02-domain-model.md) §2 与 [UI/UX 体系](../../docs/10-ui-ux-system.md) §6.1、§6.2、§9.1–9.3、§10.1。本文不另立产品或技术契约，拍板后再回写文档与 ADR。

## 评审步骤

1. **侧栏分组。** 点工作空间行只展开／收起，确认它不改变当前空间高亮；点「展示更多（5）」就地展开、「收起」折回；空空间展开后是一句行内说明而不是空白区域。
2. **窄栏。** 点「折叠为窄栏（88px）」，确认品牌行与导航收成图标、工作空间换成着色图标网格、任务列表整组隐藏。
3. **明暗两套色板。** 点「切到深色」，确认 8 档工作空间色在深色侧栏表面上仍然可读——身份色必须成对提供 Variant，这是 docs/10 §9.1 的硬要求。
4. **新建对话框。** 点虚线区依次模拟三个目录：名称自动填入文件夹名（已手改过则不覆盖）、选到 `2026Q3` 时出现「这个文件夹已经是…」内联错误；图标与颜色单选互斥，选中项的图标跟着所选颜色走。
5. **更多菜单。** 悬停空间行才出现「更多」，菜单里只有隐藏没有删除——`workspaces` 的子表全是 `ON DELETE CASCADE`，删空间会带走任务、成果、输入快照与记忆整棵子树。

## 待拍板 D1–D10

| 决策 | 本原型推荐 |
| --- | --- |
| D1 | Workspace 中文一律「工作空间」，中栏保留「任务工作区」。 |
| D2 | 侧栏列最近活跃的 8 个空间，其余进搜索浮层。 |
| D3 | 别名 ＋ 12 枚描边图标 ＋ 8 档成对色板，不做取色器。 |
| D4 | 不放「工作空间索引」开关：我们没有工作空间级索引这件事。 |
| D5 | 去掉「打开本地文件夹」，新建一律走对话框。 |
| D6 | 点空间行只展开收起，不切换当前空间、不打断运行中的任务。 |
| D7 | 本轮只「从侧栏隐藏」，真删另开一轮。 |
| D8 | 任务行 meta 只显示相对时间，进行中／失败补一枚微标。 |
| D9 | 窄栏显示着色空间图标，不整组隐藏。 |
| D10 | 新增一条分组查询通道，不复用全局 100 条名额。 |

- 本原型只覆盖结构与交互语义，不是产品实现，也不算产品验收、自动化测试证据。
- 几何与字号取自 `styles.css` 现值（侧栏 240px／窄栏 88px、行高 34 与 23、导航 13px、meta 12px、`gap` 取 4／8 档），但不代表最终实现能直接照抄；色值为示意，落地必须在 `appearance.ts` 与 `styles.css` 的明暗两套 Variant 里各出一份。
