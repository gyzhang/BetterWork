# 定时任务低保真评审原型 v0.1

**2026-10-03 光哥已通过 P1–P6 / 合成数据 / 生产功能未实现。** 原型按接手产品设计指令制作，用户本轮明确「我 review 了你的设计，我的意见是通过」。产品结论已记录；[技术契约](../../development/schedule-contracts.md)、[ADR-0037](../../adr/0037-scheduled-work-and-source-snapshots.md)、[Luna 任务板](../../development/tasks-schedules.md)与[编码提示词](../../development/schedule-coding-prompts.md)承接后续实施。技术提案不自动 Accepted，真实模型与提交发布另核对授权。index.html 保留用户通过时的视觉与交互快照，其评审工具文案不作为当前任务状态。

打开 [index.html](index.html) 即可评审，无需启动 BetterWork。顶部「评审场景」属于原型工具，不进入产品；产品导航沿用已确认的「专家」下方独立「定时任务」入口。单文件不加载外部资源，不访问 IPC、数据库、本地业务文件、网络或模型。所有按钮仅模拟页面内状态；会话内嵌版本只向宿主保存少量评审页面与草稿状态。

依据：[定时任务设计 v0.3](../../designs/scheduled-tasks.md)、[UI/UX 体系](../../10-ui-ux-system.md)、[工程规范](../../12-engineering-standards.md)。现有独立 Task/Session/Run、工作空间、专家与材料关系保持不变；本文件不另立技术契约。

## 建议评审顺序

1. **列表与入口。** 先看月度经营分析、周一 AI 调研、工作周报三个示例。确认首屏能看清执行专家、工作空间、周期、下次时间、最近结果；新版本用就地入口提示，不因新版本自动暂停。
2. **新建与来源。** 从「新建定时任务」进入整页分组表单：已有专家 → 长期工作空间 → 可选附加知识 → 工作要求与交付 → 时间与期间 → 启用。添加来源时分别查看单篇知识、知识集合和整个个人资料库；全库选择明确包含后续成员。取消来源选择不改变已选项；取消配置不改变已保存规则。
3. **时间与期间。** 改成每天、每周或每月，改变分钟；查看接下来三次计划。每月 31 日跳过没有该日期的月份。统计期间提供上一自然月、过去 7 天、本周至计划时刻、上一自然周、不指定；历史对比写进工作要求，不增加复杂对比表。
4. **六期历史。** 进入规则详情，查看同一工作目录下 4–9 月六次计划。展开工作要求和来源，分别打开缺材料、错过、目录保存失败、未生成产物、已停止、已生成记录；材料视图区分本期、历史对比、稳定参考，以及可用、已读取和成果采用。
5. **人工接续。** 「立即执行」以当前评审时刻确定期间；错过记录中的「为这一期执行」保留原期间，新建人工工作并关联原记录。已有任务优先打开原任务。修改补充要求后，查看材料、返回历史、再次打开本期，草稿仍在。
6. **失败与版本。** 切换启动前阻塞、执行失败/中断、重叠跳过、来源缺失、启用校验失败、编辑冲突；检查原因与下一步。目录保存失败只重试保存原成果 v1。专家更新先只读比较 v4/v5，再应用已存在修订；工作空间与附加知识保留，历史仍用当次绑定。
7. **启停、归档与通知。** 暂停只影响未来自动触发，停止本次单独操作；归档保留历史和文件。消息中心中的缺材料、错过与生成结果由人点击才导航。当前界面不会因后台结果主动切走。

## 已通过的产品决策 P1–P6

| 编号 | 已通过决策                                             | 理由与边界                                                                             |
| ---- | ------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| P1   | 列表以紧凑条目呈现，详情整页集中放规则摘要与历史       | 不增加常驻右栏；本期协作仍回到工作页。                                                 |
| P2   | 创建/编辑采用整页四组表单，不使用多步向导或小弹窗      | 专家、来源、工作要求、期间和启用条件能一起核对；保留统一页头和版心。                   |
| P3   | 每天/每周/每月 + 简单期间单选，显示三次时间预览        | 不引入自定义 cron 编辑器、月度文件绑定表或复杂期间模板。主期间与历史对比分开表达。     |
| P4   | 同一工作目录下默认使用「定时成果」子目录               | 默认位置已通过；命名、非覆盖、回执及边界见技术契约，未宣称存储已实现。                 |
| P5   | 对错过、缺材料、未生成目标产物、保存失败提供不同下一步 | 错过新建人工工作；已有任务继续协作；保存失败只保存原版本。产物存在不代表业务审阅通过。 |
| P6   | 专家更新用只读差异确认；保存并暂停与启用明确分开       | 调用绑定变更不编辑专家；启用说明本地进程条件、费用和结果审阅。                         |

上述呈现方式与默认值已通过；v0.3 已明确的产品方向保持。时区与生产库行为见实施契约 §4，并在 SC05-1 实测；原型没有证明 cron 库或夏令时行为。

## 页面与未来生产组件对账

| 页面/分支                    | 实施时复用的现有基座                                                                          | 状态与反馈                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 列表、详情、配置             | PageHeader / ScrollRegion / PageToolbar / ViewContainer / ListRow / SectionHeader / ActionBar | 对象状态用 Badge / StatusNote；首读失败用 ErrorPage，首次空集合用 EmptyPage。 |
| 专家、工作空间、时间与要求   | Field / FieldSelect / TextField / TextArea / WorkspaceSelector                                | 校验、来源缺失、冲突用 InlineError；失败保留输入。                            |
| 来源选择、专家差异、人工触发 | Modal / CheckList / BindingChip / Disclosure                                                  | 独立取消与确认，Esc 与焦点归还复用 Modal；不复制专家编辑器。                  |
| 本期协作、材料与成果         | App 工作页 / Composer / ContextPanel / SourceRow / RunSummaryRow                              | 过程按需披露；补资料仅影响本期，返回保留草稿。                                |
| 暂停、保存等当场结果         | TransientToast                                                                                | 不落通知库；原型主要用对象状态呈现，不模拟计时浮层。                          |
| 跨页定时运行结果             | NotificationService / 消息中心 / ToastHost                                                    | 统一持久化收口；成功留档已读，失败/部分完成按原机制处理。                     |

本原型是独立 HTML 线框，不 import 生产组件，不能把上表当作生产复用证据。SC09 仍需按 docs/10 §10.1.1 实际组合、测试和走查。
