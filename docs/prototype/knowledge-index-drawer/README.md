## 为什么出这份原型

2026-09-27 光哥在真实界面里指出：「索引与模型」和「最近作业（含已取消）· 3 条」都在知识页当前页面内展开，与全应用的界面操作不一致。仓库里已经有右侧抽屉基座（`Modal` 的 `sheet` 变体，「编辑模型」在用），所以候选出路是把配置面收进抽屉，而不是再发明第三种折叠。

## 评审步骤

1. **开合语义。** 点工具栏「索引与作业」，确认抽屉从右侧滑入、主页面灰化且点不动；按 `Esc` 或点左侧背板关闭，焦点回到入口按钮。这一步对应的是基座能力，不是新写一套。
2. **分区顺序（D2）。** 自上而下看五节：进行中的作业 → 语义检索 → 本机索引维护 → 最近作业 → 集合管理。确认「进行中」钉在顶端读起来顺，以及「集合管理」放在最后一节是否合适。
3. **代价（D3）。** 关掉抽屉后资料列表里没有任何作业进度，只有入口按钮上的状态文字；确认这个补偿够不够，还是要把「最近作业」留在页面里同屏看。
4. **清空（D5）。** 在「最近作业」小节标题右侧点「清空」，确认它只作用于这一节而不是整个抽屉，文案与已经上线的确认框一致。
5. **不变项（D4）。** 确认文档详情仍是页面内子视图、反馈落点仍是「当场确认自消／失败内联／结果进消息中心」，这两件事不因抽屉而改变。

## 拍板后的落地范围

- `KnowledgeView` 内联的 `.knowledge-admin` 面板与「最近作业」折叠组迁入 `Modal variant="sheet"` 抽屉。**实现落点与原型文字有一处出入并已按实际改动修正**：没有另建 `KnowledgeIndexDrawer.tsx`——抽屉内容要用的状态与回调全部在页面里，单独建组件只会得到一份二十多个字段的 props 转接，行为不变而文件更多。抽屉头与唯一滚动区由 `.knowledge-drawer-head` / `.knowledge-drawer-body` 承担，面板几何仍归 Modal。
- 工具栏入口改名并显示进行中状态；`adminOpen` 页面状态换成抽屉开合，Esc 层级顺序（局部提示 → 详情子视图 → 抽屉）随之调整。
- 作业进度在抽屉内继续按 `sequence` 合并；抽屉关闭时入口按钮仍显示「进行中 x/y」，不落库、不自建计时器。
- KM15 清单 §1.1／1.5／2.4／2.7／8.x／9.x 涉及「索引与模型」面板与「最近作业」的操作路径按新界面重写。
