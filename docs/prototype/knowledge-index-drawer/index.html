D1 入口与命名

现在工具栏上是「索引与模型」，展开后里面其实还藏着集合管理与最近作业——名字比内容窄。合成一个抽屉后建议改名。

建议：索引与作业

覆盖语义检索、本机重建、作业记录、集合管理四件事；有作业在跑时按钮上带「进行中 1」。

备选：索引与模型（不改名）

改动最小，但按钮名字继续少说一件事。

D2 抽屉分区顺序

自上而下五节，顺序按「先看到正在发生什么，再看到能做什么」排：

  • 进行中的作业（钉在顶端，带取消；没有就不出现）
  • 语义检索（开关、嵌入模型、普通／强制重建）
  • 本机索引维护（重建关键词索引、检查当前列表来源（N））
  • 最近作业（含已取消）· N 条 ＋ 清空 ＋ 查看条目
  • 集合管理（新建／改名／删除）

为什么把「进行中」放最上面：跑作业时你唯一想知道的是它到哪了；放最下面会被五屏内容推走。

D3 进行中作业的位置（这个方案唯一的代价）

抽屉是模态：打开时主页面 inert，你看不到资料列表；关掉抽屉回到列表时，又看不到作业进度。内联面板没有这个问题，但它把管理面板永久挂在页面上。

建议：接受这个取舍，用两处补偿

① 入口按钮上带状态（索引与作业 · 进行中 5/9），关着抽屉也知道在跑；② 作业终态照旧落库进消息中心，切走页面也不丢结果。

备选：只把「索引与模型」搬进抽屉，最近作业留在页面

进度可以同屏看，但页面仍留一处折叠，两个表面的不一致只解决一半。

D4 主页面留什么

  • 页头、工具栏（集合筛选、搜索、索引与作业、导入资料）、资料卡片列表、底部摘要行——都不变。
  • 删除：页面内联的 .knowledge-admin 面板与「最近作业」折叠组（全部进抽屉）。
  • 不变：文档详情仍是页面内子视图（返回列表保留搜索条件），它不是配置面，不该进抽屉。
  • 不变：反馈落点——当场确认 4 秒自消，可行动失败留内联，作业结果进消息中心。

D5 清空与确认

「清空」放在最近作业小节的标题右侧，不放在抽屉底部——抽屉底部是全局动作的位置，而清空只作用于这一节。确认框沿用已实现的那一条：

  • 标题：清空最近作业？
  • 说明：只清掉已结束的作业记录；资料、索引与本机原件都不受影响，进行中的作业不会被删除。
  • 按钮：清空记录（破坏性用 danger 文字）

D6 与既有约定的一致性

  • 复用 Modal 的 sheet 变体：inert、Esc、背板关闭、初始焦点、Tab 循环、焦点归还全在基座里，页面不重写。
  • 抽屉内允许开下拉与确认框（层级、Esc 交接、Tab 不抢焦点已由基座处理）。
  • docs/10 §7.4「知识页不新增常驻任务右栏或一级导航」不被违反：抽屉是模态覆盖层，用完即走，不常驻。
  • 列表行、徽标、空态继续走 ListRow／Badge／EmptyNotice 基座，不新造外观。
