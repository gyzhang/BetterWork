## 22:36 修复搜索配置「测试后保存丢失连接状态」（状态：完成，待验收）

- 背景：光哥反馈：先「测试连接」（通）再「保存并启用」，状态行仍显示「尚未验证」。根因是首次配置时测试先于保存执行，`recordSearchConnection` 的 UPDATE 影响 0 行（配置行还不存在），测试结果无处落；随后保存才建行，初始状态即为未测试。
- 变更内容：`recordSearchConnection` 改为 upsert（`ON CONFLICT(provider) DO UPDATE`）——测试时若无配置行则创建（保持未启用），并把**被测的那个 Key** 一并写入；main 的测试 handler 传入该 Key。这样「先测试→后保存」时保存逻辑发现 Key 未变化，保留「连接成功」状态。
- 关键决策：把被测 Key 写入行内而非只写状态——否则「测了新 Key、却用留空保留旧 Key 保存」时，连接状态与实际 Key 会不一致；upsert 只动 Key/状态/时间戳，不碰 enabled（启用仍只由保存动作决定）。
- 教训：「先测后存」的 UI 流程里，测试结果必须能独立于保存持久化，否则首次配置必丢状态；模型配置的 testModel 有同样的「仅已保存档案记录状态」限制，后续如反馈可同思路处理。
- 测试证据：`npm run verify` 全绿（typecheck + 55 个测试 + 构建）；新增回归测试「先 recordConnection 后 save 保留 connected」。人工验收（留给光哥）：设置→搜索→再点一次「测试连接」→状态行应变为「连接成功」；随后改 Key 保存应回到「尚未验证」。
