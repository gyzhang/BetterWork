# 工作日志

面向编码智能体与开发者的按天工作日志。它承担两层职责：记录当日事实与决策，以及把重复出现的教训回流为规则。

## 基本纪律

- **一天一个文件**：`docs/logs/YYYY-MM-DD.md`；当天已有则按时间顺序追加小节，不新开文件。
- **时间只来自 `date` 命令**；追溯历史事件的时间以 `git log` 时间戳为准，禁止凭印象写时间。
- 只记事实、决策与证据，不写过程流水账。
- 「教训」是资产：同一教训出现两次，就应考虑升级进 `.qoder/rules/` 或本文件（AGENTS.md），而不是第三次踩坑。
- 日志随对应任务的变更一起提交，不提交密钥或用户资料。

## 模板

    ## HH:MM 任务名（状态：完成 / 进行中 / 受阻）

    - 背景：为什么做
    - 变更内容：改了什么（文件/模块粒度）
    - 关键决策：取舍与理由
    - 教训：踩坑与规避（没有则省略）
    - 测试证据：typecheck / test / build / 人工验收结果
    - 相关文件：路径列表

受阻的任务也必须留痕，写明阻塞原因与下一步条件。
