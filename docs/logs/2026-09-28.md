- 关键决策：
  1. **反转 2026-09-26／27 三次写下的「不给 Button 造组件」**，走 ADR-0031 而不是静默偏离。上一轮我直接推荐造基座是没查文档就另立标准，被自己查出来后才补的决策记录。反转理由不是「组件化更先进」，而是实测证明**样式类方案缺一个封闭清单的执行者**：09-27 已经诊断出同一件事（9 颗裸按钮靠容器后代发力）并选了「搬到具名类」这条不造组件的路，那条路本身没错，但它没改变「下一个页面仍可以自己再造一档」，于是本轮又长出 5 套重复皮、7 处无高度档、8 颗压根没有规则一直按浏览器默认外观渲染。
  2. **`size` 不按 `variant` 给条件缺省**。主行动要不要比同排高一档是页面那一刻的选择，写成显式 `size="lg"` 才可解释——本轮起点就是档位差没被写下来。
  3. **`.list-row-actions :where(button)` 的兜底皮删掉**。它原先替行内动作补一份「行内文字按钮」，于是页面不写档位也能长得像按钮；现在行内动作一律 `variant="quiet" size="sm"`，槽位只留排布。
  4. **补 `link` 第八档**：`.capability-locate-link`／`.material-global-toggle`／`.back-button`／错误条里的「重试」说的是同一件事，但一直没有名字，于是四处各造一套（`padding` 从 `0` 到 `5px 6px`）。同构的一例：PageHeader 的「返回」在成果页无底无框、在专家页有底有框——**同一个导航动作在两个页面长成两种控件**。一档形态没有名字，就等于没有这一档。
  5. **`tone` 从「只有 outline 读」扩到三档带边框 ＋ quiet／link**：页面原先用 `.text-button danger`／`.danger-text` 盖字色，收进基座后特异性低于 `.btn[data-variant]` 会静默失效——所以把它升成档位而不是留一条容器改色规则。
- 教训：
  1. **推荐方案之前先查仓库有没有写过相反的决定**。我上一轮把「造 Button 基座」当推荐交出去，docs/10 §10.1 那行「不再单独组件化，避免只为包一层壳而增加第二处真相」就躺在里面，09-27 审计和日志还各重申一次。查得晚的代价是多写了一份必须解释反转的 ADR。
  2. **脚本化批量替换压空白会吞掉注释后面的代码**。第一版迁移脚本对开始标签做了 `.replace(/\s+/g, ' ')`，把多行 `onClick={() => { … // 说明 … }}` 里的 `//` 注释拉成一行，注释之后的全部代码被吃进注释里，App.tsx 直接语法崩。tsc 报了 7 行错才暴露。结论：批量改 JSX 属性时**只摘目标属性，其余文本原样保留**，交给 prettier 重排。
  3. **CSS 块解析必须处理跨行选择器**。第一版清点脚本按「行尾是 `{`」认块，漏掉了 `.knowledge-search button,\n.memory-search .clear-search {` 这类逗号续行，当场少报一处（我给光哥报的「11 处」实际是 12 处）。改成花括号配平 ＋ 选择器缓冲后才对得上。
  4. **默认档位会误伤形态**。第二遍「没有 className 的裸按钮统一给 quiet／sm」把外观预览的两格选择卡也收成了 `Button`——它们的 `className` 是 `{cond ? 'selected' : ''}` 表达式，正则只匹配 `className="..."` 就当成裸按钮了。批量迁移的默认值必须配一次全量 diff 复核。
  5. **护栏绿了不等于它在咬人**。五条新护栏各做一次变异（加裸按钮、CSS 多一档、抽掉某档 `min-height`、复活 `.examples button`、页面给 `.btn` 补 `font-weight`），逐一确认门禁转红并还原源文件后才继续。
