## 08:23 卡片悬停边框收进基座＋专家署名补来源标注（状态：完成）

- 背景：H／H2 轮人工验收后光哥目测技能页与专家页，报出两处不一致——① 技能页卡片悬停有品牌色边框、专家页没有；② 技能卡署名标「用户 Skill／内置 Skill」，专家卡没有来源标注（无署名时还显示含糊的「本机」）。
- 变更内容：
  - ① 根因是悬停边框只写在技能页的页面级规则 `.skill-card:hover` 上，基座 `.card` 没有 `:hover`，专家页没传类名所以没有效果。把 `border-color: var(--brand)` 下进基座 `.card:hover`，删页面级规则；`SkillsView.tsx` 移除失效的 `className="skill-card"`，`SkillsView.test.tsx` 选择器改 `.card`。
  - ② `ExpertsView.tsx` 新增 `sourceName` 常量（与技能页同构），`expertByline` 改为「来源（用户／内置）· 作者（有则显示）· v修订号」，作者字段 hint 的「本机」改「用户」；`ExpertsView.test.tsx` 署名期望同步。卡片与详情两档共用这一个函数，一处改两档生效。
- 关键决策：悬停边框是**所有卡片的通用事实**，归基座而不是页面钩子类——领域钩子只留位置与内容差异，这正是「一道缝一把尺」的口径；效果与技能页一致后，成果页等其他 `.card` 表面同样获得该悬停反馈。
- 教训：H2 轮把「事实」收进 `EntryFacts` 配对件时，悬停边框这类**通用外观**仍散在页面级 CSS 里，专家页照抄时又丢了一次——与 G4「列表档丢署名」同一形状。配对件收编的是内容事实，外观事实也要收进基座，否则下一次照抄还会丢。
- 测试证据：全量 `npm run verify` **EXIT=0**（lint／format:check／typecheck／test／build 五关全过），functional 172 文件／1529 用例＋heavy 6 文件／133 用例；光哥目测验收通过（悬停边框两页一致、来源标注到位）。
