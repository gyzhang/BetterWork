## 11:05 档位纪律批次①：动作排契约＋`size` 必填＋护栏自身的一处盲点（状态：完成）

- 背景：光哥连着两问——① 技能页页头「+ 导入 Skill」与专家页页头「+ 新建专家」为什么不一样大；② 全仓没几个页面，按钮大小／字号／间隙这类初级不统一为什么反复出现。要求先全面排查、举一反三摸家底，再定规矩与门禁，不许先动手改。
- 排查结论（家底）：**不是没有规范，是规范只写了「存在」没写「缺席」**。三条根因：`size` 有隐式缺省，「不写」成了第三种高度（89 处按钮调用点里 6 处没写，其中 4 处是主按钮，静默渲染成 32px）；同档规则钉在组件名 `ActionBar` 上，管得住 8 排里的 1 排，而页头那一排从来不在任何约束里；退役皮类的 CSS 规则已删、`className` 却还挂着（实测两处：`.chip-button`、`.knowledge-research-button`，那两颗按钮一直在按 `secondary` 渲染）。
- 变更内容：
  - 契约单位换成**动作排**：`ActionBar.children`、`PageHeader.leading`／`actions`、`SectionHeader.actions`、`Card.footer`、`ListRow.actions`、`PageToolbar` 直接子节点七个槽位登记进 `ACTION_ROW_SLOTS`；选档按排的性质给缺省（页头与页面区块头 `lg`／动作条·卡片页脚·工具栏·表单尾排 `md`／行内与面板小节头 `sm`），**`lg` 只住在页头与区块头**。
  - `Button`／`AsyncButton`／`Tabs`／`SegmentedControl`／`FieldSelect`／`IconButton` 的 `size` 全部改为**必填、无解构缺省**；CSS 给 `.tabs`／`.segmented-control`／`.field-select-trigger` 补出三档几何（原先三件各钉死 28／28／32px，没有档位 API 就必然与旁边的主按钮混档）。
  - 混档收口 31 处调用点（含光哥对比的那两页页头，现同为 `lg`），两处退役类名改回 `variant="chip" size="sm"`；`IconButton` 补 5 处生产调用点与基座自身用例，观感不变（一律 `size="md"`）。
  - 门禁三条：动作排同档（含「省略 size」单独报一条）、控件基座 `size` 必填＋CSS 档位集合穷举（`.icon-button` 按命中区轴单独核对 `sm／row` 覆写）、退役类名不得留在 `className` 上；ADR-0031 按「原判断不改写、同日就地修订」的写法修订，docs/10 §9.10 与 §10.1 台账同步。
- 关键决策：删掉 ADR-0031 老第六条（钉在 `ActionBar` 名上的旧断言）而不是与新断言并存——同一份契约的两处实现里，弱的那一处会给人「已经查过了」的错觉。
- 教训（本轮最值钱的一条）：**删旧断言之前先证明新断言拦得住同一件事，这一步抓到了护栏自己的盲点**。`childrenRegion` 的两个正则在游标处没锚定，`</Button>` 那里拿整段余文匹配 `</ActionBar>` 也算命中，区段被截断成「这一排只有一个控件」——`ActionBar.children` 与 `PageToolbar.children` 两档从写下起就没真正查过（表达式槽位走另一条路径，所以页头那一排一直有效）。锚定后重跑变异：混档报「32／36px」、省略 `size` 报「隐式md」，还原后全仓绿。同源的第二处是图标轴的隐式档被当成 `sm`（23px），于是「一颗隐式 28 ＋ 一颗显式 `sm` 23」这种真落差会被判成同档，已改为 `md`。

## 11:31 记忆冲突条那一排搬进 `ActionBar`：同排同档，容器不再靠换行凑（状态：完成）

- 背景：批次①收口时留了一处我称之为「有意例外」的地方——记忆冲突条里的「确认两条并存」仍是 `sm`，理由是它被一条 `width: 100%` 的说明段落顶到独立一行、不与「替代…」同排。光哥拍板「我认为该同排」，并授权把容器一起改。
- 变更内容：
  - `views/MemoryView.tsx` 的 `ConflictPair`：`.memory-conflict-actions` 那个 `flex-wrap` 容器拆掉，「替代：保留哪一条」与「适用条件说明」成为 `.memory-conflict` grid 的两个 `Field` 兄弟；说明输入原先只有 `aria-label`、没有可见标签，现改走 `Field` 的 `controlId`＋`useId` 与 `htmlFor` 关联，码点计数移进 `Field` 的 `hint` 槽。两颗动作按钮进 `<ActionBar as="div" label="处理这组口径冲突">`，同为 `size="md"`；那段讲「替代要求同一规范范围／写不出条件别确认并存」的长说明移到动作条上方，读序上先给条件再给动作。
  - `styles.css`：删 `.memory-conflict-actions` 整条（行骨架交回 `.memory-conflict` 的 `gap` 与 `ActionBar` 基座），两条选择器完全重名的 `.memory-conflict-actions input` 合成一条 `.memory-conflict-note-input`，几何仍全部取 `--control-*`（批次③由 `TextField` 接手）；`.memory-conflict-hint` 去掉那条当作换行开关用的 `width: 100%`。
- 关键决策：不新增槽位、也不给 `ActionBar` 加「底对齐」档位，而是**让这一排落到已经登记过的那七个槽位里**。上一轮定的契约是「护栏按槽位表查」，页面自己写 `display: flex` 把两颗按钮并排，护栏对它是盲的——留在这儿就是一个查不到的混排点。docs/10 §9.10 与 `.qoder/rules/betterwork-ui.md` 同轮补一条「一排要么落在槽位里，要么不存在」。
- 教训：「有意例外」这个词要慎用。我上一轮把这处 `sm` 记成例外，依据是「它们不同排」——而让它们不同排的正是那条 `width: 100%`：一个排版 hack 被当成了契约的依据。真拍板之后看，改容器只是把三段说明从行内搬到行外，比我在提议时说的「我把容器一起改」轻得多。
