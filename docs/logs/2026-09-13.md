## 10:16 ClawBible Desktop 专家定义调研（状态：完成）

- 背景：光哥要求添加专家功能，并指定先调研 ClawBible Desktop 中专家的定义（人格、技能、工具）。今早已产出设计 v0.1 与 Proposed ADR-0014，但 §4 的参考项目核对只到字段级，未回答“工具到底是专家的哪个字段”。本轮做源码级深调研，基线 ClawBible Desktop `724f1911`（工作区干净）、BetterWork `94263d2`。
- 变更内容：新增 [ClawBible Desktop 专家定义调研](../reviews/2026-09-13-clawbible-expert-definition.md)（数据结构、人格、技能、工具、缺失维度、内置分发、运行链路、取舍建议、开工前三问）；在 [专家工作模型](../reviews/2026-09-13-expert-work-model.md) §4 加入指向本稿的补充说明。只改文档，未动代码。
- 关键结论：
  - **专家 = 一行 DB 配置**：`role` + `description` + `systemPrompt` + `boundSkills` + `source` + `enabled` + `defaultPptScope`；没有 updatedAt、没有修订、没有知识范围、没有 MCP 字段、没有模型字段（模型在 `conversations.model_id` 与 `task_overrides.modelId`）。
  - **人格只有 systemPrompt 生效**：执行时只拼 `config.systemPrompt + Skill 指令`，`role` 全链路不进模型输入，仅用于搜索命中与前端图标匹配。内置提示词走 Vite `?raw` 内联的 8 个 `.md`，DB 那列成死数据。
  - **工具不是配置维度，是曾经有过后来删掉的**：`experts` 表原有 `bound_tools`/`bound_mcps`，ADR-030 判定“技能抽象形同虚设”后物理删列（`database-migrations.ts:755`–`:779`）；现行工具集合 = Tier 0 基线元技能 ∪ boundSkills 展开 ∪ 逐条消息临时 `extraMcpTools`。基线元技能被禁用时还有硬编码工具名兜底（含 file_write 与 shell_exec），等于停用与撤销可被绕过。
  - 内置专家同步是 UPDATE 覆盖 + 孤儿硬删（连带硬删记忆），与 ADR-0011“不静默覆盖用户副本”直接冲突；“万金油”是把一次性能力组合塞进常驻实体的特殊专家。
  - 同一 Expert 概念在参考项目里有三份定义（shared 遗留、service 真相、renderer 裁剪），是协议单源要防的反面样本。
- 决策：本稿只出调研与建议，不批准实现；把三件开工前必须定的事（工具的三种语义、专家是否存带修订的 Skill 预设、首版做 E1 还是 E1+E2）交给光哥定，再决定 ADR 与任务卡怎么写。
- 教训：
  - **用 `perl -pe 's/"/ ... ; $c++/ge'` 批量把 ASCII 引号换成中文弯引号，把整篇文档写坏了**：`s///e` 的替换体是 `;` 分隔语句列表，**返回值取最后一条语句**，于是三元被丢弃、每个匹配点被替换成全局计数器数字（`如0最多 10 次搜索1`）。工具返回 success，`git diff` 当时看不出错，`npx prettier --check` 依然通过——中文/符号损坏不会被格式化工具捕获，只能整文件重写加逐行回读。批量标点转换禁止用带 `;` 的 `-e` 单行脚本，改为整文件 Write 重写。
  - 重写后必须按字面 grep 抽样回读被损坏的几行，而不是只看替换符计数；`\ufffd` 计数为 0 不代表内容正确（本次损坏是数字，不是替换符）。
- 测试证据：新文档 ASCII 双引号 0 处、`\ufffd` 0 处，`npx prettier --check` 两个文档均通过；文档内 3 个相对链接目标文件存在。未运行产品构建（本轮无代码改动）。
