## 22:29 A15 取消、撤销与启动恢复（状态：代码完成，自动测试通过）

- 背景：A14 完成了资源、文件与执行工具，但 RunService 的终态事件直接广播，没有给 SkillExecutionService 留出 finishRun 收口窗口；应用退出时也没有取消活跃 Run 并等待子进程清理的机制；撤销信任时不级联取消该 Skill 的活跃执行。
- 变更内容：
  1. **RunService 终态收口**（`run-service.ts`）：`consume()` 在事件循环中遇到终态事件时暂存而不立即广播，先调用 `skillExecutionService.finishRun(runId)` 等待子进程清理完成，再广播终态事件；finishRun 失败时合成 `run.failed` 事件。

- 关键决策：终态事件暂存而非丢弃——finishRun 成功后原样广播，失败时替换为合成的 run.failed；`before-quit` 是同步事件，异步清理是 best-effort，错误只 log 不阻塞退出；`createTrustedSkill` 必须保存 runtime profile 使 `profileHash` 非 undefined，否则 `getGrant` 的 early return 导致 trust 校验失败；ESLint `no-floating-promises` 配置 `ignoreVoid: false`，因此 `before-quit` 用 `.then()/.catch()` 链而非 `void`。
