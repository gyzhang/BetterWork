- 关键决策：
  1. **规范必须是可执行的，不能只是文档**。配置即规范，文档只解释「为什么是这条」；两者冲突时以配置为准并同时修文档。这是「只能有一份规范」唯一可靠的实现方式——靠人记住的规范一定会分叉。
  2. **规则误报要改配置并记录理由，不能靠逐文件 disable**。三处策略性关闭全部写在配置注释里：`require-await`（接口签名要求 async，同步实现必然无 await）、`prefer-nullish-coalescing` 对字符串放行 `||`（空串回退是有意的，机械换 `??` 会引入缺陷）、React Compiler 的优化类规则（本项目未启用编译器，强推手写 useMemo 只产生噪音）。测试文件按「文件角色」统一放宽非空断言与 unsafe 系列——这是一条策略，不是逐文件例外。
  3. **外键与迁移必须一起做，且要能拒绝脏数据**。补外键要重建表，重建前先 `foreign_key_check`；发现孤儿行整条迁移回滚、不打版本戳，宁可启动失败也不把用户数据留在半迁移状态。历史库走「识别 → 对账到 v1 → 打戳 → 继续增量」，因此不会漏掉 v2。
  4. **错误处理只给两个出口，不给第三个**。`reportAction` / `trackAction` 按「失败后用户能否采取行动」二选一；`ignoreVoid: false` 让 `void promise` 无法通过 lint，从机制上消灭静默失败。
  5. **工作会话状态刻意留在 App**。它同时牵动任务列表、上下文面板、成果列表与通知跳转，抽成 hook 只会变成双向回调传递，耦合不减反增；而外观、资料库、模型设置三簇是自包含的，抽出后视图里一个 IPC 调用都不剩。
  6. **UI 违规集中一次收敛，不夹带进功能**。字号与动效都改变观感，混进功能切片会让验收无法归因。
