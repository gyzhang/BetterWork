## 14:50 CI 焦点环红定性并修在共享层：减动效降级把环冻回盒外（状态：完成）

- 背景：光哥说「要，推吧」，`8be2cdd` 上去换 run #245（`36971277546`）的回答。runner 报 `帧数 1 · 首帧同值`——**上一节的时序假设被自己买的读数推翻**：那个值是稳定的，不是读得太早。同一批环境读数里 `prefers-reduced-motion: reduce` 为 `true`，就是线索本身。
- 复现：本地拿真构建产物起离屏窗口，只模拟这一个媒体特性，同一条断言立刻读出与 runner 一字不差的四元组 `3px / 0px / solid / rgb(29,36,32)`，而 `element.getAnimations()` 当场给出三张 running 的 `CSSTransition`——`outline-color`、`outline-width`、`outline-offset`。反向注入 `transition-duration: 0s` 后同条件读回 `2px / -3px`、过渡归零；只压 `animation-*` 或只改 `scroll-behavior` 都无效，逐条排除到此为止。
- 根因：`styles.css` 的降级块按 docs/10 §9.9 那句「动效与过渡一律压到 0.01ms」写成 `* { transition-duration: 0.01ms !important }`。`animation-name` 初始值 `none`，设时长造不出动画，那两行无害；`transition-property` 初始值却是 **`all`**，给 `*` 设非零时长等于替每一个没声明过渡的元素声明「所有属性都动 0.01ms」——**「减少动效」的降级反过来开启了动效**。焦点环正落在这批本来不动的属性里，起始值就是聚焦前的 `3px/0px/currentColor`，环又跑到盒外，正是 ADR-0035 第一轮消灭的那个形状。离屏窗口时间线不推进，0.01ms 也走不完，所以读数稳定地错；真实窗口一帧走完，界面上几乎看不见——但聚焦那一帧确实画在盒外，贴边的 `overflow` 裁的就是那一段。
- 旁证自洽：按钮一直绿，因为 `styles.css` 给 `button/input/textarea/select/.list-row` 显式列了五个过渡属性、不含 `outline`。同一句 CSS 两种命运，分岔点就是「有没有自己声明过 transition-property」——这也解释了此前四轮排查为什么每次都只证伪掉一条路径：坏的从来不是那条规则，是另一条规则的作用域。
- 变更内容：① 共享层一处——降级块 `transition-duration` 取 `0s`（`animation-duration: 0.01ms` 与 `animation-iteration-count: 1` 保留，那两轨不产生动画且留着 `animationend`）；② 文档两处错源同轮改掉：docs/10 §9.9 那句「一律压到 0.01ms」改写为「动画压到 0.01ms、过渡取 `0s`」并给出初始值不对称的理由，docs/12 §8 补「两轨不可互换」的判据；③ 护栏第 6 条（`standards/coding-standard.test.ts`「界面观感基线 › 全局动效降级只能关过渡、压动画」）：作用域落在 `*`（含伪元素）的 `transition-duration` 只能取 `0s`，除非同一条规则显式声明了 `transition-property`——拦的是配方本身，不是某一行历史；④ 夹具注释与 [ADR-0035 第三轮](../adr/0035-focus-ring-inside-control-box.md) 记录探针表与链条，[ADR-0036](../adr/0036-macos-only-platform-scope.md) 那条「未结」改「已结」，ADR README 的 0035 行补一句第三轮。
