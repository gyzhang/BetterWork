## 11:13 平台范围定死为 macOS、CI 门禁迁到 macOS runner（状态：完成）

- 背景：光哥问「推送到 github 后会执行 ci 门禁？」。查下来门禁确实在跑（`.github/workflows/verify.yml`：PR 与 `main` 推送触发，跑 `xvfb-run npm run verify`），但 `main` 无分支保护所以红不阻塞任何东西，且从 2026-10-01 11:51 起连红五次。他随后定下范围指令：**项目只关注 macOS，其他操作系统暂不关注、也不兼容**。上一节 10:36 那笔改动由本轮按他的指令先落为提交 `4a0d79c`，未夹带进本轮变更。
- 变更内容：① workflow 的 `runs-on` 由 `ubuntu-latest` 改 `macos-latest`，去掉 `xvfb-run --auto-servernum` 前缀与那行虚拟显示注释；② 删 `scripts/fixtures/ui-render-runner.ts` 里 `process.platform === 'linux'` 追加 `--no-sandbox` 的分支；③ `SkillsView.test.tsx` 加 `beforeEach`，逐用例装一份全新内存 storage；④ 新增 [ADR-0036](../adr/0036-macos-only-platform-scope.md)，`AGENTS.md` §3 加平台范围硬约束一条，`docs/adr/README.md` 索引补一行，`docs/11` 两处（「Linux 使用 xvfb-run」「macOS 和 Windows 基础打包验证」）与 `docs/07` 范围段＋未达成项、`docs/10` §9.13 字体族那句同轮对齐。
- 关键决策：四类 CI 红先逐条归因，不就地放宽任何断言——三类（Electron 在 Ubuntu 上 `FATAL:sandbox`→SIGTRAP、codesign-only 的文案断言、8.5s 文件里一条 ESLint 门禁用例撞 5s 超时）是 runner 测错平台的产物，随迁移消失；第四类是真实缺陷，不因换平台豁免，独立修在测试层。`expert-release-preflight.mjs` 的非 macOS 守卫**保留**：那是产品语义（签名校验只在 macOS 有意义），作用是报错而不是伪造通过，与「为别的环境变绿而绕路」正好相反。
- 验证：本地 `--project functional` 整档 175 文件全绿，证明 CI 那四类红没有一类是本地可复现的代码回归。探针（一次性文件，跑完即删）打出 darwin＋jsdom 30＋vitest 4 下 `typeof window.localStorage === "undefined"`（url `http://localhost:3000/`）。成对实验两发：给 `SkillsView.test.tsx` 在模块加载时装一份**跨用例持久**的 store → 精确复现 CI 那两条红（`× switches between card and list view`、`× returns to browse`）；同样留着持久 store 但让 `beforeEach` 换新 → 12/12 绿。承重的是「逐用例换新」，不是碰运气换环境。
- 待观察：macOS runner 首跑的 `npm ci`（`better-sqlite3` 编译）耗时与 15 分钟 `timeout-minutes` 是否够，读数记回 ADR-0036。公开仓库的 macOS 托管 runner 不额外计费，所以迁移没有成本代价。
- 边界：`main` 不设分支保护，同日由光哥定案——这是单人项目，`main` 就是他的工作分支，没有也不需要他人协作；门禁的红当信号看，真正拦人的是提交前那次 `npm run verify`。字体栈里 `'Microsoft YaHei'`、`'Segoe UI'` 两个回退名**未删**：它们是 CSS 回退顺序而不是兼容分支，删了无收益，而 `docs/10` 那句已改成「不作为适配目标或验收项」。ADR-0010 与 skill-executor 设计稿里的 Windows 叙述属历史记录，按「ADR 一经 Accepted 不重写历史」不回改。
