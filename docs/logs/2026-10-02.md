- 关键决策：用 §9 现成判据，不新建机制。没选「把这两个文件挪进 `heavy` 串行档」：`ui-render-check.test.ts` 整文件墙钟才 3.5s，远低于 ≥20s 的收录门槛，挪档得先改档位判据，动静比放宽单条大得多，而问题从来是单条预算贴太紧。
- 验证：安静机两轮实测高度可复现（ESLint 首条 1825／1846ms；CLI 三条 541／1234／1609ms 与 546／1235／1584ms）。变异验「预算真的接在用例上」：把两个常量压到 1ms 重跑 → 四条全部红成 `Test timed out in 1ms`，其中三条是阻塞式 `spawnSync`，说明超时判定发生在子进程返回之后，所以抬预算是把随机红消掉而不是换个地方红；还原 20_000 后 39／39 绿。完整 `npm run verify` 退出 0、175＋6 文件全绿——这一轮并发下那条冷加载用例实测 4705ms，距默认 5 秒只差 295ms，不放宽迟早再红第三次。
- 边界：没改任何断言判据，没动 `HEAVY_TEST_FILES` 门槛，也没动 `testTimeout` 全局默认（放宽只落在确实昂贵的四条上）。runner 上 `jade-light-760` 的焦点环红仍待定性，靠的是上一节那三项读数，与本轮无关。未推送远端。
