# AI+Human 工作流第三方审计

审计日期：2026-10-02。起始基线 `99c5d14e4770120bbd85683f1cc0bc8baa9cfcec`，工作树干净。本次由 Codex 从产品、UI 与工程执行三个角度复核 Qoder 本日治理；报告记录审计事实，不建立第二套规范或改写产品任务验收状态。

## 1. 完成度判断

**Qoder 已完成有效的规则与门禁基础治理，项目可以继续增量开发；现有证据仍不足以证明 AI+Human 全流程长期稳定闭环。** 本轮还发现了会影响工具加载、推送有效性和任务判定的遗漏，并已修正明确问题。

不建议用护栏数量或单个完成百分比代替评价：规则、共享组件、实际页面和最终产品交付有不同证据。本次判断如下。

| 维度 | 完成度 | 依据与限制 |
| --- | --- | --- |
| 工程规范与可执行约束 | 较成熟 | docs/12、配置、结构护栏与 verify 已形成闭环；有实际反例验证。扫描仍只能判断其覆盖的形态 |
| UI 语言与共享基座 | 较成熟 | docs/10 有真实导出台账、页面组合流程、Token/几何/反馈/浮层契约；16 组共享组件真实渲染通过 |
| Codex/Qoder 指令一致性 | 基本成型，本轮补缺 | 原 Qoder glob 元数据、贡献指南和跨平台旧前置仍有遗漏；本轮修正并增加入口与回归 |
| 提交、推送与远端验证 | 基本闭环，本轮加固 | 当前远端 SHA 全绿，本机 hooks 已接入；原钩子未保证被测工作树就是推送提交，本轮补实际对象校验 |
| 实际产品页面与人工验收 | 尚未收口 | 合成组件冒烟不能证明完整页面、失败恢复、真实 Run、对比度与签名安装；已有任务板仍保留这些边界 |
| 长期漂移治理 | 有可运行机制，尚有盲区 | drift:check 能复查配置、日志文件、未推送提交和静态规模；不是规则语义、例外合理性或全部任务证据的审计器 |

从高级产品经理视角，最有价值的成果是 AI 已有可查的任务、契约和失败语义，可以持续开发；不足是一些入口仍把人类拉回技术维护或把局部全绿写成整体完成。从 UI 设计师视角，共享语言已经足够稳定，下一步应提高实际页面完成工作的效率和状态可信度，不需要再换组件库、按行数拆文件或另写一套规范。

## 4. 仍需改进的地方

### 4.1 AI 应承担页面检查，人类保留最终验收

docs/10 §10.1 已明确“页面/分支 → 组件 → 状态/反馈 → 自动检查与走查 → 未验项”。应该把它作为每次 UI 开发交接的实际证据，而不让人类替 AI 扫基础布局、找未处理异常、追 CI。人类只判断取舍并验收可复查结果。

后续最值得设计的一项增量，是使用合成数据/注入 IPC 覆盖**实际生产页面**的主要用户路径，优先成果正文与版本、知识列表/详情/失败、专家参考选择、记忆记录与提炼状态。保留长中文/英文路径、受支持窗口、明暗/减动效与失败恢复证据。先做少量关键路径，逐步扩展，不把现有固定组件夹具改名为“全页面验收”。真实模型语义、屏幕阅读器与签名安装仍走原专项。

### 4.2 漂移检查要比较语义变化，不只比较数量

当前脚本只统计例外 reason 标记：在数量不变的情况下扩大白名单、改理由或删除一条再加一条都可能仍绿。工作日志也仅检查文件是否存在，当天漏追加本轮任务不会被识别；hooksPath 正确也不证明没有通过环境变量停用 Husky。本轮没有把这些绿色读数写成更强保证。

下一步可评估例外清单指纹/具体差异、批次证据和实际 hook 运行读数；先说明判据、误报边界与维护成本，再实施。`--save` 必须在发现已处理或取舍有理由和证据后使用。不能把“新增更多规则”或“重新留基线”当成改进本身。bench 不在 verify 是合理隔离，但性能变化的任务/里程碑应由 AI 另跑对应基准，不因 verify 绿而跳过。

### 4.3 减少规则重复与无效阅读成本

新会话应先读 AGENTS 路由与对应唯一契约，不要求把全部历史报告当现行任务。CONTRIBUTING 已收缩，UI 台账已经可用；后续继续把长规范中的落地过程移回带日期报告/日志，保留规则、理由和指针。AI 修改例外或标准时同时审核文档、配置、护栏及反例，不能只补一条针对旧类名的防复活断言。
