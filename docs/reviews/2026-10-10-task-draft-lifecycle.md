## 实施边界

在 Renderer 内集中 Task 草稿与选择身份。`useTaskDraft` 以 reducer 管理专家、技能、材料、记忆排除和 MCP 绑定；已保存的 TaskContextRevision 是 CAS 基线，本地编辑字段是下一次发送的工作草稿，不把保存回执当成重新加载。输入正文仍由 Composer 就地编辑，草稿所有者维护重挂载读取、重置代号与记忆预览正文，避免每次输入都重绘 App。

`useTaskSelection` 同时更新可见 Workspace/Task/Run 与同步身份，集中选择代际和有效性判断。每类读取仍保留自己的最新请求代号；Task 历史有独立代际，不因同 Task 的 Run 选择或启动新 Run 的代际变化而过期，同类读取仍采用后发请求优先。App 继续负责事件合并、跨区域 IPC 装配、导航和反馈，D2 再评估消息投影、成果保存语义与上下文面板组合。

不改变 IPC、数据库、运行授权、核心领域关系或安全边界，不增加通用请求框架、依赖或规范例外，无需新增 ADR。专家配置、材料精确引用、记忆排除 CAS 与定时来源契约沿用现行文档。

## 保持的行为

- 新建 Task 清空配置与正文；切 Workspace 开新 Task 保留当场正文和已选技能，清除其他 Task 配置。
- 恢复 Task/Run 的上下文以同一份快照替换草稿；没有上下文的旧 Task 只恢复最近 Run 的技能，不补造专家身份。恢复期间清除上一 Task 的配置。
- 召唤专家只准备当前修订、适用 Workspace 的参考材料与预设；从成果版本开始只带来源身份和精确版本材料，不复制旧 Task 的权限。
- 保存回执只更新 CAS 基线；记忆排除保存同时更新排除项，定时续作保持本地补充草稿。同 Task 的定时导航不清空输入框。
- A→B→A、迟到启动回执、材料请求取消与重复读取保持过期保护；历史快照继续与流式事件按稳定标识合并。启动中切走仍完成原启动请求，但迟到回执不得改写新选择或正文。
