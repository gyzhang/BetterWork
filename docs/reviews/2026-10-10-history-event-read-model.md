# E6：历史重放与来源事件读模型整理（R10）

## 范围与现行口径

用户授权推进 E6，批次基点 `43da0513cf2abd300f39e4589fbd342dcca67e8d`，分支 `codex/e6-history-event-read-model`，沿用当前 checkout。

历史重放为 Task 下每个候选 Run 调用完整 `listEvents`；助手来源存在性与人工来源正文也扫描完整 journal。自动提炼的前轮消歧回答重复相同非空消息扫描。完整事件会逐条 JSON 解码和 Zod parse，带入不消费的 reasoning、工具输出和增量。

保留三种现行含义：历史重放和前轮消歧取最后非空 message.completed；人工助手来源取最后一条 message.completed，并检查无后续工具、指定 eventId 和第一条已有 run.completed 的正文一致性；已保存记忆的助手来源可用性仅检查指定 Run/eventId 的事件仍存在，不新增最终回答要求。空尾消息、缺终态事件、多个终态事件的既有区别不统一成另一套规则。

## 实施边界

增加 RunRepository 内部候选过滤、精确事件读取、最后消息/最后非空消息、第一条完成事件和后续工具存在性查询。目标正文使用协议 Schema 校验，核对 journal 元数据；工具存在性只查完整类型/sequence 范围的元数据。没有 IPC、表结构、迁移或算法版本变化。

历史 Run 的上下文、快照、已选材料、实际读取及直接/传递依赖仍完整读取，连续安全后缀、边界理由与预算保持。没有依赖 LIMIT、来源摘要截断、缓存或安全门禁放宽。其他冲突枚举与知识检索留后续任务。

## 实现与 Review

候选查询把原先 JavaScript 的 Task、completed、当前 Run 排除、创建时间和完成时间条件移到 SQLite，保持 createdAt 正序和原有同时间顺序；当前 Run 不存在时仍不加创建时间边界，completedAt 缺省仍可入候选。查询不加 LIMIT。

最后非空消息用按 sequence 倒序的消息完成事件游标，找到后立即关闭，不加载其他事件正文。人工来源读取最后消息、第一条完成事件，并用五类工具的完整 sequence 范围存在性查询；指定来源使用 Run/eventId 联合定位。每个目标载荷都经过协议校验，并比对 id、runId、type、sequence 与 journal 列。定向查询只解释其所需事件；无关损坏事件不再阻断该查询，目标损坏或身份不符仍明确失败。现有 UI 完整 journal 入口保持。

审查确认：历史/消歧仍允许空尾消息前的非空回答；人工来源遇空尾消息必须拒绝，并沿用缺 run.completed 的兼容规则。多个完成事件仍检查第一条，不能改成最后一条。已保存来源不重新检查当前 Run 状态或最终回答资格。历史快照、实际材料读取与直接/继承依赖的全量装配、安全判定、审计边界和预算没有改动。
