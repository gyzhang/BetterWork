## 实施契约

1. 工作消息列由 `WorkMessageList` 组合现有消息、工具、状态与捕获基座。每个 Run 的纯投影按自身事件数组缓存；活动 Run 增量不重新投影历史回答。保留最终回答与中间流式文本的既有区别。
2. 每条非空已完成回答可以保存，按钮携带该 Run 的身份和最终正文。仍追加当前 Task 已有 Markdown 成果的版本；不把 PPTX 等文件成果当作 Markdown 目标。主进程的 Run/Task 校验、版本 Evidence 关系和来源登记规则保持现有契约。
3. 保存动作由专用 Hook 持有忙与反馈状态，等待期间阻止重复保存。失败只有目标回答的 `InlineError`；成功只有列表的一枚 `TransientToast`。新 Task、选择离开及 A→B→A 后，旧保存响应不打开新任务的上下文或覆盖当前反馈；已经提交的保存不撤销。
4. 记忆捕获入口仍只显示于最新完成回答，定位、原文选区和幂等保存保持原行为。
5. `ContextPanel` 保留开关、页签、组合及跨页签的共同短时反馈；按过程、资料、记忆、简报、成果分组传入明确的领域数据与动作。既有表单、来源预览、记忆范围和跨页动作保留，不引入通用 CRUD 控制器或第二套业务状态。
