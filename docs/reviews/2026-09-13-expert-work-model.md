## 1. 本轮明确的需求

算台为工作而生。重复工作应固化为专家，例如财务部门每月经营数字分析、调研后制作 PPT。专家拥有自己的人格、工具、MCP 工具、Skill 和记忆。当前通用智能体继续承接临时工作，可自由选择技能与工具。

专家的价值是复用工作方式与积累，减少每次从头解释职责、口径、工具和交付要求的成本。重复工作不自动意味着定时启动；本轮没有提出定时任务或多个专家自主协作。

## 2. 建议的产品模型

通用助手与专家复用同一个 Agent Core。差异由可持久化的配置、能力绑定和记忆范围产生。

| 维度 | 通用助手 | 固定专家 |
| --- | --- | --- |
| 适用工作 | 临时、探索性、尚未形成稳定方法的工作 | 经常发生、有稳定方法和交付要求的工作 |
| 人格与职责 | 通用协作方式 | 角色、判断原则、表达习惯、职责边界 |
| Skill | 为当前任务选择 | 保存常用方法组合，启动时展开为可见绑定 |
| 工具与 MCP | 按当前需要选择已配置能力 | 保存自己的工具清单及连接引用 |
| 资料 | 当前任务与工作区选定资料 | 另有长期参考资料和模板绑定 |
| 记忆 | 用户与当前工作区的适用记忆 | 额外积累该专家的方法、经验和偏好 |
| 交付要求 | 当前任务约定 | 默认结构、模板、质量检查和讨论节点 |

“自己拥有”建议解释为独立选择、配置与作用范围；多个专家仍可复用同一 Skill、工具实现或 MCP 连接，不必复制安装和凭据。

专家应以工作职责命名，例如“月度经营分析专家”“行业调研与汇报专家”。同一个专家可使用分析、研究、写作、PPT 等多项 Skill 完成整项工作；现有 `ppt-generation-expert` 虽然名字带 expert，在算台中仍是 Skill，不应按名称自动升级成 Expert。

## 3. 两个具体场景

### 月度经营分析

- 人格：严谨、关注经营原因、结论先行，区分事实与推测。
- 方法：核对输入与统计期间 → 校验指标口径 → 计算同比/环比/预算偏差 → 分析原因 → 形成报告与汇报。
- Skill：数据质量检查、经营分析、图表、报告、公司模板 PPT；此处是能力需求示例，不表示这些 Skill 均已存在。
- 工具：文件读取、确定性计算、脚本执行；需要业务系统数据时使用明确配置的 MCP 查询工具。
- 资料：当期数据、指标定义、预算、历史报告和模板。
- 记忆：用户确认的展示习惯、分析经验，以及限定在该公司工作区内的统计口径。
- 工作组织：财务工作区长期保留；每月新建 Task，复用专家，历史成果按需要引用。上月结论不自动成为本月事实。

### 调研与汇报

- 人格：重视来源、明确不确定性、理解汇报对象。
- Skill：研究、来源核验、方案分析、报告写作、PPT 制作。
- 工具：搜索、资料检索、文件与脚本工具；按实际需要配置 MCP。
- 记忆：常用研究方法、领导关注点、已确认的表达偏好；项目事实保留在对应 Workspace。
- 交付：同一专家持续完成调研、讨论、大纲、报告、PPT 和修改，沿用既定六个讨论节点的产品方向。

## 5. 记忆需要同时回答“谁的经验”和“适用于哪里”

建议最小范围：

1. User：用户跨工作的表达与协作偏好。
2. Workspace：公司、部门、项目的事实与口径。
3. Expert：这个专家可跨任务复用的方法与经验。
4. Task：当期输入、进度、临时决策。

专家专属、同时只适用于某公司的记忆需要 Expert + Workspace 的适用约束，不能简单把两类记忆无条件合并。具体关系需在实现 ADR 中确定。

首版建议支持查看、手动新增/编辑/删除、明确“记住这个”、来源与适用范围，并在下一任务中真实读取。模型发现的经验作为 candidate，经用户确认后生效；旧数字带统计期间，过期内容不继续当作当前事实。历史聊天和历史成果均不自动等于长期记忆。

继续遵守 ADR-0004：SQLite 记录负责状态与来源，Markdown 作为可重建投影；手工文件编辑如何回写须在实现前定义，不能形成双真相源。暂不以向量检索、后台反思或完整记忆中心作为最小专家记忆的前置。

## 6. 配置如何影响执行（建议，待实现 ADR）

- 任务选择专家；运行时固定专家修订、实际 Skill 绑定、工具清单和读取的记忆版本。专家修改从下一 Run 生效，历史 Run 不被改写。
- 专家预设展开到现有 Composer 能力展示中，用户能看见本次用了什么。本次增删形成任务使用的配置差异，不静默回写专家；“保存为专家”展示将保存的内容，不复制整个聊天历史、密钥或未确认记忆。
- 沿用 B0：Skill 仍通过 Run 的能力绑定进入执行，保持现有数量上限、修订、信任、依赖检查，不另建旁路。调整专家能力必须解决与既有选择的冲突并展示最终集合。
- 实际可执行工具为已注册可用能力、专家/本次选择、有效授权的交集。Skill 需求不自动授予权限；必需能力缺失时说明缺项，不能静默退化。
- MCP 连接由应用统一管理，专家引用连接和具体工具；运行中断线、超时、取消、同名工具映射、服务新增工具与凭据存储均在 MCP ADR 中定义。新发现工具不自动获得授权。
- 记忆和知识检索在 Application/检索层实施范围过滤，模型不能用任意 expertId 绕过范围；Agent Core 不读取数据库和安装目录。
- 停用/撤销必须阻止后续使用；活跃 Run 的取消策略、专家删除后的历史保留、复制专家是否携带记忆均需明确。建议复制默认只复制配置、删除默认归档并保留历史快照。

## 7. 现状、范围变化与建议实施顺序

当前 B0 代码已具备多 Skill 绑定、Composer 选择、指令注入与撤销级联；任务板仍将真实窗口双技能运行和重启恢复列为人工验收。`RunService.buildPreviousMessages` 已读取任务历史，旧记忆文档中“执行不读取历史”的描述已落后于代码；这项历史上下文能力仍不等同于专家长期记忆。

本轮没有实现专家、MCP 或记忆。既有 B01–B04 规划需要补入本轮明确的 MCP 与专家记忆需求，不能继续仅按提示词和 Skill 绑定验收完整专家功能。

建议分四步，各自都有可运行结果：

1. 专家定义与执行：人格、Skill、内置工具范围、资料范围、配置修订、任务选择与管理，复用同一引擎。
2. 最小专家记忆：用户确认、作用域过滤、查看编辑删除、新 Task 复用；实现前补记忆投影与适用范围 ADR。
3. MCP：连接管理、工具发现与选择、生命周期和运行审计。可与上一步交换顺序，由首个真实场景的输入决定；最终必须真实调用，不能只留字段。
4. 以连续两期经营分析或连续两次调研汇报验收：第二次复用已确认的方法和偏好，更新当期输入，产出可追溯成果。

开工前先形成专家领域/执行 ADR，并分别落实 MCP 与记忆边界；再更新 B 任务卡。完整 Office 路径继续按 C 分阶段交付，自动调度、多 Agent 和公开市场不因本轮需求自动进入范围。

## 8. 验收重点

- 修改人格与方法后，下一 Run 的实际模型输入变化，旧 Run 可解释。
- 两位专家的工具与记忆范围不同，越范围调用被拒绝；同一专家在不同 Workspace 不串公司事实。
- 同一专家真实使用多项 Skill；所选 MCP 工具进入执行，未选工具不可调用。
- 保存一条已确认记忆，重启并创建新 Task 后生效；编辑/删除后下一 Run 使用最新状态。
- 停用 Skill、撤销授权、MCP 断线与取消均有明确结果；成果和运行历史不丢失。
- 通用助手仍能不选专家直接工作，并自由组合当前可用能力。
