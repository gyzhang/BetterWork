# UI 组件、规范与 AI 执行规则对齐评估

评估日期：2026-10-02。起始代码基线 `4cf45e4`，工作树干净。用户授权全面评估并落实治理；本轮范围是 Renderer 页面/组件、UI 规范、AI 规则入口与执行门禁，不改变业务协议、数据库关系或既有产品任务板状态。

## 1. 负责人的判断

现有 UI 基座已经可用，继续换组件库或按文件行数拆分没有充分理由。主要问题在于**AI 读到的现行规范并不总是现行事实，门禁通过也不总能证明文档承诺的检查范围**。这种偏差会让 Review 重复报旧问题、新页面复制已退役写法，甚至把机器漏检当成新的合法例外。

本轮把 AI 的工作入口收敛为：AGENTS 任务路由 → docs/10 §10.1 的同一流程 → 真实导出台账 → 对应产品/视觉条款 → docs/12 工程与验证。Qoder UI 文件只做阅读路由。历史报告保留证据，但不再作为当前待办或组件 API 来源。

产品经理的验收点是主要目标、内容、行动和状态是否易于找到；前端设计负责人的验收点是语义、几何责任与状态是否一致；AI 治理的验收点是规则能否定位、能否执行、能否被正反用例核验。三个维度分别给证据，不把一个维度的通过包装成全部通过。

## 2. 核查范围与证据方法

- 核对工作页 App 编排，成果/知识/技能/专家页，设置外壳和记忆内嵌分区；检查共享布局、控件、反馈、空态、菜单/模态及领域组件与实际导出。
- 对齐 AGENTS、docs/10、docs/12、docs/11、docs 索引、Qoder 常驻/编码/UI/启停规则、历史 UI 评估与 ESLint/Prettier/结构护栏/CI/真实渲染入口。
- 用最小合法/违规用例检查条件子树、可选包装、非渲染属性、CSS 末声明、组件台账与 Field 语义。已有新名字表面、内联几何、主题缺项和交互角色探针继续保留。
- 首轮因 Mac 锁屏，原生窗口不可读，仅运行独立合成 Electron 渲染验证。用户随后确认已解锁并要求补做真实产品走查；本日已在正在运行的产品原生窗口完成 §7 所列页面与路径。两层证据分别记录，不把合成页面算作真实页面验收。

## 5. 治理后的职责与后续规则维护

- **AGENTS**：硬边界与任务路由；UI 细则回 docs/10，工程回 docs/12。
- **docs/10**：当前产品/视觉语义、页面执行流程、真实组件台账、检查边界；状态指向任务板，历史过程指向报告/ADR/日志。
- **docs/12**：代码分层、错误处理、命令、测试与例外；规则冲突必须修正，不能单凭配置放宽语义。
- **Qoder UI 规则**：任务路由；不再维护组件 API、尺寸表和迁移数量的第二份副本。
- **ESLint/类型/结构护栏**：执行能自动判断的约束；检测器用正例与违规变异验证，白名单看具体用途与真实出口。
- **ui:check 与页面走查**：前者是固定生产组件组合的渲染冒烟，后者才覆盖本次页面的用户目标、信息层级和真实状态；每次报告必须说清实际验证范围。

新组件必须有真实需求和消费者，再登记实际导出；新页面按 §10.1.1 执行。更新台账无需同步旧报告。修改设计契约时同步可执行配置/护栏与必要行为用例；若规则没有适用到真实实现，先改实现或核对规则用途，不能只增加例外理由来消红。
