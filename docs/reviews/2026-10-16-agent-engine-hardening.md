## 工具与模型边界

- 损坏 JSON 和非对象参数由 Provider 输出内部 `tool-call-error`。Core 对每个被拒绝调用产生 `tool.failed`，将错误反馈模型，继续同批合法调用；不执行非法调用，不静默用空对象替换参数执行。消息中的原始参数字符串仅供下一次模型请求还原调用/结果配对，不进入共享工具输入事件。
- 缺失或重复的上游工具调用 ID 映射成 Run 内唯一 ID，分片期间固定该映射，历史消息与结果保持同一 ID。
- 同步抛错、异步拒绝及不可 JSON 序列化的工具结果统一为可恢复工具失败，清理监听器并允许模型纠正。合法结果先确认序列化，再发布完成事件；不放宽宿主结果审计。
- 轮数上限继续约束非法调用与纠正轮次。length、content-filter、unknown、缺少完成信号以及无工具且无有效回答均不可成功；没有 finishReason 的旧 `[DONE]` 路径在存在有效回复或工具时继续兼容。
- `[DONE]` 是传输终止边界，不能等待 HTTP EOF 才执行工具；finish_reason 后、`[DONE]` 前的 usage 仍保留。结束或提前停止消费时释放响应体与 reader。

## 取消与提交

- Core 在每次 yield 恢复、每项工具派发及每次进入等待前检查取消；取消不能依赖可能丢失的一次性进度唤醒。已取消后不启动下一工具、不发布迟到结果。
- RunService 在运行和清理期间接受取消；清理成功后、进入成果/终态提交段前最后核对 signal。此时取消优先于候选成功，保留取消原因且不登记 Markdown 成果。
- 进入成果/终态提交段时同步关闭取消入口；此后的 cancel 返回 false，避免接受无法兑现的取消。已提交终态和成果不会因完成后回调失败改写；清理失败仍优先于安全取消。

## 清理与退出

- Skill 与 MCP 清理分别尝试，失败聚合为 Run 失败；Skill 失败不能跳过 MCP。准备异常的恢复同样执行两类清理。
- MCP Run 资源在确认关闭之前保留所有权；并发释放共享在途 Promise，成功连接不重复关闭，失败连接留待后续重试。不得先删除所有权再关闭。
- shutdown 等待已接收操作退出；操作因取消而拒绝不等同于清理失败。OAuth/连接的真正清理失败必须传播至应用退出协调器，保留资源重试入口；并发 shutdown 共享等待，失败后可重试。
- 继续遵守应用退出总预算和本机子进程清理契约，不以 AbortSignal 或发起 close 代替关闭确认。

本轮不扩展审查另列的总上下文预算、自动网络重试或任务断点恢复；这些策略另行设计。真实模型与 Electron UI 验收仍独立安排。
