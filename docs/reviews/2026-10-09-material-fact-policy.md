## 现行范围与本次边界

[ADR-0020](../adr/0020-deterministic-business-analysis.md)要求经营指标由确定性工具计算，未规定把材料防护限定为某个专家。[材料契约](../development/material-contracts.md)区分选择、读取和采用；[知识契约 §5.2](../development/knowledge-contracts.md#52-返回与落库顺序)要求事实审计只使用工具实际返回文本。现行代码对 `materialScope && materials.length > 0` 的 Run 启用防护，通用助手、专家和定时 Run 共用此规则；无材料或非材料范围 Run 不启用。本次保留范围，不按专家名称、Skill、提示词或文件名重新推断。

| 接点 | 保留的行为 |
| --- | --- |
| 用户当前请求 | 只采集带现有业务单位或客户数标签的数字及肯定定性表述；请求本身不算读取材料。 |
| 成功读取 | Text/Artifact/Office/Knowledge 搜索或正文读取，沿用现有片段提取与读取计数；Run 工作文件不作为材料输入。 |
| 确定性结果 | 现有 `analyze_business_metrics` 返回值加入数字池，但不满足“已经读取材料”。其他工具、网页和 MCP 不新增事实授权。 |
| 审计 | 无成功读取先失败；数字错误优先于定性错误。保持原错误文案、单位空白处理、客户数标签、非断言/否定窗口、舍入精度与 0.01 容差。 |
| 生命周期 | Run 完成前调用审计；保持失败终态、取消、来源登记与成果发布顺序，账本随 ActiveRun 结束释放。 |

纯策略落在同一 Application 层的 `material-fact-policy.ts`，不依赖 Electron、SQLite、Provider 或 I/O；RunService 保留工具结果识别、片段选取和事件/来源持久化。输入具名区分材料读取与确定性结果，集中判断启用范围。没有新 IPC、Schema、迁移、package 或领域关系，无需新增 ADR。

## 数值枚举优化与实际限制

当前采集会对全部累计数字反复两两组合，再展开舍入后的允许值。本次保留许可结果，改为存储原始值与直接允许值，仅在最终输出中的数字不能直接匹配时按需检查旧差值/变化率/比值。采集不再构造数字笛卡尔积；审计不永久存储派生集合，同一输出内所有未匹配查询共用一次配对扫描，以排序索引匹配严格容差并复用同类数字的判定。旧实现的离线对照用于确认兼容，墙钟与内存预算只放 bench。

这仍是兼容现行规则的启发式防护，不能证明数字属于正确的指标、单位、期间或来源。旧规则允许任意材料数字配对、部分小数的百分比展开及固定业务词，全部显式保留；本次不把它称为完整业务事实证明。最坏的未支持数字查询仍需两两检查，后续若改为只接受显式事实项与确定性计算结果，需要单独定义关联和失败契约。工具结果适配与终态整理继续留后续切片。
