# 产品定义

> 2026-09-08：定位与已确认顺序见 [ADR-0008](adr/0008-personal-workbench-and-capability-first.md)；具体首版功能范围见 [修订稿](reviews/2026-09-08-product-scope.md)，其中建议项仍待审阅。

## 1. 产品名称

- 中文：算台
- 英文：BetterWork
- 品类：知识工作者的个人 AI 工作台

“算”既包含计算，也包含分析、谋划与推演；“台”表示用户持续工作的操作台和工作台。品牌来自传统算盘，但产品面向现代知识工作。

## 2. 产品愿景

让知识工作者能够在一个自己掌控的桌面工作台中，调用个人知识积累、长期协作记忆和外部新信息，完成可信、可复核、可继续修改的专业工作成果。

## 2.1 产品定位

> 以我所知，成我所作

算台是面向个人知识工作的 AI 工作台。用户通过配置化专家调用多项 Skill，结合长期工作目录、个人知识与协作积累，在持续讨论中完成研究、分析、文档和演示，并让成果成为后续工作的基础。

产品优先服务个人自用及周边同事的个人工作，不建设企业管理或组织提效平台，当前不以市场化为目标。没有预先建立知识库也应能开始任务。

## 3. 目标用户

第一阶段主要面向：

- 产品部门负责人
- 市场、运营和战略人员
- 顾问、研究员和解决方案人员
- 需要经常处理客户资料的知识工作者
- 经常制作汇报、分析和方案的个人用户

第一阶段不面向软件开发者，不以代码生成和代码仓库操作作为核心场景。

## 4. 核心问题

知识工作者的资料通常分散在 Office、PDF、Markdown、文本和图片中。许多工作重复依赖这些历史积累，但现有工具往往存在以下问题：

- 个人资料不适合或不愿贡献到公司公共知识库。
- 聊天工具难以持续积累对个人、客户和项目的理解。
- 搜索、分析、写作和制作演示文稿分散在不同工具中。
- AI 输出缺少来源、过程和版本，难以复核与继续修改。
- 长任务缺少清晰步骤、确认点和失败恢复。

## 5. 产品承诺

算台帮助用户：

1. 在本地建立和管理个人知识空间。
2. 通过全文、向量和结构化检索找到相关资料。
3. 将历史知识与新信息结合，生成新的分析、方案和想法。
4. 使用长期记忆持续适应用户、项目和工作方式。
5. 通过专家、Skill 和套件复用成熟工作方法。
6. 生成并持续修改研究报告、Excel、Word 和 PPT 等 Artifact。
7. 保留来源、执行过程、版本和关键决策，便于复核。

以上七条是产品演进承诺，不是当前实现状态，也不全部构成首版前置。其中全文检索、本地 Artifact 版本与来源追溯已落地；向量与结构化检索、长期记忆、专家/Skill/套件、Markdown 以外的 Artifact 类型仍按 [MVP 与路线图](07-mvp-and-roadmap.md) 分阶段建设。判断「现在做到了什么」以 [Qoder 开发交接](11-qoder-handoff.md) 第 2 节的能力表为准。

## 5.1 Skill 的信任与默认执行（已确认，待实现）

Skill 配置提供「受信任」选项。它表示用户允许该 Skill 在已经授予的范围内执行脚本及必要子进程，正常步骤无需逐次确认；不代表关闭超时、取消、日志、质量检查或成果版本规则。

- 产品随包审查的内置 Skill 默认信任；用户导入的 Skill 可勾选「信任并允许执行脚本」。仅导入和查看不会执行代码。
- 信任与启用独立：受信任但停用的 Skill 不可被任务调用，缺依赖也不能显示为可运行。
- 信任绑定具体内容、依赖和授权范围；更新导致变化时展示差异并重新确认。产品发布的已审查内置新版本可采用发布默认策略，但用户撤销信任/停用的选择持续保留。
- 用户可以撤销信任；撤销后阻止新脚本启动，并停止仍在执行的该 Skill 脚本，保留已有成果与记录。
- 覆盖源文件、增加访问范围、安装新依赖、向外部系统发送内容不因信任自动获得授权。已有授权不重复询问，范围变化另行说明。

首版脚本使用本地用户权限执行。此选项是授权机制，不是文件或网络沙箱；宿主可拦截自身工具的越界请求，但不能声称能够拦截任意原生脚本内部的系统调用。具体机制见 [执行器设计](designs/skill-executor-and-dependencies.md) §7。

## 5.2 本地 Skill 与产品分发（已确认，待实现）

产品源码提供 `resources/skills/` 维护内置 Skill，安装包携带完整的 `skills/` 资源目录，用户数据目录中的 `skills/` 保存导入、自建及内置副本。每项 Skill 保留 SKILL.md、scripts、references、templates、assets 等原有结构。

安装包中的内置内容按只读资源使用；用户修改创建自己的副本，产品升级不覆盖。Python、依赖包与工具链可以作为共享运行资源分发；用户配置外部服务并完成必要环境准备后即可使用，不要求手工 clone/pip。

公司模板及私有知识默认只在用户本地使用；是否加入某个分发包由用户明确选择，公开分发仍需具备相应资源使用条件。信任授权不随 Skill 导出到其他设备，接收端重新按自身策略判断。


## 6. “本地优先”的含义

本地优先表示：

- 原始文件、知识库、记忆、索引和 Artifact 由用户在本地管理。
- 用户不需要将资料贡献到公司统一知识库。
- 数据可以备份、迁移和删除，不被某个云知识库锁定。
- 用户可自由选择公网模型、公司内网模型或本地模型。
- 检索出的内容可以发送给当前选择的模型，不承诺“数据永不离开设备”。

算台不是企业级数据防泄漏或合规平台。

## 7. 核心体验

典型任务如下：

1. 用户进入一个 Workspace，例如“客户 A”或“2027 年市场规划”。
2. 用户选择专家或直接描述任务。
3. 算台检索个人知识库，必要时搜索新信息。
4. 算台展示计划、证据、分析步骤和待确认问题。
5. 用户在关键节点确认大纲、数据口径或修改方向。
6. 算台生成可预览的报告、表格、Word 或 PPT。
7. 用户通过对话或直接操作继续修改，形成新版本。

## 8. 产品原则

### 工作成果优先

对话服务于工作，不能成为信息终点。重要结果应成为 Artifact。

### 过程可见但不过度暴露

展示计划、步骤、工具、来源和状态，不要求展示模型私有思维链。

### 可控胜过完全自治

在研究范围、指标口径、大纲和最终交付处保留用户控制。

### 确定性计算优先

统计、公式、表格变换和文件修改交给确定性工具，模型负责理解、规划和解释。

### 默认非破坏性

修改 Office 或其他用户文件时默认另存新版本，不覆盖原件。

### 可读性也是产品能力

模块、事件、数据关系和执行过程应清晰可维护。教学目标与实际可用性冲突时，实际可用性优先；教学总结独立于产品验收。

## 9. 非目标

首个可交付版本明确不做（与 [MVP 与路线图](07-mvp-and-roadmap.md) §8 保持同一口径）：

- 编程和代码仓库智能体
- 企业级团队权限与合规系统
- 公司级公共知识库平台
- IM 机器人和多渠道消息接入
- 多 Agent 自主协作网络
- 通用 DAG 可视化编辑器
- Skills 商店和商业生态
- 云同步和多人实时协作
- 全自动浏览器操作
- 图片、视频生成平台
